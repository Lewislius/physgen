R11A 重设计：先对齐 Q/C，再联合生成（API 修订数据）

目标与已有证据
固定 VideoPhy2-40 目标为 PC>3.8、SA>3.3、Joint>10/40，同时检查真实物理过程与画面缺陷。60 例保持 R10A 的 PC3.833333 并改善 SA/Joint。最多迭代至 R13B，完成已声明评测后暂停。
旧 R10A400：40 例 SA2.825/PC3.750/Joint7；60 例2.750/3.833333/9。其物理执行有价值，但语义和联合通过率不足。
失败旧 R11A67214：40 例2.900/3.450/6；60 例2.866667/3.516667/10。新增文本 Q/K/V/O 适配和融合顺序变更的组合未达目标，不能继续默认继承。
R10A 固定16例关闭物理融合后 SA 与原生400步模型16/16一致；完整物理条件在 VP010/017/025 上降低 SA，整体 PC 增加0.25。故改进重点包括物理条件准确服从原请求，不能只把 SA 损失归因于原生语言通路。
现有 R10A400 的 Q 两轮读取，16个混合头分给原请求的平均注意力质量为0.281616/0.228455；折算全部32头为0.140808/0.114227。按 token 数均匀读取时混合头比例约0.287045。这说明请求和较长分析在同一读通路竞争，不证明注意力质量就是因果贡献，也不证明新设计已改善生成。记录：../r11_r12/reports/r10a_request_read16.json。

架构：保留有效执行，明确请求读取
保留 R10A 的 Q256、两轮共享物理增强、关系内/关系间交换、路由 C 和执行 C、状态相关并行融合；官方 Wan 文本 cross-attention Q/K/V/O 冻结。只训练原有 self-attention/FFN LoRA，不恢复失败版本的文本适配。
原32个 Q 读取头改为16个关系内读取、8个原始请求专读、8个请求与 reasoning 混合读取；使用相同 Q/K/V/O 参数，无新增参数、分支网络、语义头或损失。空请求时退回原混合读取，避免空注意力。最终路由值读取和 Q 执行投影保持 R10A 原式。
这一改动直接改变 Q 在执行投影前获得的请求信息；不靠强制 token 差异、cosine 惩罚或放大注入。新鲜官方底座及新训练接口初始化，不继承旧实验训练权重。

阶段一：第1–64步，只做表征对齐
每步累积4个样本，使用 API 修订后文本/首帧 reasoning 经本地冻结 Qwen3-VL 编码的特征，以及本地 Wan 原生词目标。
更新 Q、共享增强块、路由投影与共享偏置；损失为路由 C 对原生词目标的归一化 MSE。
不执行 Wan 视频前向、不计算 FM、不更新 Wan LoRA、fusion 或执行 C 投影。执行 C 保留拟合接口的初始表征，等待真实生成目标学习。Wan 权重仍会预先加载，便于统一检查点；这不等于参与本阶段计算。
不直接把执行 C 拉回文字目标，保留 R10A 生成专用执行的分工。64步是本次具体预算选择，并非已证明最优。

阶段二：第65–400步，336步联合视频生成
同一个完整生成前向，同时更新全部物理增强/融合和原有 Wan self-attention/FFN LoRA。
L = 0.8×平均 FM + 0.2×原有多尺度高误差区域项 + lambda×路由词对齐。
lambda 在联合阶段前32步升至0.03，之后保持。路由辅助不约束执行 C，执行 C 从真实视频生成损失取得梯度。
Q/路由从全程起点 warmup32；fusion 在联合阶段 warmup32；Wan LoRA 从联合阶段起点 warmup128。峰值学习率保持原 R10A，无新增衰减或中间训练阶段。
400个优化步骤、1600条固定抽样记录，其中前256条仅表征对齐，后1344条参与真实视频生成。Q/路由400次更新，执行/fusion/LoRA336次；R10A参照为物理生成400次、LoRA272次。总步数相同，但生成监督曝光量不同，不能宣称严格等生成计算预算。
训练日志分开记录 alignment 与 FM，表征阶段 sigma=null；仅保存64/250/400及常规恢复点，不做250步额外评测。

数据与推理兼容
使用已完成的1600条 API 修订训练缓存、3200正/空请求本地特征与已拟合的新接口。原3857条manifest顺序保持，实际训练范围与准备范围一致。
训练 caption 通过实际截断视频修订并保持原 WISA 风格；生成侧 reasoning 只读首帧和请求，不读取未来视频。API 输出是文本，特征仍由已有冻结 Qwen3-VL4096编码，Wan T5 不替换。
评测原始 prompt、公共首帧、保存噪声、seed42、gamma5、50步采样均不改；仅首帧/原请求驱动新的 API reasoning。与 R10A-API400 共享一次准备的60例缓存，文件锁防止重复API调用和并发写入。

评测与下一步决策
完成自身400步后生成原40例，追加20例合并60；同时给出5分均分及 SA>=4、PC>=4、二者同时>=4 的0–1通过率。
固定16例：正常结果复用40例；关闭注入、无关reasoning、空reasoning、固定训练均值 C、固定路由保留完整执行、请求专读退回混合读取。所有干预使用相同图片、prompt、噪声与采样配置。
请求专读退回混合读取是同一已训练模型的推理干预，不能冒充独立重训消融；均值 C 同时影响幅度，不能仅按文本信息解释。若要给新增读取设计作因果归因，需要后续训练对照。
分别比较旧 R10A/R1/原生400与新 R10A-API400。后者相同更新数据与评测输入，能帮助区分数据收益与整体训练/架构修订收益；新版同时改训练阶段和读取方式，二者贡献还需后续证据。
保留实际视频人工审看，尤其动作/关系是否按请求执行、过程是否连贯、画面是否出现不自然形变及纹理。FM、表征距离、单元测试均不作为生成质量已提升的证据。
下一版本由400步评分、配对得失和视频失败模式决定，不预先提交 R11B。旧R11A及此前被否定的双路/128-FM训练草案、取消的自动提交器保持原状。
