R16Gt：把 R16G 的“多全局读 + R15C 局部视频状态算子”原样迁到文生视频

目标
R16G 在固定 VideoPhy2-40 的 I2V 协议上取得 SA 3.050 / 12/40、PC 3.500、
Joint 12/40。本版只回答一个问题：同一套 R16G 设计在 T2V 里表现如何。除任务
入口（无首帧）外，不改变 R16G 的增强结构、三路全局物理执行写、R15C 局部算子、
训练预算、采样器和评测口径。本版记为 R16Gt，训练与评测在 ada-48g 的
L40S / RTX 4090 48GB 上执行（GPU_POLICY=ada-48g），拒绝 H100。

保留的 R16G 设计
1. 三路独立归一化的干净全局读：
   - direct C（R10A）：视频 query 直接读 C execution；
   - request-bound C（R15B）：原生请求 key 先把 C 值绑定到字面请求，再由视频
     query 读取；
   - joint direct+request C（B400）：两路物理记忆共享一个 null，保持原始总
     关系先验的 R:1 质量。
2. 每个全局读各有独立的 zero-init 全宽 3072->3072 输出和独立的 zero-init
   全宽 3072->3072 乘性 state gate，不使用低维 bottleneck。
3. R15C 局部算子原样保留：local Q = 原生 video Q + zero-init 全宽 direct C
   条件；local K = 原生 video K；local V = 原生 video V（视频状态，不被 C
   覆盖）；5 帧 x 3x3 非循环局部时空注意力，真实视频网格 RoPE，交替 shift，
   zero-init 输出。R16G 的 local Q 只加 direct 条件，本版不变。
4. 原训练预算：400 updates（128 interface + 272 joint），accumulation 4，
   共 1600 个 micro-batch；Wan LoRA 第 129 步才参与；seed42、学习率、warmup、
   gradient clip、text dropout、辅助系数、保存步点与 R16G 一致；从官方
   Wan2.2-TI2V-5B 与全新项目参数开始训练，不加载 R16G 权重。
5. 原评测协议：固定 VideoPhy2 40 + 追加 20，共 60 条历史 caption；seed42
   持久化噪声；832x480、81 帧、24fps、50 步 shifted-Euler、shift5、CFG5；
   官方本地 VideoPhy2 AutoEval 的 SA/PC 1-5 分，>=4 为通过，Joint = 同一视频
   SA>=4 且 PC>=4。

唯一任务改动：I2V -> T2V
1. 不接收任何首帧、首帧 latent、首帧 RGB 或首帧派生条件。模型入口断言
   first is None。
2. 整个 21 帧 latent 全部为噪声，patch_embedding 直接编码完整 noisy latent；
   所有 token 使用 sigma*1000 的时间位置；物理增量写入所有帧，不存在 known
   前缀，也没有首帧恒等约束。
3. Fusion 的时间特征在 T2V 下使用全部 21 个时间点（I2V 使用 times[1:]）。
4. 生成损失覆盖全部 21 帧（I2V 排除已知首帧）；FM/tail 口径不变，只改覆盖。
5. Qwen 证据为 request-only：只给 caption/时长，不给图像、未来帧、评分或
   物理标签。直接使用现有 v10 T2V 处理数据：训练 latent/native T5 来自
   data_revision_qwen38 的 encoded cache，request-only 证据与 native words 来自
   physics_content_v10_impl/runs/t2v_cache。
6. 接口在 train split 上重新闭式拟合，不使用测试样本，不加载 I2V 接口。

数据配对
R16G I2V 的 400 步训练在 3666 条 train 记录上以 SampleOrder(seed42) 抽取
1600 个 micro-batch；这 1600 个 draw 的 unique 样本集合恰好等于 T2V
evidence-complete 的 1600 行（已由 CPU 测试核对）。R16Gt 复用 R18E/G 的 T2V
loader：先从 3666 行过滤到这 1600 行，再使用 SampleOrder(seed42)。因此
样本集合与 R16G 相同；加载顺序是 R18E/G T2V 顺序，不是 R16G I2V 的逐步顺序。
由于使用 qwen38 reviewed revision，R16Gt 与 R16G 的 caption 数据修订不同，
分数差不能当作纯任务/范式差异。R15Bt 也是同一处理方式。

评测与解释边界
- 这是固定 60 条历史 caption 的 T2V 评测，不是官方 590 条 caption 的全量榜单。
- 评测器为本地官方 VideoPhy2 AutoEval；不声称与 ProPhy 或任何外部论文的
  judge 相同。
- 主结果输出 40、20、60 三套 SA/PC/Joint；不预写目标分数，不把 I2V 成绩当作
  T2V 成绩。
- 推理干预 no_c / condition_off / global_off / local_off /
  global_direct_off / global_request_off / global_joint_off / temporal_off
  是同一权重的推理控制，不是独立重训消融。
- 本版只做一次 400 步训练；是否继续迭代由 40/60 结果与真实视频复盘决定。

代码与验证
- physical_content/model.py：R16G 原模型 + T2V 入口。只改首帧边界，不改三路
  全局读和 R15C 局部算子。
- physical_content/data.py：T2V latent/text/times/valid，无 first 字段。
- physical_content/train.py：400 步训练、无首帧采样、全帧损失。
- prepare_inputs.py：把 request-only 评测证据压成推理用 positive/negative。
- infer.py：无首帧采样，输出 manifest/summary/video.json；推理只读
  r16gt/eval_native_inputs（text/null_text/times），不读 I2V prepared_inputs。
- gpu_preflight.py：全尺寸一次性预检，验证零初始化=native、三路全局读写梯度、
  全帧物理写、显存峰值；不保存正式权重。
- tests/：T2V 无首帧契约、R16G 设计锁定、全帧损失、1600 样本集合与 R16G
  一致、joint read 等价性、零初始化、全帧写、梯度开启顺序、真实缓存证据。
- run_candidate.py：训练后自动 40、disjoint20、60 合并与 report。
- report_results.py：独立合并 40+20=60，避开旧 merge 脚本的 guidance 字段依赖。
