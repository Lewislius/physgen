**H_content_message：由内容状态直接更新得到 C**
方案正式名称：`H_content_message`。本文件保留此前的内容状态更新方案；与固定 128 个可学习查询的 [Q_seed128_message](Q_seed128_message_设计方案_20261026.md) 分开保存。

2026-10-26。本文是设计建议，未修改模型代码，也未运行训练。分析对象是两张 Qwen 多轮 reasoning 图及其对应的 v14 配置。

**建议让内容本身成为可更新状态，更新后直接输出 C。**

现有路径先保留 H_content，再由独立的 32 个可学习 query 产生 R，最后将二者拼成一组条件 token。这在张量上合法，但拼接后的归一化和线性映射逐 token 工作，没有建立“R 如何修订原内容”的显式计算。

本次建议取消独立 Q_seed 和末端的 H_content/R 拼接。用当前样本的 H_content 初始化工作状态，让这个状态读取完整多模态证据、更新自身，然后直接成为 C。这里的更新模块放在冻结 Qwen 外部；它属于可微条件修订，不能再描述成“训练 Qwen 内部的多轮推理”。

**4096 是当前 Qwen 的原生语言宽度，3072 是 Wan 的宽度。**

当前配置选择 `/home/liuzhirui/model/Qwen3-VL/Qwen3-VL-8B-Instruct`，其配置为 hidden_size=4096、36 个语言层、32 个 Query 头、8 个 KV 头、head_dim=128。Wan2.2-TI2V-5B 的 dim=3072、24 个注意力头、30 个 block。

| 位置 | 实际宽度 | 说明 |
|---|---:|---|
| Qwen 视觉编码器内部 | 1152 | 视觉塔自身的隐藏宽度 |
| Qwen 原生视觉对接输出 | 4096 | 对接语言主干，属于原模型 |
| Qwen 语言嵌入与最终隐藏状态 | 4096 | H_X、H_content 和原图 R 的宽度 |
| 项目的 Qwen→Wan 映射 | 4096→3072 | 新条件与 Wan 的维度对接 |
| Wan 隐藏状态与本方案 C | 3072 | Wan 的原生宽度 |

不存在“把原生 3072 维 Qwen 先扩成 4096”的步骤。4096→3072 是实际存在的可训练映射，它不是无损变换，任务相关信息能否保留依赖学习。不能用维度比例计算保留了多少语义信息。

证据：[v14 配置](/home/liuzhirui/Project/physGen/code/v5.2.2-native/configs/native_multiround_reasoning_wisa3857.yaml:4)、[本地 Qwen 配置](/home/liuzhirui/model/Qwen3-VL/Qwen3-VL-8B-Instruct/config.json:7)、[本地 Wan 配置](/home/liuzhirui/model/Wan2.2/Wan2.2-TI2V-5B/config.json:1)。官方配置亦一致：[Qwen](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct/blob/main/config.json)、[Wan](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B/blob/main/config.json)。

**S、T、N_C 是数量，4096、3072 是每个 token 的宽度。**

| 符号 | 含义 | 原图/当前 v14 | 本次建议 |
|---|---|---|---|
| L | 完整多模态上下文 token 数 | 由输入决定 | 由输入决定 |
| T | 选中内容 token 数 | caption、clauses、analysis 等内容位置的数量 | 保持这一含义 |
| S | 工作状态 token 数 | 独立配置为 32 | S=T |
| N_C | C 的有效 token 数 | T+S | N_C=T |

32 个工作 token 并没有经过线性映射变成 128 个 token。线性映射作用于最后一维，不改变 token 数量。原图中如果 T=96、S=32，则拼接后 N_C=128。

另一个 128 来自旧配置的 `max_condition_tokens: 128`：旧内容读出按预算执行平均池化。v14 的多轮读出则完整选择内容位置后追加 R。这两个版本的长度规则不能混用。证据：[旧读出](/home/liuzhirui/Project/physGen/code/v5.2.2-native/physgen_native/knowledge.py:241)、[v14 读出](/home/liuzhirui/Project/physGen/code/v5.2.2-native/physgen_native/multiround_knowledge.py:79)。

**现有拼接的问题是把融合责任留给了 Wan。**

原图相当于 `C = concat(P(H_content), P(R))`，其中 P 是逐 token 的映射与对齐。它保留两组表示，但并不把 R 的计算结果写回 H_content。

在 Wan 读取这一组 C 时，两组 token 共同参与条件注意力的归一化。模型可能依赖已经足够有用的 H_content，忽略尚未学好的 R；R 也可能只是重复内容，或者与内容存在不一致。单纯统一宽度和数值尺度不能解决这件事。

拼接在其他模型中可以训练有效，因此不能把它称为数学错误。本项目需要解决的是如何把推理计算明确地落在最终条件上，而不是把“放在一起”当作已经完成融合。

**新流程只有一份可更新的内容状态。**

```text
首帧 + caption + clauses + analysis
                ↓ 冻结 Qwen，一次编码
H_X [B,L,4096]，以及其中的内容位置 indices
                ↓ 在这里停止向 Qwen 回传
共享的归一化与映射 P：4096→3072
                ↓
完整证据 E [B,L,3072] ───────────────┐
                ↓ 选内容位置         │ 每轮读取同一份证据
初始状态 U0 [B,T,3072]              │
                ↓ 内容更新模块 G ←──┘
更新状态 U1 [B,T,3072]
                ↓ 可选再复用一次 G
更新状态 U2 [B,T,3072]
                ↓ 原有 Wan 条件归一化/对齐
C [B,T,3072]
                ↓ 原生 Wan 条件注入
视频生成
```

用公式表示：

\[
E=P(\operatorname{stopgrad}(H_X)),\qquad U^0=E[:,\mathrm{indices},:].
\]

H_content 仍表示原始 Qwen 内容读出；U 是这份内容在 Wan 宽度中的可更新副本。旧 R 的“继续处理关系”职责由 U 承担。最终只输出更新后的 U，不再追加一份原始内容或其他 R。

E 在同一次多轮计算中保持不变，但 P 可以训练。冻结的是 Qwen 参数和它到 P 的上游梯度；G/P 的梯度仍正常保留。

**G 做实际的信息读取与内容更新。**

采用一个普通的交叉注意力加 FFN 模块即可，不增加门控头、关系分类器或新的 verifier：

\[
\widetilde U^{k+1}=U^k+\operatorname{CrossAttn}(\operatorname{Norm}(U^k),\operatorname{Norm}(E)),
\]

\[
U^{k+1}=\widetilde U^{k+1}+\operatorname{FFN}(\operatorname{Norm}(\widetilde U^{k+1})).
\]

这里 CrossAttn 的 Q 来自 U，K/V 来自完整证据 E。每个内容位置可以读取其他要求、条件、分析和视觉位置，将读到的信息写回自己的状态。残差保留内容起点，FFN 对读入信息作非线性变换。

第一版采用一个模块、执行一次更新；需要两轮时复用同一个模块。轮数不改变 token 数量。更新轮次是条件计算轮次，不是视频时间，不承担额外的未来状态预测。

新模块在 3072 维中使用 24 个 128 维的注意力头：

```text
Q       [B,24,T,128]
K、V    [B,24,L,128]
每头输出 [B,24,T,128]
合并输出 [B,T,3072]
```

这属于新条件模块的标准多头注意力，不能说成复用了 Qwen 的 32/8 头配置。Qwen 自身的 4096 维结构不变。

这里仍有注意力中的 Query，但它由当前样本的内容状态计算；取消的是独立、与样本无关的 `[1,32,4096]` 可学习 Q_seed 参数表。

**一个例子说明融合应当实现什么。**

输入要求是：“前两秒从喷口释放烟雾，之后关闭喷口，已有烟雾继续扩散。”完整上下文还说明：“停止来源意味着不再补充新烟雾，不意味着已有烟雾立即消失。”

“关闭喷口”对应的工作位置可以读取后半段条件，形成同时考虑来源终止和已有介质延续的表示；“继续扩散”对应的位置也能读取来源已经关闭的信息。最终 C 里的相关内容向量已经经过这种相互关联的处理，Wan 不必从两组独立 token 中自行决定如何组合这层关系。

这是明确的计算目标，不是给某一维向量指定物理变量，也不意味着注意力本身已经保证物理正确。模型仍然需要从生成任务和可信反馈中学会选择相关信息。

**S 的选择在这个方案中不再是猜一个固定的 query 数。**

因为工作状态就是内容本身，所以 S=T，输出 N_C=T。例如 T=96 时工作状态和 C 都是 96 个 token；T=128 时二者都是 128 个。更新两轮不会得到 256 个或 384 个 token。

样本之间的 T 不同时，批处理按当前批次最大长度补齐，并传入有效位置 mask。这是存储对齐，不增加有效语义容量。

完整内容较长会增加修订模块和 Wan 读取 C 的开销。应在输入组织上保持要求、条件和必要分析简洁，避免重复分析与无用模板进入 T；本提案不另外叠加一个将所有内容压成 32 个 token 的查询模块。若将来必须输出固定数量的 token，那属于一个独立的压缩设计，不能靠修改 S 或重复 token 实现。

**训练边界遵守冻结 Qwen、不训练新 verifier 的要求。**

新增可训练部分是 P、G 和 C 对齐参数。Qwen 只提供当前样本合法输入的表征。生成条件的建立不使用真实未来视频。Wan 继续承担视频状态演化。

如果 verifier 反馈用于训练这个条件模块，梯度路径为：固定现成评估器的连续损失 → 视频 → Wan → C → G/P，到冻结的 Qwen 输出处结束。评估器参数固定，但它对视频的输入梯度仍需保留；不能对整个评估器前向使用 no_grad 后还期待同一条梯度。

这项设计没有声称省掉评估器、VAE、Wan 的反传，也没有重新引入需要校准的新评分头。直接优化单个样本的 C 仍可作为另一种使用方式；那不等于训练了一个可复用的 G/P。

**计算成本应按这个具体结构计算。**

P 的无偏置权重有 4096×3072≈1260 万个参数。一个全宽交叉注意力的 Q/K/V/O 权重约有 3775 万个参数；若 FFN 使用 3072→6144→3072，则再增加约 3775 万个参数。合计约 8810 万个权重，另加少量归一化和对齐参数。这不是几千参数的小头。

计算上的优势是：Qwen 不再为该条件模块反传；条件更新只执行一个模块的一次或两次前向；同一个模块跨轮共享权重；C 在视频生成前构建，不在 Wan 的每层、每个去噪步重复运行 G。相比旧图三次穿过 Qwen 36 层工作区，结构明显不同；实际总训练时间还受 Wan/verifier 主导程度影响，本文不估计未经测量的加速倍数。

**这次修订解决的是表示形成方式，而不是用检查替代设计。**

明确变化是：样本内容直接初始化工作状态；工作状态通过注意力读取完整证据并更新；有效长度贯穿 U0/U1/U2/C 保持一致；最终只交给 Wan 一组经过更新的内容；Qwen/Wan 宽度只在边界对接一次。

实现后最有意义的比较是：相同输入和相同 C 长度下，直接映射 H_content 与经过 G 更新后的 C 能否产生更符合条件关系的视频，并记录实际计算成本。比较的作用是衡量这个设计的收益，不是继续增加额外评分头或保护分支。
