**Q_seed128_message：128 个可学习工作 token 读取并融合内容，直接形成 C**

2026-10-26。设计文档，未修改模型代码或运行训练。与已保留的 [H_content_message](H_content_message_设计方案_20261026.md) 并列，互不覆盖。

**本方案保留 128 个可学习 Q_seed，让 R 成为唯一的条件输出状态。**

H_content 是可读取的内容证据，R 是承载读取结果和关系计算的工作状态。H_content 的信息通过交叉注意力写入 R，128 个工作 token 再通过自注意力交换信息，最终直接由 R 形成 C。不会将 H_content 与 R 作为两组 token 一起追加给 Wan。

沿用 H_content_message 的训练边界：Qwen 冻结，条件更新放在 Qwen 外部的 3072 维空间中，不训练新的 verifier。这里保留的是可学习 query 机制，不恢复旧图中反复穿过 Qwen 36 层的工作区计算。

**两套方案的差别明确放在工作状态的来源与输出长度上。**

| 项目 | H_content_message | Q_seed128_message |
|---|---|---|
| 初始工作状态 | 当前样本的 H_content 经映射得到 | 128 个共享的可学习 Q_seed |
| 工作 token 数 S | S=T，随内容长度变化 | S=128，固定 |
| 内容信息怎样进入工作状态 | 初始化时已有内容，更新时继续读取完整证据 | 通过交叉注意力读入工作状态 |
| 工作 token 的关系交互 | 原方案保留的内容更新模块 | 增加工作区自注意力，允许 128 个位置互相交流 |
| 最终 C | 更新后的内容状态 | 更新后的 128 个 R token |
| C 有效长度 | T | 128 |
| 内容表示取舍 | 保留每个选中内容位置 | 将输入有选择地汇总进固定容量的工作区 |

第二套明确选择固定容量；不能说它完整、无损地保留任意长度的内容，也不能认为 128 个 query 必然对应 128 种独立物理关系。

**Qwen 和 Wan 的宽度不变，Q_seed 定义在条件模块空间。**

当前 Qwen3-VL-8B 的语言隐藏宽度是 4096，Wan2.2-TI2V-5B 的宽度是 3072。两套方案都在 Qwen 输出之后进行一次 4096→3072 的对接。

| 变量 | 形状 | 含义 |
|---|---|---|
| H_X | [B,L,4096] | 冻结 Qwen 的完整上下文表示 |
| H_content | [B,T,4096] | H_X 中选中的正文内容位置 |
| E | [B,L,3072] | 经映射后的完整证据 |
| H | [B,T,3072] | E 中与 H_content 对应的内容位置 |
| Q_seed 参数 | [1,128,3072] | 共享的可学习初始工作状态 |
| 广播后的 Q_seed | [B,128,3072] | 每个样本的起始工作区 |
| R0、R1、R2 | [B,128,3072] | 首次读取及后续更新得到的状态 |
| C | [B,128,3072] | 提供给 Wan 的统一条件 |

旧图中 Q_seed 的 4096 维，是因为它作为 Qwen 语言层的输入。这里的 Q_seed 输入的是外部条件模块，因此直接使用 3072 维。不会把一个 3072 维向量不经转换送入 4096 维 Qwen 层。

Q_seed 是一张可训练参数表，不是 128 个词表 ID。各行以不同的小随机向量初始化，所有样本共享这套初始参数；读入不同样本的证据后，R 会不同。不预设每个位置的人工物理含义。

**完整证据只编码一次，H_content 是其中明确可定位的内容部分。**

在准备好首帧、caption、clauses 与 analysis 后，冻结 Qwen 编码完整上下文：

\[
E=P(\operatorname{stopgrad}(H_X)),\qquad H=E[:,\mathrm{content\_indices},:].
\]

P 包含归一化和 4096→3072 映射，可训练。E 保留完整上下文位置，包括视觉、内容及上下文辅助位置。每轮读取 E，因此 H_content 对应的内容信息和视觉证据都可以被访问。

H 是 E 中已有的内容位置，不把它再次复制并追加到 E；否则会重复计算同一份内容的注意力权重。这里也不保存并重用 Qwen 的 36 层 K/V：使用的是冻结 Qwen 最终输出的 token 表征，与 H_content_message 保持相同证据来源。

**一次更新做三件直接的事：读证据、交换关系、更新状态。**

第一步，工作状态读取完整证据：

\[
Z=R+\operatorname{CrossAttn}(\operatorname{Norm}(R),\operatorname{Norm}(E)).
\]

Q 来自 R，K/V 来自 E。H_content 的信息作为 E 中相应位置的 Value，通过注意力权重写入每个工作 token。这里有实际的跨 token 数值计算，不是将两组表示并排放置。

第二步，工作 token 之间交换刚读到的信息：

\[
Y=Z+\operatorname{SelfAttn}(\operatorname{Norm}(Z)).
\]

128 个工作位置使用双向自注意力，可以相互读取。它们是连续工作状态，不是正在自回归生成的自然语言 token，因此不需要沿用语言生成的下三角掩码。

第三步，对组合后的状态作非线性更新：

\[
R_{\mathrm{next}}=Y+\operatorname{FFN}(\operatorname{Norm}(Y)).
\]

将这三步合称一个 G 模块。保持常规残差与归一化，不增加专门的融合门控、评分头或关系分类器。G 内不同子层使用各自的参数；同一个 G 在不同轮之间共享参数。

**Q_seed 只在开头初始化，后续轮次直接延续 R。**

\[
R_0=G(Q_{\mathrm{seed}};E),\qquad
R_1=G(R_0;E),\qquad
R_2=G(R_1;E).
\]

R0 表示首次读入证据后的状态。沿用原图“两次追加更新”的计数时，总共调用三次 G。需要较少更新时，也可以在 R0 或 R1 形成输出，长度始终为 128。

每轮都使用相同 E；每轮继续更新上一轮 R。无需再增加 Q_seed+A(R) 的回灌桥，因为整个工作状态始终处于同一个 3072 维条件空间。

```text
首帧 + caption + clauses + analysis
                    ↓ 冻结 Qwen
              H_X [B,L,4096]
                    ↓ P：4096→3072
              E [B,L,3072]
       （包含 H_content 对应的内容位置）
                  │      │      │
                  ↓      ↓      ↓
Q_seed ─────────→ G ───→ G ───→ G
[B,128,3072]      │      │      │
                 R0     R1     R2
               [B,128,3072] 始终不变
                                ↓ Wan 条件对齐
                         C [B,128,3072]
                                ↓
                         Wan 原生条件注入
```

最终直接取：

\[
C=\operatorname{Align}_{\mathrm{Wan}}(R_2).
\]

这里的 Align 是逐 token 的归一化与通道尺度对齐，保持 3072 维和 128 个 token。语义融合已经由 G 完成，不能把 Align 本身称为融合。

**这怎样解决 H_content/R 的拼接问题。**

原先是 H_content 与 R 各保留一组 token，等待 Wan 从两组状态中选择。现在 H_content 的内容已经写进 R，R 内部又交换、整合了这些内容，Wan 只接收统一的 128 个更新状态。

因此，条件模块中没有 H_content 另一路直达 C、绕过 R 的出口，也没有 T 个内容 token 与 128 个 R token 作为两个分组在 Wan 的同一个 C 注意力里争取权重。

普通注意力选择仍然存在：R 选择读取哪些证据，Wan 选择读取哪些 C token。这里改变的是信息先在条件模块中形成统一状态，而不是试图消除所有注意力竞争。Wan 还有自身的原生输入路径，因此这项结构变化不等于保证它一定充分使用 C。

**一个具体的语义处理例子。**

要求是：“前两秒释放烟雾，之后关闭喷口，已有烟雾继续扩散。”内容中包含“来源停止”“不再补充新烟雾”“已有烟雾继续演化”等信息。

交叉注意力允许不同工作位置读取这些内容；工作区自注意力使读取来源条件的位置与读取介质延续条件的位置交换信息；FFN 将组合后的信息写入新的 R。

最终 C 承载的是对“停止来源”和“已有介质仍继续变化”的联合处理结果。这里没有人工规定第几个 query 专门表示哪个概念，信息可以分布在多个位置中。

**S 和 C 的长度从入口到出口都固定为 128。**

不论正文是 80、200 还是 500 个 token，R0/R1/R2/C 都保持 128 个 token。更长正文通过注意力被有选择地汇总；更短正文不会因为有 128 个输出位置而产生更多真实信息。

这 128 个位置都是实际参与计算的工作 token，不是把不足 128 的内容用零填满。内容证据 E 的变长批次仍需 padding mask；C 侧本身不需要为了凑齐 128 再补零。

128 是本方案明确采用的容量预算，不是已经证实的最优关系数量。与 H_content_message 相比，它用固定输出容量换取可控的条件读取长度。

**每头 128 维与 128 个工作 token 是两个不同的数。**

条件模块使用 3072 维、24 个注意力头，每个头 128 维。交叉注意力的形状为：

```text
Q                    [B,24,128,128]  工作 token 数为 128
K、V                 [B,24,L,128]    证据长度为 L
合并后的工作状态       [B,128,3072]   24×128=3072
```

工作区自注意力的 K/V 长度也是 128。这里使用标准全宽 Q/K/V/O，不增加 64 维接口瓶颈，也不更改 Qwen 自身的注意力头配置。

**学习和计算集中在条件模块。**

训练 Q_seed、P、G 与 C 对齐参数，Qwen 保持冻结。固定现成 verifier 的连续反馈可以通过视频生成回到 C，再到 R、G、Q_seed 和 P，止于冻结 Qwen 的输出；不训练新的 verifier。

128×3072 个 Q_seed 参数约为 39.3 万。按两个全宽注意力子层、一个 3072→6144→3072 FFN、一个 4096→3072 映射计算，主要权重合计约 1.262 亿，另有少量归一化/对齐参数。跨轮共享 G，因此增加轮数增加运算，不复制这套权重。

单轮主要注意力的长度因素为 128×L 和 128×128；Wan 读取的 C 长度固定为 128。相对 T 长度的方案，长内容时条件读取可能更省，短内容时也可能增加计算。G 在构建 C 时执行，不在 Wan 的每一层、每个去噪步骤重复执行。

**两套方案分别保留两种清晰的表示选择。**

H_content_message 让每个选中内容位置继续保留一个工作位置；Q_seed128_message 将完整输入读入 128 个可学习工作位置，所有后续关系处理和最终 C 都在这些位置内完成。二者都在形成 C 之前完成跨 token 更新，都不以 H_content/R 的末端拼接代替融合。
