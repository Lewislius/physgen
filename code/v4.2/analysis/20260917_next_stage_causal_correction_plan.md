**下一步建议：把 LoRA 做成必须通过的强基线，把设计目标收敛到“可验证的物理状态控制与误差校正”。** 如果普通 LoRA 加相同监督就能做到同样好，应删减冗余模块；如果模块能在相同条件下改善干预响应、交互时序和组合泛化，它才有独立价值。研究价值需要用对照证明，不应靠限制基线或强行放大模块输出来维持。

本文基于 2026-09-17 的 v4.2 代码与公开研究，给出下一轮实验设计，不代表这些方案已在本项目上验证。此次读取的运行完成到 step 17，仍处于 50 步学习率预热，尚不能依据这轮早期 loss 判断基座上限或模块无效；前次参数与梯度证据见[容量分析](20260917_fm_capacity_and_trainable_scope_review.md)。

**“基座不行”和“模块不起作用”可能同时存在，但需要分开定位。**

| 观察到的问题 | 优先检验的解释 | 有区分力的实验 |
|---|---|---|
| 外观、对象数量、身份保持都不稳定 | 基础生成能力或采样设置不足 | 原生 5B 与另一基座做同任务盲评，先排除实现和设置差异 |
| 画面清楚，但领域动作经常错误 | 数据分布适应不足 | 标准 LoRA＋相同数据的 FM 训练 |
| 对象和动作基本正确，但接触、支撑、响应关系错误 | 缺少明确物理条件与监督 | 对象／事件监督、受控干预测试 |
| 状态预测正确，生成仍不执行 | 写入和执行能力不足 | 给出正确计划的 oracle 对照，再比较不同执行器 |

本地已有 Wan2.2 I2V/T2V A14B 目录，可在确认权重与原生推理链可用后作为对照候选；不能预先断言它一定解决物理问题。I2V、T2V 分开比较，报告分辨率、帧数、采样成本；各模型使用合适的原生设置，并单独补算力预算对照。若最终换基座，应先证明其基础能力收益值得移植，避免同时更换基座、数据、监督和结构而无法归因。

**当前设计最薄弱的是物理语义和输出监督之间的连接。** `STRUCT` 对齐内部 P15 与 JEPA 特征，梯度只进入两个 core；它不会直接要求 writer 把某次碰撞修正。`TEMP` 监督相邻 RGB 差分，也没有明确规定何时接触、冲量向哪里传播。当前训练数据的可靠物体标注数量为 0，因此局部对象分支实际未启用。[梯度路径](/home/liuzhirui/Project/physGen/code/v4.2/train/train.py:58)、[损失定义](/home/liuzhirui/Project/physGen/code/v4.2/physgen_v42/losses.py:13)

因此，“P 更像 teacher”和“视频按物理机制改变”之间仍存在缺口。现有 P 没有被明确绑定到对象身份、速度、接触或作用力等可干预变量，代码也没有成对干预目标。当前实现更适合称为状态特征辅助校正，因果能力尚待证明。给时间注意力增加 causal mask 也不能单独补上这点：生成算法的时间掩码与物理机制的因果关系是两件不同的事。

这也决定了研究定位。[VideoREPA](https://arxiv.org/abs/2505.23656) 已研究视频基础模型到生成模型的时空关系蒸馏；[SARA](https://arxiv.org/abs/2605.07800) 进一步研究按语义分配关系监督。[Tora](https://arxiv.org/abs/2407.21705) 已研究轨迹条件写入 DiT。它们说明相关组件有研究依据，也意味着“特征对齐＋插层控制”本身不足以证明新的贡献；仍需进一步检索和实验，不能据此声称方案具有独创性。

**先建立下面几组对照，特别要保留“LoRA＋同监督”。**

| 对照 | 用途 |
|---|---|
| B0：原生基座 | 测量所有适配的总收益 |
| B1：标准 LoRA＋FM | 测量普通领域微调已经能解决多少问题 |
| B2：LoRA＋同样的输出物理监督 | 区分“监督有效”与“我们的结构有效” |
| B3：LoRA＋相同物理条件＋简单条件编码器 | 区分“多给了信息”与“特殊状态／校正机制有效” |
| M：当前模块；M＋LoRA：联合方案 | 测量当前设计及其互补收益 |
| 最佳联合方案逐项移除模块 | 找到必要的 core、writer、状态与反馈通道 |

主结论应建立在优于 B2/B3，而不只是优于 B0。标准 LoRA 应正常训练、调参和推理，不应人为套上较弱的残差预算。若研究有界适配，再为各方案另做相同约束的对照。比较使用相同训练划分、监督信息和测试条件；另外报告参数量、GPU 小时及推理成本，不能把同更新步数当成同算力。若给模块额外物理变量，基线也必须获得这些变量。

**最优先的改造，是让监督直接落到生成结果。** 从现有可微 VAE 路径出发，在可信的中低噪声位置构造预测视频 `V_hat = D(x_sigma − sigma*v)`；从中读出轨迹、对象关系与事件，计算输出损失，反传到 writer、core，以及启用的 LoRA。推理使用 CFG 时，应覆盖相应预测路径。内部 P 的 JEPA 对齐可以保留为辅助。

| 监督方式 | 具体监督什么 | 主要条件与限制 |
|---|---|---|
| 对象与轨迹监督，优先 | 身份保持、位置、速度、运动方向、可见性 | 需要可靠跟踪／标注；按置信度加权，使用真实时间戳 |
| 接触与事件监督，优先 | 接触时刻、支撑解除、碰撞后响应顺序 | 事件窗口加权，避免背景均值稀释局部错误 |
| 生成路径的关系蒸馏 | 物体间与跨时间关系，而不仅是 P 的逐元素 MSE | 明确回传到真实生成分支；可作为已有 JEPA 缓存的过渡方案 |
| 物理方程与可行性约束 | 适用场景下的非穿透、接触、动力学残差 | 必须知道坐标、尺度、外力及适用机制，不能直接对一般 2D 像素套守恒律 |
| 物理偏好训练，后置 | 同一条件下物理正确／错误的输出排序 | 使用物理标签，控制画质混淆；与 FM 联合，另做独立盲评 |

成本最低的起步方案是将离线对象 mask 与事件时间窗投影到 latent，对 FM 增加归一化的局部权重。这不需要对 tracker 反传，可先解决关键区域被平均误差稀释的问题；它只是调整监督重点，不能单独证明学到了物理机制。GT mask 仅用于训练损失，推理时不能依赖真实未来区域，B2 也应使用同样权重。

关键工程条件是**损失对生成结果必须可微**。离线 tracker 可以提供标签，但带 `no_grad`、硬匹配或离散输出的评估程序不能直接充当反传监督；需要经过校准的可微读出器，或合适的偏好目标。冻结监督网络权重时仍要保留对输入视频的梯度，且不能只让可训练读出头变好、生成结果不变。

当前 JEPA 包装器使用 `no_grad`，现有 `observations` 也被 detach；把新损失挂在这些已断开的张量上不会训练到预期路径。若采用输出监督，应单独测量其梯度与 FM 的方向和规模，而不是沿用仅面向 core 的 STRUCT 分配规则。偏好学习可以参考 [Diffusion-DPO](https://arxiv.org/abs/2311.12908)，但其原始推导针对扩散模型，迁移到本项目 FM/CFG 链路需要适配，不能直接复制公式。

还有一个应避免的伪改进：在固定基座下，`MSE(delta_v, v_target − v_base)` 与当前 `MSE(v_base + delta_v, v_target)` 完全等价。把 FM 改名为“强残差监督”不会增加信息。新的监督必须来自对象、事件、物理约束、真实干预或新的生成状态分布。

**若要研究因果强校正，最值得投入的是成对干预数据。** 普通视频展示了一个结果，通常不足以识别“某个因素改变后会怎样”。[CoPhy](https://projet.liris.cnrs.fr/cophy/) 提供了通过受控初始条件干预研究物理反事实的具体范式。建议先限定固定相机、少量刚体的 I2V 场景，把物体和初始几何固定，再逐步拓展。

| 干预例子 | 在明确条件下应出现的变化 | 应保持的内容 |
|---|---|---|
| 水平滑动中增大动摩擦系数，保持初速度与其他条件 | 停止距离减小 | 对象身份、相机、初始状态 |
| 改变与固定平面碰撞的恢复系数，保持入射速度 | 反弹速度／高度按机制变化 | 外观、碰撞前轨迹 |
| 在时刻 τ 移除唯一支撑，保持此前状态 | τ 后开始失去支撑；下游接触随之变化 | τ 前状态、无关对象与相机 |

数据优先来自可控仿真或实拍；单纯改一句提示词、反转视频、打乱 JEPA token，都不能自动成为真实反事实。单帧无法唯一识别质量、摩擦和初速度时，应提供明确条件、保留不确定性，或限定可识别任务，不能把外观猜测当成物理真值。颜色、纹理与物理参数要解耦，留出新的对象、相机及参数组合，以检查捷径学习。

可以增加成对响应损失：

`L_cf = d(Phi(V_hat_do) − Phi(V_hat), Phi(V_GT_do) − Phi(V_GT))`

其中 `Phi` 是经过校准的轨迹／事件读出，且两条生成都应有各自的绝对目标监督。使用相同初始随机噪声可减少比较方差，但本身不建立因果性。还需验证干预发生前的一致性、无关区域的稳定性，以及接触链下游的正确变化；受影响范围不能只限于被干预物体，因为物理作用会传播。

评价核心是“改变可解释变量后，输出是否按正确机制响应”。仅看到视频变了、随机替换状态后变差，证据都不充分；随机替换可能只是分布外破坏。若另一个状态代表可行的不同未来，就应生成那个未来，不应故意把它训练成坏视频来证明状态重要。

**更强的执行通道应由诊断结果决定。** 我建议将 reader 增加为可读的物理状态估计，例如对象位置、速度、接触关系及置信度；core 根据部署时可得的首图、文本和条件预测目标状态／计划；writer 同时读取计划和当前生成偏差，执行对象与事件位置上的校正。密集 JEPA 特征可以继续提供上下文，但需要明确它与这些可测变量的关系。

先做两个实验：一是使用**正确计划的 oracle 控制**，检验执行器能否实现；二是换成模型自行预测的计划，检验状态推断能否达到同样效果。oracle 需要训练与输入分布相容的控制器，不能仅向现有 writer 塞入陌生 GT 状态后就判断基座失效。真实未来只用于训练监督和显式标注的 oracle 诊断，正式推理只能用可获得或自行预测的条件。

若正确计划可以执行而预测计划不行，优先改善状态预测；若同一正确计划由简单 LoRA 控制器可以执行、现有 writer 不行，优先改 writer。可选改造包括增加后层写入、以状态调制 attention/FFN，或使用状态条件化的低秩增量；先选择一种，不同时堆叠。已有轨迹控制方法是必要的近邻对照，[Tora](https://arxiv.org/abs/2407.21705) 就包含向 DiT 注入轨迹条件的设计。

当前高噪声端的校正预算较小，可能限制早期运动布局调整；低噪声大幅校正又可能损害外观。预算应按噪声阶段、事件位置和观测置信度做单因素对照，不能一律增大。反馈误差在高噪声下不可靠时，应降低其权重，避免根据错误读出过度校正。允许原本正确的生成保持零修正，没有必要设置“最小影响幅度”强迫模块改动画面。

**硬约束更适合施加在明确的状态空间。** 对校准过的刚体任务，可以先把轨迹投影到满足接触／动力学约束的集合，再让生成器遵循修正后的计划。外部研究 [PhysGen（2024）](https://arxiv.org/abs/2409.18964) 展示了物理仿真与视频生成结合的路线，但其刚体适用范围不能直接推广到液体、布料或开放世界。

例如，在已知质量、外力和接触冲量的仿真片段，可监督离散冲量平衡 `m*(v_next−v) ≈ integral(F_ext*dt)+J_contact`。碰撞处必须包含冲量，不能把速度跳变一律当成不平滑错误。未知量不能随生成结果任意调整来消掉损失；仿真中的约束成立，也不等于真实世界的因果泛化已经得到证明。

状态满足约束不保证 RGB 输出也满足，所以仍需要输出反馈。昂贵但有诊断价值的方案是在采样中优化一个小的 latent 修正，使输出物理损失下降，同时限制修正范数。它只能保证所用代理目标得到改善，不能宣称一般视频物理绝对正确；如果这种校正有效，再考虑把它蒸馏进 writer。直接用通用视频评估器做大幅梯度引导容易产生代理漏洞，应放在可靠对象监督之后。

训练也要覆盖真实生成偏差。当前主要从 GT 加噪开始；第 801 步之后每批才有一个一步修复样本。可以在已有采样轨迹的中间状态上做短段、如 2–4 步的可微展开，或收集失败轨迹训练修复，逐步减少只在 GT 邻域有效的问题。这里是原采样过程的一小段，不是把完整 50 步采样直接换成 4 步。普通自由生成可能存在多个正确未来，应优先监督物理条件与事件，避免强迫其逐像素复现唯一 GT。

**建议按照可停止、可归因的顺序推进。**

1. **先完成测量与强基线。** 给当前方案补同条件 `FM_base/FM_corrected`、各损失的梯度和生成消融；训练 B1，建立 24–36 个小场景、多个采样 seed 的开发面板。先分清外观、动作、物理错误，这个小面板只用于筛选方向。
2. **先做一项输出监督。** 从有可靠标注的对象轨迹＋接触事件开始，在 B2 和当前模块上都使用。若收益主要由监督带来，及时接受更简单的实现；只有 JEPA 标签时，先用生成分支关系蒸馏作过渡。
3. **做小规模干预与 oracle 试验。** 可先制作约 100–300 个基础场景，每场景 2–3 个干预条件；按基础场景分割训练／测试，不能让同场景的反事实分散到两侧。这些数量是启动规模建议，不是效果保证。先验证一种机制再扩展。
4. **通过后才扩大控制通道与闭环训练。** 将表现稳定的普通 LoRA 作为所有方案共享的域适配起点，先冻结它测增量模块收益，再考虑联合训练；同步保留可继续训练的 B2/B3，避免冻结基线造成不公平。
5. **用独立评估决定去留。** 同时报告物理／事件成功率、语义执行、身份保持、画质与成本；开发集用于调参，测试集封存。受控场景检验干预响应与组合泛化，开放视频使用独立自动指标加人工盲评。[VideoPhy-2](https://arxiv.org/abs/2503.06800) 可作为开放场景评估参考，不能替代本任务的干预测试。候选收敛后使用多个训练 seed，并以基础场景为单位估计配对差异的不确定性。

| 实验结果 | 下一步决策 |
|---|---|
| B2/B3 已与完整方案持平，移除状态模块也无稳定损失 | 简化为 LoRA＋有效监督，重新界定贡献 |
| 正确计划有效，预测计划无效 | 改善状态可识别性、计划学习与数据 |
| 现有 writer 无法执行，简单条件 LoRA 可以 | 改造执行通道，减少对当前 writer 形式的依赖 |
| 合理控制方案仍失败，另一基座在基础能力与可控性上稳定更好 | 排除训练／映射问题后迁移基座 |
| 模块在相同信息与监督下稳定改善干预响应、组合泛化，成本可接受 | 保留并强化这部分机制，删掉无贡献的组件 |

对当前项目，我优先投入的组合是：**标准 LoRA 强基线＋生成结果的对象／事件监督＋一个小而可信的干预数据集**。先用它们判断状态和 writer 到底缺在哪里，再决定是否增加动态控制、闭环修复或更换基座。最终值得保留的设计，应当在正确输出、可控响应或泛化上提供可重复测量的收益。
