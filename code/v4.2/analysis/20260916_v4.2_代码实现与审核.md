# v4.2 当前实现与审核（2026-09-17 ΔH监督修订）

本文件描述正式默认 `fm_struct_write_repair_trajectory_v1`。方法与公式见[ΔH监督与时序状态增量设计](20260917_v4.2_DeltaH监督与时序状态增量设计.md)，既有视频/训练故障证据见[上一轮分析](20260917_v4.2_监督信号与生成故障修正设计.md)。此前实现文件保存在 `delta_h_quality_20260917/source_before/`。

## 1. 新增的实际学习机制

- `physgen_v42/model.py`：`ConditionTrajectoryInit`用首图/均值、文本、时间空间位置与时长产生16槽P0，两层分解时空attention，输出增量有界且零初始化。I2V也读取文本。正式总可训练参数 **68,266,498**，比上一轮增加3,220,224。旧`static_v1`仍可严格加载旧checkpoint。
- `physgen_v42/write_supervision.py`：构造同视频/同噪声的轻度受扰辅助输入，直接监督两处实际ΔH。目标复用正常FM前向完成写入后的H，stop-gradient；没有第二个5B模型或额外EMA参考前向。
- `physgen_v42/backbone.py`：返回detach的正常写后H；`hidden_prefix`只运行受扰支路的前15层，取得写前H、基座H和P。两处writer可分别缩放，默认均1。
- `train/train.py`：FM仍在标准高斯线性加噪输入训练。辅助STRUCT使用受扰H学习原真实视频状态；WRITE只给writer/gate梯度。目标、观察与P按职责detach，避免WRITE把state空间改成无约束的H编码。

I2V首片在输入、目标、写入和导出中继续保持。P0不读取GT干净未来；训练的真实视频只参与正常加噪/teacher目标/配对参考。推理无需修复支路。

## 2. ΔH监督的可达性与梯度

`L_WRITE`是实际ΔH与有方向参考增量之间的归一化MSE，不是把ΔH压向零的正则。目标使用token/帧两级soft-bound的联合可达范围做径向投影，留0.95余量；已在该范围内的目标不缩小。不能把目标简单硬截在帧budget边界，否则可能逼writer追逐soft-bound无法达到的值。

FM到全部校正参数；STRUCT仅到initializer和两个core；WRITE仅到对应writer（包括gate）。`GradientMixer.accumulate_aux(..., parameters=...)`显式路由，各组累积8条之后按FM方向移除冲突分量。原全模型20%缩放不用于新方案。投影仅约束当前梯度内积，不保证AdamW有限更新或画质单调改善。

目标系数：STRUCT上限0.1、WRITE上限0.05，均200步预热、线性高噪声衰减；保留grad_clip=1、状态/隐藏/velocity原幅度预算。控制台分别显示FM/STRUCT/WRITE贡献，TOTAL(nominal)明确是投影前标量和。

## 3. 配方与兼容

`configs/stability.yaml`是正式新方案。`stability_trajectory_control.yaml`保留时序initializer但无WRITE；`stability_fm_struct_control.yaml`保留上一轮静态initializer与FM/STRUCT。历史TEMP入口quick16/batch1仍引用`stability_legacy_step0100.yaml`。

原Wan/T5/FP32VAE/JEPA资产路径、数据配置和缓存预处理指纹不变。仍为2279 train/121 validation、最多121帧、原512尺寸桶。1200步、每步8普通曝光、每条I2V/T2V等概率、原LR/EMA不变。

正式训练YAML及shell默认 `PREPARE=0`：直接使用原缓存前2400条，跳过bootstrap与所有编码阶段；训练时仍检查缓存身份和文件记录，异常即报错，不自动重算。[参数与启动说明](20260917_v4.2_正式训练参数与启动说明.md)列出实际权重、学习率和提交命令。

新旧recipe或initializer不能混合恢复。训练启动先检查recipe，再进行完整配置/数据/源码/优化器/队列身份核对；没有添加宽泛的checkpoint兼容豁免。新正式方案需新建run，原权重与视频保持原样。

## 4. 监控、固定验证与推理

`physgen_v42/monitoring.py`记录实际ΔH的有效区分位数、能量集中度、逐帧/时空分布；第15层写前相对base的偏移用于观察第5层影响的传播。padding与I2V已知片不参与局部统计。训练step1及每25步全部8条曝光记录，不改变这些曝光的目标。

FM反向hook记录实际ΔH方向上的`dL_FM/da`，撤销micro累积因子；不会混入STRUCT/WRITE梯度。正值表示在当前状态局部放大写入会增大FM，不等于有限关闭该层一定更好。

step0和每100步固定正常加噪health，raw/EMA分别报告。新默认前4个health案例另外做full/half/单writer有限干预与固定受扰恢复检查。受扰端点误差明确叫`endpoint_velocity_mse`，不是标准FM损失；受扰随机数隔离，不改变普通health噪声与训练RNG。EMA验证结束恢复raw参数。

推理支持`VARIANT=full/base/half/writer5_only/writer15_only`。half限幅后缩放，单writer模式仍计算两个P，base跳过全部adapter。P0只用部署条件，缓存一次并在各solver调用reset。

默认UniPC/50/shift5/CFG5/seed42及原checkpoint路径不变；原生源码路径显式设置。输出后缀`_r3_<variant>`，每条自动导出ΔH摘要、曲线及空间图，记录latent逐帧RMS与校正/CFG方向关系。`inference/intervention_report.py`不依赖JEPA，可产生同条件视频配对审核表，拒绝混合不同提示词/图像/画幅/seed/采样/基座资产。

## 5. 验证范围

必要CPU检查：`tests/test_delta_h_repair.py`覆盖5项——padding/已知片统计、FM导数符号、恢复端点恒等式、时序initializer条件/梯度、WRITE梯度隔离与合法目标保持。此前`test_corrected_training.py`6项仍通过，覆盖路径/权重限制、gate首步可学、状态监督梯度、队列/断点、冲突投影和EMA恢复。

真实Wan5B在64×64、5帧完成T2V/I2V两次训练更新，验证标准FM首步等于base、WRITE给两处writer梯度、STRUCT给时序initializer梯度、AdamW/EMA有限；记录[paired_write_training_gpu.json](delta_h_quality_20260917/paired_write_training_gpu.json)。该脚本还检查固定health/干预和随机状态恢复。小尺寸证据不是完整121帧显存或画质结论。

真实5B+FP32VAE正式`sample_case`完成5种variant、4步采样与自动图表/配对报告；零初始化时5种最终latent完全相同，base通过hook确认没有调用core/writer。记录[inference_contract_r3/result.json](delta_h_quality_20260917/inference_contract_r3/result.json)。
