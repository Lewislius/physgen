当前范围收敛到 [ΔH* 原生教师的核心设计](delta_h_native_teacher_core.md)：保留 P 当前的 JEPA 内容加权 MSE 监督，暂不采用本文第 3 项的 Planner 改造及第 7 项对 P 损失的变更。新的教师构造与写入语义以该核心设计为准；本文保留之前的完整候选方案供参考，正式代码均尚未切换。

**1. 核心判断与目标定义**

采用 PhyBridge：冻结稳定的视频生成基线，训练 Physics Planner 和单点 Native Writer；训练时通过冻结 Wan 后半段与真实 GT 构造并验收 correction teacher。该路线有条件可行，关键改进是目标的来源与验收，而不是宣称优化 H 就自动得到正确物理流形。

| 对 ΔH* 的判断 | 能否成立 | 准确含义 |
|---|---|---|
| 属于当前 Wan 层的数值坐标空间 | 可以 | 固定同一个输入、层、sigma、条件和 token 坐标，在该 H 上求导并相减 |
| 是后续 Wan 对生成目标有响应的方向 | 局部可以 | 梯度经过真实 suffix；有限步长效果仍须重新前向确认 |
| H+ΔH* 必然是正常预训练隐藏状态 | 不可以 | 对激活自由优化不保证它落在正常数据形成的状态分布中 |
| 对当前样本的已定义目标有益 | 通过验收后可以 | 真实 FM 不变差、输出物理表征目标改善，限于该样本与计算设置 |
| Writer 学到后仍有同样收益 | 不自动成立 | 学生近似误差可能破坏教师的收益，需要检查学生实际输出 |
| 最终视频必然不闪色且物理正确 | 不可以 | 单步目标、教师表征和完整采样质量之间仍存在差距 |

旧 writer 投影出的 3072 维张量，数学上也属于同一个向量空间；旧方案缺少的是对内容、分布与下游效果的可靠约束。因此不使用“原来不在 Wan 空间，现在天然就在正确流形”作为论据。

文中 ΔH* 指**通过验收的局部教师增量**，不是唯一 GT 隐藏标签，也不是求得了全局 argmin。更准确的名字是 `accepted_delta`。

现有关闭 CORRECTOR 后仍闪色的记录继续有效：新增注入是需要解决的监督缺口，尚不能据此锁定全部闪色来源。

**2. 基线与单点插入位置**

从 `v4-static-lora` 已生成稳定画面的原生 Wan 路径与 `checkpoints/lora_20260917T140727Z_dae2a0/step0800/ema.pt` 开始。冻结原 Wan 和这份 LoRA；将它们合称为基线 B，不把 LoRA 基线误写成未经微调的纯 Wan。

首版只在第 18 个 block 的输出 H18 处修正，对应 30 层模型的 60% 深度；后面保留 12 个冻结 block。位置是合理起点，不宣称后半段会自动把错误增量投影回正常流形。

保持 3072 维 H、原生时空 token、I2V 首帧处理、文本编码和采样接口。Writer OFF 直接走原生基线，不计算会改变主干的旁路；初始 ON 应在相同算术路径下与 OFF 一致。

本方案替代上一份“三处原生层微调＋直接表征对齐”的主方案；现有正式训练与推理配置不自动切换。

**3. Planner 与 Writer 的具体结构**

Planner 读取 H17、首帧、文本、sigma 和时空坐标，输出 1664 维 P；GT 视频不能作为额外输入。采用两个原生 1664 维、26 头的 process transformer block。H→1664 仅用于 Planner 读取，不压缩生成主干；不保留 512 维 P0 网络或跨深度递归状态。

P 与同一 GT 片段的冻结 V-JEPA 2.1 特征进行逐位置余弦监督。P 的含义是预测的视频过程表征；当前数据没有显式状态、力、接触或因果标签，不能把 P 自动解释成已标注的物理变量集合。

Writer 使用**同层 Wan block 的可训练副本**，不采用 `H作Query、P作Value、再投影输出ΔH` 的旧结构：

```text
H17 ──→ 冻结 B18 ──────────────────────→ H18
 │
 ├──→ Planner ──→ P ──→ 原生残差分支的调制
 │                              │
 └──→ 可训练 B18 副本 ───────────┴─────→ H18_candidate

实际写入 C = mask * (H18_candidate - H18)
H18_corrected = H18 + C ──→ 冻结 blocks19–30 ──→ 预测速度
```

副本完整保留 3072 维、24 头、14336 维 FFN，由同一 B18 权重初始化，副本中的已有 LoRA 仍冻结。其原模型可训练参数为 163,656,704。

将 P 按真实时空坐标固定插值到 H17 网格，用 `Linear(1664, 2*3072)` 产生 self-attention 和 FFN 两条原生残差分支的附加调制量，分别加到 Wan 原有 e[2]、e[5]；其余四组调制及原生文本 cross-attention 保持原结构。这一投影共 10,229,760 参数，权重和 bias 零初始化。它控制原生分支的贡献，不直接输出加到 H 的物理特征向量。

初始化时副本与 B18 相同、附加调制为零，因此 C=0。首帧对应 hidden token 的 C 固定为零；Oracle 必须使用相同 mask。训练期间允许副本更新，原基线保持冻结。

这个结构提供预训练计算的归纳偏置，仍不能保证训练后的副本状态总在原始隐藏分布内。最终依据仍是 ΔH* 监督及实际输出。

首版不再增加一个可学习的最终 gate，直接监督实际写入的 C；需要不修正时让 C 学成零。以后如添加 g，必须监督 `g*delta_hat`，不能只监督 gate 前的 delta_hat，否则实际写入量与教师目标不一致。

**4. 将物理目标落到真正重建出的内容上**

固定当前 x_sigma、首帧、文本、sigma 和基线权重。冻结 suffix 的权重，但保留对 H18 输入的梯度。

```python
v_cond = suffix(H18 + delta, saved_context)
z0_hat = fix_first(x_sigma - sigma * v_used, first)
video_hat = differentiable_vae_decode(z0_hat)
features_hat = frozen_jepa(same_32_frame_view(video_hat))
```

`v_used` 使用第 6 项定义的实际推理 CFG 组合。FM 的真值仍是 `noise - clean`，排除固定首帧。相同 sigma 下，干净 latent 重建 MSE 等于 FM MSE 乘 sigma²；二者不是两种独立信息，首版只使用 FM。

物理目标比较预测视频与真实 GT 的冻结视频表征。首版用一个时空 token 关系目标：从有效画面与各个时间片固定选择至多 256 个对应 token，归一化特征，计算 token 间的余弦关系矩阵；对预测与 GT 的非对角关系做平均平方误差。空间关系和跨帧关系分别求均值再等权平均，防止某类 pair 数量主导。短视频重复时间片合并权重。选择坐标在一个 Oracle 的所有候选间保持不变。

该关系目标借鉴 [VideoREPA](https://arxiv.org/abs/2505.23656) 对时空关系的监督思路；这里将它用于**解码后同一个冻结编码器的表征**，并非直接要求 Wan H 拟合 JEPA。该论文在 CogVideoX 上报告普通 REPA 微调可能损伤生成质量；不能据此断言所有直接对齐都失败，也不能把它当成本方案在 Wan 上的验证。

该目标是与物理过程相关的代理目标，不能独立证明数量、接触、守恒或因果关系都正确。固定编码器也有盲区，局部激活优化可能利用这些盲区。若以后有真实轨迹或事件标签，可替换这一目标，不预设当前 JEPA 缓存已经包含显式物理标注。

不能用 `distance(Planner(H), P_GT)` 作为 Oracle 唯一物理目标：那可能仅使 Planner 更容易读出标签，却没有改善 suffix 的生成内容。

**5. 构造并验收 ΔH***

每次只做一次局部方向构造，最多三次步长候选，不更新 Wan、Planner、Writer 或 JEPA 参数。所有操作在单个样本上进行，不能用 batch 平均收益替代各样本验收。

1. 令 `h = H18.detach().float().requires_grad_(True)`；先计算基线的条件分支 FM、实际 CFG 输出 FM 和输出物理目标。
2. 分别对 h 求 g_FM 和 g_phy，先对两者应用与 Writer 一致的首帧/有效 token mask。g_FM 来自条件分支的标准 FM；物理梯度经过真实 suffix、CFG、VAE 和冻结 JEPA。
3. 以 d=-g_phy 为候选方向。若 g_FM·d>0，去掉沿 g_FM 的上升分量。若 g_FM 范数接近零，不使用不稳定除法，直接交给真实候选验收。

\[
d_{\mathrm{candidate}}
=d-\frac{\max(0,g_{\mathrm{FM}}^Td)}{\|g_{\mathrm{FM}}\|^2}g_{\mathrm{FM}}.
\]

这一投影在非零梯度、精确算术下只保证 FM 的**一阶变化**不为正。它不保证有限步长安全；例如沿某方向一阶导数为零，二阶项仍可以增加损失。物理梯度与 FM 完全对抗时，该方向可能变成零，没有理由强行制造非零标签。

4. 将初始候选的 RMS 设为有效 H RMS 的 1% 作为局部搜索起点，依次尝试这个步长及其 1/2、1/4。该比例是待校准的搜索半径，不是“正确性的证明”，也不在推理时对 Writer 再套固定限幅。候选方向几乎为零、含非有限值时直接拒绝，不归一化放大数值噪声。
5. 对每个候选，实际重跑 suffix 与物理评估。必须同时满足：条件 FM 不增加；部署 CFG 下 FM 不增加；物理目标下降超过计算重复性所确定的容差。接受优先级考虑 FM 和物理改善裕量，不优先选择刚好卡在边界的目标。
6. 使用已有 FM 的逐 latent 时间片误差检查局部退化，首版拒绝任一有效时间片误差增加超过 `max(数值容差, 旧误差的1%)` 的候选。它是验收条件，不是新增闪色损失；全局平均改善仍不能保证每个物体或像素都改善。
7. 在通过的候选中取物理目标最小者；近似相同时取更小增量。保存实际经过加法、dtype 转换并送入 suffix 的增量，不能监督一个前向舍入后根本没有生效的微小理想值。

验收结果分开记录：`accepted` 是有效非零教师；`rejected` 表示本次有限搜索未找到可接受方向；`invalid/uncomputed` 表示教师失效或未运行。对于 rejected，零增量可以作为保留基线的策略目标，但不能声称证明零是最优；invalid/uncomputed 不作零标签。

不将有限搜索结果写成求得了 argmin。新目标也不是额外的 GT 物理真值；它把已有 GT 目标经冻结生成器转化为可直接蒸馏的局部执行示范。

**6. 验收包含真实 CFG，学生不能自动继承教师保证**

为保持单个可优化隐藏状态，首版明确采用：**条件分支启用 Writer，负提示词分支保持冻结基线**。CFG 公式不变：

```python
v_cfg = v_negative_base + guidance * (v_cond_corrected - v_negative_base)
```

这是本方案明确选择的新分支策略，不冒称与原 V4 双分支写回完全一致。按当前使用的 guidance=5 构造与验收教师；在给定样本里，负提示词基线输出可以缓存。变化后的条件速度在这里会放大 5 倍，单独验收条件速度不足以约束实际输出。

Oracle 的物理目标在上述 CFG 输出重建的视频上计算，同时核对条件 FM 和 CFG FM。新的 guidance 或改为双分支 Writer 都会改变验收对象，不能直接沿用旧教师结论。若以后扩展到双分支，必须联合验收两路增量，不能只分别通过再假设组合安全。

学生正常前向使用其预测的 C，绝不把 ΔH* 替代 C 后再计算学生 FM。Oracle 得到标签后完全 stop-gradient，不反传穿过搜索过程。

在已经运行 Oracle 的样本上，额外记录学生自己的条件/CFG FM 和物理目标，得到 `student_accepted` 与教师改善保留率。教师通过而学生未通过，说明蒸馏尚未成功；ΔH 拟合 MSE 较小不能替代此判断。教师收益没有裕量时尤其容易发生这一问题。

**7. 三项学生损失与训练条件**

\[
L=L_{\mathrm{FM}}+\lambda_\Delta L_\Delta+\lambda_P L_P.
\]

- L_FM：实际学生写入 C 后的标准条件分支速度误差；完整图经冻结 suffix 反传到 Writer 和 Planner。
- L_delta：实际 C 与停止梯度的 accepted_delta 的原生 H 空间 MSE；经过搜索但 rejected 的样本可用零策略目标。首帧 token 不参与。
- L_P：预测 P 与冻结 JEPA(GT) 的有效位置平均余弦距离。不平均掉全部时间信息，也不以推理不存在的完整 GT 初始化学生。

保持 I2V、最多 121 帧、JEPA32、有效 batch 8、800 步、每 100 步保存。x_sigma 仍按标准 FM 从 GT 加噪构造；“GT 只进教师”指不提供额外干净未来条件，不是禁止正常加噪训练使用 GT。

训练首版不使用文本 dropout 训练一个带 Writer 的空文本分支；负提示词基线已经冻结。需要空提示词生成时，应将其纳入条件分支的数据覆盖，不能认为已自动验证。

学习率起点：原生 block 副本 1e-5，新 Planner 与调制投影 1e-4；100 步学习率预热。L_P 系数从 0.05 起、200 步辅助预热。L_delta 的系数通过少量有效教师样本，在同一 Writer 参数上一次性标定加权梯度为 FM 的约 20% 起点，随后固定；不能按旧 WRITE 的 1.0 直接继承，也不在每步投影或裁剪学生参数梯度。

首版每个 optimizer step 的 8 个 microbatch 中轮换 1 个运行 Oracle，全部样本计算 FM 和 P。L_delta 按实际已评估教师样本数单独平均，不能又除以 8 导致贡献缩小八倍；对 accepted/rejected 的占比分开记录。该频率是成本起点，不是已证明足够的教师覆盖率。

如果几乎没有非零通过样本，或者教师改善很小、只覆盖少数 sigma，暂不声称模型学会了物理修正。有限方向搜索可能过于保守、目标可能冲突，或高噪声下一步重建不足以可靠评估；应先查这些日志，再决定是否增加搜索方向或教师计算频率。

**8. 现有代码的复用与必须处理的接口**

- 原生 Wan 与 I2V：参考 `v4-static-lora/static_lora/backbone.py` 和 `native_wan.py`；使用正确的原生 forward，在单一 block 接入包装。不要将现有 ProcessWan 关闭 CORRECTOR 后的路径直接视为已验证稳定基线。
- 可微解码：`physgen_v4/encoders.py:DifferentiableDecoder` 已存在。121 帧的因果 VAE 解码需保留时间上下文，不能直接抽取 32 个 latent 时间片独立解码。分块重算必须保留梯度和缓存依赖。
- 冻结 JEPA 的输入梯度：`physgen_v4/remote_teacher.py`、`tools/teacher_worker.py` 已有跨运行环境反传接口，可复用一阶 VJP；本方案不需要二阶梯度。GT 特征可缓存，预测视频的 JEPA 前向与输入反传不能被缓存 GT 替代。
- 采帧：当前 `VideoTeacher.forward` 默认 uniform，而当前 GT 缓存为 adjacent_pairs。必须把实际帧索引贯穿 remote teacher 与 worker，确保 GT 和预测使用同一 32 帧、同一 letterbox 和有效权重。当前 out_weight=0，因此这个未启用分支的差异不是已有闪色视频的已证实原因；它是接入新 Oracle 时必须修复的错位。
- 数值与显示范围：现有可微 decoder 会 clamp RGB，严重饱和会使部分梯度为零。记录原始输出范围与饱和比例，异常样本不形成可信教师；不能通过 clamp 后的特征 loss 掩盖失真的输出。
- Oracle 对 H 求梯度前 detach 冻结前缀，避免保留无用前缀图；学生副本之后的冻结 suffix 保留梯度。候选验收用无梯度前向，每次结束释放教师图，不把多个候选图保留到学生更新。
- 新配置、checkpoint 和入口使用独立的 phybridge 架构标识，保存冻结基线身份、位置、CFG 分支策略、教师规则、Planner、block 副本及调制层参数。旧 CORRECTOR checkpoint 不做兼容加载。

**9. 计算量与完成标准**

“一次梯度＋三个候选”仍包括一次 suffix/VAE/JEPA 的可微评估、两个目标对 H 的梯度，以及最多三次候选的 suffix/VAE/JEPA 前向；带真实 CFG 验收还需要负提示词基线计算。它不是一次普通 FM 前向的成本。96GB 可运行性须在接入时核对峰值显存与单步时间，本设计未运行 GPU 验证。

最小核对只覆盖：OFF 与冻结基线等价；初始 ON 等价；teacher/student 使用同一插入语义与 mask；预测特征确实对 H 有非零有效梯度；接受条件按实际写入与实际 CFG 计算；有效教师能被学生学到；保存后能恢复同一计算。

质量判断保留完整视频：先看已有 P03/P06/P11 闪色场景是否稳定，再看有明确运动、数量与接触关系的少量既有案例。只需要针对性的验收，不启动多组无关 ablation。若 OFF 本身不稳定，先恢复稳定基线；若只在 ON 恶化，在同一基线和其他设置固定的前提下定位 correction 路径。

高噪声输入与首帧/文本通常不能唯一决定训练视频；教师知道的 GT 细节未必可由学生推断。MSE 蒸馏可能平均不同有效修正，完整多步采样也会遇到训练中未覆盖的 H。因此“非零教师有效、学生保留收益、完整视频改善”是三层分别需要满足的结果，不能相互替代。

激活梯度控制有 [PPLM](https://arxiv.org/abs/1912.02164) 的方法先例；通过生成 RGB 的可微评估反传到视频生成器有 [VADER](https://arxiv.org/abs/2407.08737) 的依据。这些支持构造方法的可行性，不证明本 PhyBridge 已获得正常隐藏流形、已经解决闪色或具有未经比较的研究新颖性。
