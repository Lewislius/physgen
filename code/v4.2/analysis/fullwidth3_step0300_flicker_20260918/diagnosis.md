**新版 V4.2 step0300：闪色、形变与运动不足的代码及记录分析**

对象：`v42_fullwidth3_write_20260918T081555Z_1x96g`，无 PRIOR 训练的 `checkpoint-0000300`。
纳入用户提供的 `logs/experiment_62293_trial_63458_logs.txt`、对应 steps/micro JSONL、实际 checkpoint 配置、20 个现有视频，以及 V4 / v4-static-lora 的现有视频。下文区分直接观测、目标函数性质与尚待验证的因果解释。

**1. 直接观测：进入解码器前，latent 的时间变化已经异常。**

P03/P06/P11 等存在整片红、黄、绿色变化，P01/P04/P05 等同时存在应有事件未发生或运动很少的问题。不能把这批结果称为已经恢复 V4 的视频质量。

统计量定义：每帧 RGB 在空间上求平均，然后计算相邻帧平均色彩的绝对差，RGB 归一化为 0–1；跳过前几个帧间隔。20 个视频的该指标平均值：

| 现有输出 | 平均颜色跳变 |
|---|---:|
| 新 V4.2 step0300 | 0.053006 |
| V4 原输出 | 0.000711 |
| v4-static-lora 原输出 | 0.001299 |

这只量化全局闪色，不是物理正确性或完整视频质量评分。三个训练模型和 V4 的长度设置不同，因此该表不能单独作某个架构改动的因果证明。

P03 完整新模型的实际生成 latent：相邻 latent 时间片、各通道空间均值的差分 RMS 为 **1.33547**；现有 LoRA P03 为 **0.18717**。完整新模型的 latent 总 RMS 为 1.45965，LoRA 为 0.99883。变化不是仅由视频编码器产生，最终 latent 中已经有很大的全局通道偏移。不同 latent 时间片的通道均值漂移可以被 VAE 解码成颜色变化；数值尚有限并不能证明其分布正常。

必要的边界：同一个坏 latent 重新解码，TF32 开/关的颜色跳变分别约 0.146219 / 0.146229，未支持解码精度是本例主因。关闭所有 CORRECTOR 调用，当前 Wan/Euler 路径的 P03 仍有严重闪色，颜色跳变约 0.150016。因此，**“新增 WRITE 或 P→H 写回是所有闪色的唯一来源”不符合已有证据**。关闭写回也不是解决方案。用户要求后已终止 solver 核验 62304，不将其当作有效比较结果。

对应数据：`record_audit.json`、`latent_statistics.json`、`p03_probe/report.json`、`p03_probe/frames.jpg`。

**2. 当前没有发现 48 维 VAE latent 与 1664 维 JEPA 状态直接相加的实现。**

实际路径：

```
视频 latent x_t: 48 通道
  → Wan 隐藏特征 H: 3072 维
  → read_norm + learned read: 1664 维 observation
  → P + observation + position + condition → StateCore → 更新 P
  → H 查询 P 的 cross-attention
  → write_norm + gate + learned writer: 3072 维 ΔH
  → H + ΔH → 后续 Wan blocks → 48 通道预测速度 v
```

同一写回点的 reference/student 使用相同 block、sigma、坐标和 P0；代码没有把第 5 层 H 直接拿来减第 25 层 H。`write_residual` 的投影和加法顺序沿用 V4。

但这些只能证明张量和对应关系成立，不能证明**学出来的 ΔH 是保真、保色、保物体身份的方向**。跨注意力和输出矩阵必须靠训练目标学会语义对齐；参数恢复到 1664 维并不自动获得这种能力。

**3. 最值得纠正的新增设计：WRITE 实际是自一致性约束，不是独立的正确写回监督。**

`physgen_v4/write_supervision.py:42` 的目标可写成：

```
L_WRITE = || H_bad + W(H_bad, P_bad)
             - stop_gradient(H_ref + W(H_ref, P_ref)) ||²
```

这里 ref 是当前模型在未额外扰动的 noisy training input 上的输出，仍然包含同一个模型自己的写回。它不是 GT Wan 特征，也不是已证实的视频重建正确方向。detach 只切断目标分支梯度，不使目标自动正确。

一个可以直接从公式确定的性质：当两路输入一致时，任何 W 都可以令 L_WRITE=0；同时现有 `no_write_mse - mse` 可以等于 ||W||²。因而日志中 `mse_gain>0` 不能当成物理修复或重建质量提升的证明。当前目标可以用于局部扰动一致性，但此前把它描述为足以保证正确写回的“修复监督”过强。

扰动形式也有限：主要是小幅空间 warp 和平滑通道漂移，幅度乘以 sigma*(1-sigma)，最大约为 clean latent RMS 的 5%。训练因此没有直接覆盖自由生成时已经观察到的大幅、逐时间片通道漂移。不能期待只增大同一个 WRITE 权重就解决这个分布差异。

**4. 无 PRIOR 并没有去掉 GT 视频对主生成分支的输入。**

`train/train_native_p.py:321` 给主 FM 分支传入 `gt_video=sample['latent']`，再通过 P0 初始化器使用整段干净视频；dropout 为 0.25。

提供的流程日志以及结构化日志一致：前 300 步中 **227 步有 GT、73 步无 GT**。step276–300 中 24 步有 GT。推理没有完整 GT 视频。因此“无 PRIOR”只表示 prior_weight=0，并不表示训练完全是推理时的 image+text 条件。这是训练—推理条件差异，会给依赖未来信息的 P 状态及其写回留下捷径。

该机制 V4 原来同样存在，不能凭它单独解释两版质量差距；但它是需要修正的训练设计。去掉 PRIOR 之后，P0 仍从 STRUCT 和 FM 获得梯度，并非没有训练。

**5. 三个 CORRECTOR 的状态更新没有形成三个有效的逐层修正步骤。**

P03 推理条件分支在 50 步中的平均值：

| 位置 | state gate | ||ΔH|| / ||H|| |
|---|---:|---:|
| A@5 | 1.000000 | 19.28% |
| A@15 | 0.000939 | 15.97% |
| A@25 | 0.0000018 | 10.70% |

后两层 P 更新几乎关闭，但仍然从 P 检索并向 Wan 写回。不能把这描述为三次有效的物理状态纠正。

同一个 P03，V4 的 A@15 写回比例约 4.42%，新版本约 15.97%，约为 3.6 倍；A@5 由约 13.73% 变为 19.28%。因此目前已经不是旧窄版“写回太弱”的情况。比例不等于错误程度，但足以说明不能继续以“多加写回就会更好”为默认判断。

V4 原版同样有后层 state gate 接近零的现象。门饱和可以解释“结构状态没有逐层改善”的限制，不能单独作为新版独有闪色的根因。

**6. 新日志不支持沿用旧版“WRITE 与 FM 严重对抗”的结论。**

流程日志第 300 步（文件第 662 行）：

| 项目 | 数值 |
|---|---:|
| FM | 0.14107311 |
| weighted STRUCT | 0.13727930 |
| weighted WRITE | 0.00123182 |
| 梯度裁剪前全局范数 | 0.04811185 |

不能用单步 loss 或不同 sigma 下的训练 loss 直接判定视频质量。step100–300 的九次单 micro 梯度诊断中，三个 CORRECTOR 的 WRITE/FM 梯度范数比平均约 2.8%、3.0%、3.1%；FM/WRITE 余弦平均约 0.008、0.008、0.011，既有正值也有负值。记录的 FM 与联合梯度内积均为正。这些是单 micro 观测，不是累积 Adam 更新的因果证明；但也没有证据支持“WRITE=1 已压倒 FM”。

STRUCT 在 A@5 的梯度可明显大于 FM，而后两层状态门饱和后 STRUCT 梯度很弱。状态特征拟合和视频重建并不是同一件事，需要分别观察。

前 300 步的最大全局梯度范数仅 0.49613，clip=1 未触发。因此删除梯度裁剪不是这次问题的修复。

**7. 为什么物体不动、物理事件不发生。**

当前 STRUCT 主要约束 JEPA 特征的逐位置 MSE；WRITE 约束自身特征一致性。两者都没有直接要求与 GT 对齐的时间变化或事件发生。较高的特征余弦可能主要来自物体、背景等静态信息，不能当成碰撞、倾倒、流动等正确性的证据。

训练 2279 条记录的 caption_scope 全为 `video`，而实际取原视频中心最多 121 帧。视频级说明不保证与选中几秒内的事件逐项对应。这是运动指令与可见事件不匹配的风险，不代表已经证明每个选中片段都缺少事件。

现有验证在单卡上每个 sigma 只用一条固定验证视频；它是 59.94fps、约 2 秒的 121 帧片段。该验证的 sigma=0.10 FM 从 step100 的 0.401215 到 step300 的 0.400921，几乎未变；sigma=0.98 则从 0.272238 降到 0.188408。它不能覆盖 demo 的全部场景和 5 秒自由生成，单步加噪重建改善也不等于长轨迹稳定。

**8. 当前改造方向。以下为待实现方案，不是已经验证的画质修复。**

详细实施采用[原生 Wan 物理监督方案](native_wan_physics_implementation.md)。

1. 从已经生成稳定画面的 v4-static-lora 原生路径和 step0800 EMA 基线开始，训练 Wan 第 5、15、25 个原生 block；维持 3072 维 H，取消外部 P、P0、状态门与 P→ΔH 写回。
2. 最终预测继续接受真实 FM 目标；第 5 层增加只用于训练的读取头，以同一 GT 片段的冻结 JEPA 特征作为独立辅助目标。读取结果不注入主干，不构造所谓正确的 H_GT 或 ΔH_GT。
3. 主条件始终为首帧和文本，GT 仅用于标准加噪训练与目标构造。保留实际时间、空间坐标及有效内容对应，使用 121 帧上限、JEPA32 和仅 I2V。
4. 删除多空间尺度和相邻时间差分的闪色损失建议。历史颜色跳变统计仍保留为观测记录，不作为新训练目标。
5. 新结构不继承旧 WRITE/PRIOR，也不沿用旧 CORRECTOR checkpoint 接口。用原生预训练层和真实监督减少未经校准的外部写回风险，是否修复闪色必须由生成结果确认。

这次更新了实施文档；正式训练、推理配置和既有 checkpoint 未切换。已有关闭 CORRECTOR 仍闪色的记录说明，只删除写回不足以宣称解决全部问题。
