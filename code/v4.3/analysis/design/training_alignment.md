# V4.3 训练对齐与学习率选择

> 本文记录现有实现及历史配置依据；当前设计与效果结论见 [分析入口](../README.md)。稳定基线为 STRUCT=.1、Oracle=1，不能将默认 YAML 的 .01/60 当成质量推荐。

V4.2 的源代码、配置、权重和缓存均不修改。V4.3 默认配置为 `configs/flow_oracle.yaml`，同结构消融为 `configs/fm_struct_control.yaml`。

GT输入策略、原生3072维交互和三损失是已说明的设计变化；不能将跨版本全部收益归因于Oracle。同结构有/无Oracle配置使用完全相同的5e-5学习率及数据设置。数据顺序与sigma采样规则对齐不等于两种不同计算图拥有逐位相同的完整随机过程。

当前两个辅助损失的固定权重按初始 V4.3 运行第 27 步静态校准：200 步预热结束后，STRUCT 和 Oracle 分别约占 FM 的 5.73% 和 5.66%。初始运行使用 `struct_weight=0.1`、`oracle_weight=1.0`。新设置以各占约 5%～10% 为起点，后续实际比例随损失变化；无 Oracle 对照同步采用 STRUCT 权重 0.01。

## 学习率依据

检查了V4.2两组已完成的800步日志：

- `v42_v4_fullwidth3_with_prior_A1_1x96g_20260918T071246Z-9b14ea9f`：最大裁剪前梯度范数0.5985；全部训练步裁剪系数为1。固定验证样本的五sigma平均FM从第100步0.1882降至第800步0.1630。
- `v42_v4_fullwidth3_without_prior_A1_1x96g_20260918T071253Z-9945c9d7`：最大裁剪前梯度范数0.4961；全部训练步裁剪系数为1。对应验证FM从0.1993降至0.1678。

日志位于原V4.2的 `train/train_log/<run>/<session>/steps.jsonl`。这些数据不支持“V4.2的1e-4已经过大”，也不能证明V4.3应直接沿用。验证每rank只有一个样本，不能代表全部视频生成质量。

V4.3同时改变了P/H双向交互、映射、writer及监督。writer仍零初始化，但使用3072维直接输出，未沿用旧writer的外部幅度门。选择峰值5e-5是给首轮更新留余量的工程判断，保留原100步warmup，避免把学习率直接降到很小而让新增模块在800步内难以学习。所有模块先用同一学习率；不预设某个尚未测量的分组倍率，也不按参数量机械缩放。该值不是通过V4.3学习率搜索得到的最优值。

训练中已有 `learning_rate`、`grad/global_norm_before_clip`、`grad/clip_coefficient`、各层 `write_relative_rms` 与Oracle接受/改善指标，可在后续实际训练中判断。若固定验证FM恶化且写回幅度持续增大，再对比2e-5；若稳定但进展不足，再与1e-4做同设置比较。不能仅凭训练loss或参数量判断。当前不自动启动这些额外实验。

Oracle `relative_step=0.01` 表示一次候选H修改的RMS为该层H RMS的1%，失败时回溯减半；它只用于构造detach目标，与AdamW的5e-5分别控制不同变量。
