# V4.4：原生物理写入与生成主流程监督方案

日期：2026-09-21。状态：**实施设计已整理，V4.4 训练代码及训练结果尚未完成。**

本版针对三个问题修改结构和训练：P 学到的信息能否写进 H；写入是否带来正收益；Oracle 的临时优化能否变成正常推理时学生自己的能力。总目标正式按 **四个主损失：FM、P/STRUCT、注入收益 Gain、Oracle 效果蒸馏** 组织。原编号 8、9、10 是 Gain 内的三个计算分量，不是三个独立训练任务；连同原编号 1、2 和 Oracle，展开后仍为六个标量计算，统一更新同一套学生参数。

本次按用户要求只修订设计文档，不修改训练代码、配置或启动训练。以下“必须”均是后续实现要求，不表示当前 V4.3 已具备这些行为。文档可以规定计算图和更新方式，不能提前保证最终生成效果。

本次补齐正收益、连续采样和分阶段优化三个设计环节：

- **第 9 项增加 Oracle 正收益目标。** Oracle 在联合微批中直接优化输出动态；学生即使已经略优于关闭写入的基准，只要没有达到教师正收益的指定比例，仍会收到改善动态的梯度。
- **两步训练采用实际部署的 UniPC、噪声序列和 CFG，并携带正确的求解器历史。** Oracle 评价第二次预测的干净视频估计，蒸馏则比较第二次实际采样更新后的状态，梯度穿过学生两次调用。
- **推荐分三个阶段接入上述目标。** 先让新 writer 学会去噪写入，再引入动态正收益，最后打开两步之间的完整反传。三个阶段复用现有训练数据，具体梯度冲突分析、参数组和数据来源见第 8 节。

不增加画质专项损失、独立 H 物理读出器、人工物理标签、额外 P 时间/关系损失、隐藏 ΔH 回归或独立的短程采样损失。两步采样按后续讨论纳入 Oracle 联合训练；此前“两次 Euler 大步直接到零”的草案由本文替代。

## 0. 本版必须发生的实际修改

本版交付的核心是修改 forward、训练目标的计算对象和 optimizer 更新链。仅增加名为 gain、physics 或 oracle 的日志，不满足本版定义。

| 修改位置 | V4.3 当前行为 | V4.4 必须替换成的行为 | 为什么会改变训练或推理 |
|---|---|---|---|
| 单处 Corrector 的 forward | 两个交互块连续计算内部特征，末端一个 writer 加回原 H | 第一个交互块后执行 writer₁/step₁ 得到 H¹；第二块读取 H¹，再执行 writer₂/step₂ 得到 H² | 第二轮处理的是已改变的真实生成状态；两组 writer/step 都进入 optimizer，推理也运行这条路径 |
| Oracle 学生目标 | 学生 ΔH 拟合停止梯度的 Oracle ΔH* | 学生自己生成 ΔH，再经真实 Wan 后缀得到输出；这个输出与 Oracle 的更优输出计算误差 | Oracle 项的梯度必须穿过实际生成后缀，优化产生有效输出的写入参数，隐藏向量距离不再是学生目标 |
| 注入收益的处理 | 没有本文定义的局部/整体收益训练项 | 相同入口计算 on、local_off、Wan 基准；组装 Gain，加入四项总目标 | 负作用及动态收益不足进入 backward；比较分支固定，不能通过把基准变差来降低损失 |
| 输出动态的入口 | 原 STRUCT 比较 P 与 GT JEPA 特征 | 学生写后 H 产生干净视频估计，经可微 VAE/JEPA 得到动态误差，进入 Gain 的第 9 分量 | 误差通过生成结果回到 writer；不能用 P 的拟合分数或离线视频评分替代 |
| 连续去噪的更新 | 标准单次加噪任务 | 保留标准 FM 分支，并加入真实 UniPC 两步窗口；C 阶段跨步 latent/history 不 detach | 第二次调用的输出误差能够训练第一次写入；不只是把第一步结果存下来再单独训练第二步 |

上述修改复用四个主损失，不追加更多损失名称。原 8/10 是 FM 的条件重加权，真正改变目标内容的是输出动态正收益和 Oracle 输出/采样状态蒸馏；不能把重新分组本身当成算法创新。

### 0.1 对 V4.3 和冻结主干的准确界定

V4.3 的 Oracle 不是只有日志：[losses.py](../../physgen_v43/losses.py) 将有效教师的隐藏 ΔH 回归加入总 loss，[train.py](../../train/train.py) 对学生图执行 backward 和 optimizer.step。它的缺口是**学生 Oracle 项没有直接以真实后缀输出的改善为拟合对象**；隐藏回归已接入不等于已学会教师收益，也不能据此认定生成有效。

现有 Wan 权重在 [backbone.py](../../physgen_v43/backbone.py) 中被冻结；V4.4 首版也保持这个参数范围。必须区分三件事：

- Wan 参数不更新：本版的明确选择。
- 写入改变 Wan 后续计算及输出：本版实际训练的作用位置。
- 输出误差经过 Wan 的运算回传给 writer/交互参数：本版不可缺少的计算图。

因此本版训练的是“怎样驱动冻结 Wan 产生更好的输出”，不声称在更新 Wan 原生权重。冻结 Wan 参数时仍须计算相对于输入 H 的梯度，不能用 no_grad 包住学生的生成后缀。若以后决定微调 Wan 权重，需单独修改可训练参数范围和优化器，不能以本版措辞代替这项工作。

## 1. 修改什么，以及为什么

| 现有缺口 | 本版修改 | 实际训练作用 |
|---|---|---|
| P 的 JEPA 拟合好，不代表 H 得到有效信息 | 每处两个交互块分别执行真实 H 写入；所有生成目标经过写后 H | writer、步长头及 P/H 交互参数接受真实输出梯度 |
| ΔH 可能使预测变差 | 局部 FM 收益 8、整体 FM 保护 10 | 相对基准变差的样本增加 FM 梯度权重 |
| 只罚负注入，零写入也容易满足 | 第 9 项要求达到有效 Oracle 动态收益的 50% | 零写入、负注入和收益不足均可产生梯度 |
| Oracle 自己优化了，学生没有学会 | 用更优输出/采样状态蒸馏替换隐藏 ΔH 数值回归 | 临时搜索结果进入共享学生参数 |
| 单次训练改善未必适用于连续推理 | 在真实采样配置下展开相邻两步，保留跨步梯度 | 第二次调用读取学生自己产生的状态，前一次修正也接受监督 |

这里“监督 H”指监督 **H 经过真实 Wan 后缀后的作用**。无需另外训练一个 H 分类器，也不把 P 的分数当成 H 的效果。

## 2. 架构：每个交互块后真正写一次 H

### 2.1 保留原生宽度和同时交互

保留 Wan 第 5、15、25 层后的三个位置，P/H 主通路均为 3072 维。每处仍使用现有两个 JointPHBlock，改为两个独立 writer 和两个小型步长头：

~~~text
(P⁰, H⁰)
  → 同时交互块 1 → (P¹, Z¹)
  → writer₁ 产生方向、step₁ 产生倍率
  → H¹ = H⁰ + ΔH¹

(P¹, H¹)
  → 同时交互块 2 → (P², Z²)
  → writer₂ 产生方向、step₂ 产生倍率
  → H² = H¹ + ΔH²

H² → 下游 Wan
P² → 下一个位置及原 JEPA 解码头
~~~

同一个 block 内，P/H 都读取同一组写前状态，同时交互；第二个 block 才读取已经更新的 P¹、H¹。不能继续让第二个 block 只读取内部特征 Z¹，绕过第一次真实写入。

每个 writer 为 3072→3072，每处新增一个约 944 万参数的 writer。步长头读取归一化的 H/P 摘要和噪声条件，首版只输出每样本、每轮一个标量；不新增逐 token 步长。

### 2.2 写入和初始化的具体约定

~~~text
方向 = writer(LayerNorm(Z))
倍率 = sigmoid(step_head(H摘要, P摘要, 噪声条件))
ΔH = 已知首 latent 保护 mask × 倍率 × 方向
写后 H = FP32(写前 H) + FP32(ΔH)
~~~

首版倍率上限设为 1，初始值设为 0.1；步长头最后一层权重置零、bias 约为 −2.197。两个 writer 的输出权重及 bias 零初始化。这样第一次更新可以训练 writer；当 writer 离开零点后，生成损失进一步训练步长头和上游交互。不能宣称零初始化时所有路径都立即具有非零梯度，更不能把 writer 和乘法门同时置零。

倍率上限不等于 ΔH 的 RMS 上限，本版不另加残差幅度损失。Oracle 的相对步长只控制临时教师搜索，也不冒充部署 writer 的硬限幅。

可迁移 V4.3 匹配的初始化器、交互块和 P 解码器；两个 writer 按上述规则重新初始化。使用独立 V4.4 架构标识及新优化器，不作为旧 checkpoint 的原样续训。

每次 Wan 调用都重置 P；CFG 条件和空文本分支分别初始化。推理仅使用首图、文本、当前 noisy latent 和噪声条件，不使用未来 GT、在线 JEPA 或 Oracle 搜索。

## 3. 损失总表：四个主损失，Gain 包含三个分量

### 3.1 首版完整目标

| 主损失 | 原编号 | 实际计算内容 | 预热完成后的外层系数 | 计算位置 |
|---|---|---|---:|---|
| FM | 1 | 标准配对加噪样本的 FM MSE | 1.0 | 每个微批的标准 FM 分支 |
| P / STRUCT | 2 | 原 P 与 GT 的 JEPA 特征拟合 | 0.1 | 同一标准分支，沿用原 P 解码点 |
| Gain / 注入收益 | 8、9、10 | 0.5×局部 FM 负作用 + 0.1×动态收益不足 + 0.5×整体 FM 退化 | 1.0 | 8/10 每微批计算，9 在联合微批计算 |
| Oracle 效果蒸馏 | — | 基础 velocity 蒸馏，或联合采样状态蒸馏，二选一 | 1.0 | 按微批模式选择 |

完整阶段的总损失如下；阶段 A/B 的启用范围及新增分支预热见第 8 节：

~~~text
LGain = 0.5 × L8 + 0.1 × L9 + 0.5 × L10

L = LFM + r × [0.1 × LSTRUCT + 1.0 × LGain + 1.0 × LOracle]

r = min(1, (optimizer_step + 1) / 200)
~~~

非联合微批不计算 L9，LOracle 使用基础模式；联合微批计算 L9，LOracle 改用联合模式，**不再额外加一份基础 Oracle 损失**。阶段 A 暂不开联合微批；阶段 B 新开启的 L9 与联合 LOracle 另用 100 step 从 0 预热至表中系数，阶段 C 使用完整系数。LGain 已包含 0.5/0.1/0.5 三个内部系数，进入总目标后不得再次分别加回 L8/L9/L10。

这些数字是损失系数，不是精度、收益比例或各项当前的损失值。例如 0.1 表示该项在总目标中乘以 0.1；它不保证梯度比 FM 小十倍。第 9 项的教师收益比例另用 ρ=0.5 表示，不与损失系数混用。

上述均为首轮设计初值，尚未经过 V4.4 训练验证。当前 V4.3 默认配置仍为 FM=1、STRUCT=0.01、隐藏 Oracle=60；旧隐藏回归的 60 不迁移到新版输出蒸馏。

### 3.2 可以放在一起算，但要保留不同基准

同一正常学生输出的 FM 只计算一次，供 1、8、10 复用：

~~~text
L1  = E_FM(on)
L8  = relu(E_FM(on) − stopgrad(E_FM(local_off)))
L10 = relu(E_FM(on) − stopgrad(E_FM(Wan)))
~~~

先逐样本计算 hinge，再取 batch 平均，不能先做 batch 平均让不同样本的正负收益相互抵消。

- on：学生正常执行全部六次写入。
- local_off：只关闭选中的一个位置、一个轮次的 H 写入；该轮更新后的 P 保持相同，剩余交互和 Wan 后缀重新计算。
- Wan：所有 H writer 关闭，Wan 条件及输入保持相同；确保没有其他路径修改 H。

三个分支使用相同视频、噪声、σ、条件和随机性；基准停止梯度。8 回答某一次写入的作用，10 回答累计写入后的作用，不能合并为同一个比较对象。

8、10 的 margin 均为 0。它们激活时沿用 FM 误差的梯度方向，只增加对应样本权重；都激活时，这部分 FM 梯度系数从 1 增至 2。这里不再额外叠加“有害样本权重翻倍”。

8/10 的实际用途是让不同样本按注入负作用获得不同权重。若一个更新中的样本权重恰好全相同，且梯度整体近似按同一比例缩放，Adam 或总梯度裁剪可能削弱这个倍率对实际步长的影响；不能承诺它们每一步都产生独立的新更新方向。按样本计算并在有效 batch/梯度累积中汇总，保留其选择性重加权作用；主动学习动态改善和教师方向由 9 与 Oracle 完成。

L2 保留原三个位置的 P/GT 特征拟合及原有效 token 权重，按位置平均，不再给每个轮次或每次采样调用加一套 STRUCT。每样本继续乘一次噪声因子：

~~~text
STRUCT 噪声因子 = clip((1 − σ) / 0.2, 0, 1)
~~~

0.2 是该噪声权重的过渡宽度。它不表示新增一项损失；也不能在 loss 函数内外重复乘。

### 3.3 第 9 项同时训练“不要变差”和“达到正收益”

以下 D 都是第 4 节定义的同一个动态误差，越小越好：

- D_on：正常学生输出的动态误差，保留梯度。
- D_off：同一入口关闭选中写入的动态误差，停止梯度。
- D_teacher：通过第 5 节筛选的 Oracle 输出动态误差，停止梯度。

若 Oracle 找到了相对 off 的可靠正收益，且也改善了当前学生动态，则：

~~~text
教师正收益 = max(D_off − D_teacher, 0)
学生目标动态误差 = D_off − ρ × 教师正收益
L9 = relu(D_on − stopgrad(学生目标动态误差))

ρ = 0.5
~~~

若没有有效的动态正收益教师，就令教师正收益为 0，退回 relu(D_on−D_off)。不能伪造一个固定正 margin，也不能因教师拒绝而让负注入保护一起消失。

例如 D_off=0.30、D_teacher=0.10，教师收益为 0.20，本版先要求学生学到其中一半，因此目标是 0.20：

| 学生 D_on | 状态 | L9 |
|---:|---|---:|
| 0.34 | 负注入 | 0.14 |
| 0.30 | 零收益 | 0.10 |
| 0.24 | 已有正收益，但不足 | 0.04 |
| 0.18 | 已达到当前目标 | 0 |

这就是正注入的训练激励：**降低可反传损失，更新产生写入的参数。** 不需要另加强化学习奖励。达到半数收益后，L9 可以归零，Oracle 蒸馏仍推动学生接近完整教师输出。

例中数字只是说明计算，不是实测结果。教师目标随当前学生重新生成；ρ=0.5 是初值，不代表保证恢复教师一半的最终视频收益。

## 4. 输出动态怎样提取：只用现有视频和冻结 JEPA

### 4.1 采用一条明确的输出链

本版 L9 在联合微批的第二次 Wan 调用上计算；阶段 B 暂只反传第二次调用，阶段 C 才打开以下完整跨步路径：

~~~text
第二次输入 latent + 当前学生 P/H 交互及真实写入
  → 完整 Wan 后缀
  → cond / uncond 合成后的 guided velocity
  → 当前时刻的干净 latent 估计
  → 可微 Wan VAE 解码
  → 与 GT 完全相同的取帧和空间预处理
  → 冻结 JEPA 时空 token
  → 相邻时间格的特征变化误差 D
  → L9 → backward → 两次学生调用中的可训练参数
~~~

干净估计复用当前 Wan flow 参数化：

~~~text
clean_estimate = current_latent − current_sigma × guided_velocity
~~~

已知首 latent 恢复为条件首 latent，和推理保护规则一致。它是模型在当前噪声时刻预测的干净视频，**不是已经完成 50 步生成的视频**。第二次采样更新后的状态通常仍有噪声，不直接送入 VAE 冒充干净输出。

### 4.2 动态算子的固定定义

现有教师为冻结 V-JEPA 2.1，使用当前选定层的 dense token。当前 JEPA32 缓存对应 32 帧 adjacent_pairs、16 个时间格、24×24 空间网格、1664 通道。沿用已有 checkpoint/层，不在本版更换教师。[本地编码器](../../physgen_v43/encoders.py)、[官方 V-JEPA 项目](https://github.com/facebookresearch/vjepa2)。

1. **对齐输入。** 预测和 GT 采用同一视频时间窗、同一 32 帧索引、同一 resize/letterbox、同一空间坐标。
2. **规范化 token。** 每个 token 按通道 RMS 归一化，分母下限 1e−6。不是把 1664 维向量变成单位 L2 长度后再按通道平均，避免仅由维数造成误差量级缩小。
3. **提取变化。** 在同一空间格点，取相邻两个时间 token 的差，再除以这两个 token 中心的真实时间间隔，单位为秒。每个 tubelet 的时间中心由其两帧实际时间戳计算。
4. **比较变化向量。** 预测变化与 GT 变化相减，对通道取平方均值，再按有效时空权重归约。不同样本各自归一化后取 batch 平均。
5. **处理无效区域。** 屏蔽 padding、无有效画面及重复/非正时间间隔；两个格点均有效才保留该时间差。

保留差分向量的幅度，不能再次把差分单位化。这样 GT 持续变化而预测静止时，零差分仍会与 GT 产生误差；GT 确实静止时，也不会因额外“运动越大越好”的奖励而鼓励乱动。

这只是一个相邻时间变化算子，不隐藏加入绝对特征损失、多尺度变化、光流、对象轨迹或空间关系损失。它提供对输出动态的代理监督，不等于精确速度、碰撞、受力或物理守恒标签；全局相机运动也可能影响该特征。

### 4.3 无需新标注，但必须接通真梯度

需要的监督来自已有配对视频、GT latent、JEPA 缓存和时间/视图元数据，不要求人工标注物理量，也不预训练新的 H 读出器。

必须解决现有代码的实际接入点：

- VideoTeacher.forward 当前默认 uniform 取帧。增加显式帧索引和视图参数，使用与缓存一致的 adjacent_pairs。缓存视图不一致时重算 GT 特征，不能从全视频 JEPA token 中截一段代替新窗口编码。
- 预测视频的 JEPA 前向必须在同一可微训练图内运行。现有 runtime/teacher 环境隔离需通过兼容的训练环境接通；离线导出预测视频再算分数不能训练 writer。
- Wan、VAE、JEPA 均冻结权重，但预测链路不使用 no_grad、不 detach 输入。GT、off、教师最终目标可以停止梯度。
- VAE 按真实因果顺序解码，保留所需前序上下文及 cache。不能为了省显存把任意 latent 片段当作独立视频开头。
- 首版沿用真实解码输出的像素范围处理；现有 clamp 对饱和位置导数为零，不能用伪造直通梯度声称已解决。重计算需复现相同 VAE cache 和同一输入。
- GT 编码可以离线缓存。on/off/Oracle 在相同坐标下比较；若该样本没有有效时间差，则该样本 L9 为 0，不生成动态正收益标签。

## 5. Oracle 怎样从“自己优化”变成“学生学会”

### 5.1 一个教师生成器，两种任务

每次只选择一个“位置＋轮次”，总计六个可选写入点。Oracle 从当前学生实际 ΔH 出发，优化临时 d；同一轮的 P 保持对应状态，下游包含剩余写入及所有 Wan/Corrector 模块。

| 微批模式 | 教师内层搜索任务 | 接受后的学生蒸馏目标 |
|---|---|---|
| 基础模式 | 标准 FM + 临时 d 正则 | 更优最终 velocity |
| 联合模式 | 第二次调用的干净估计误差 + 0.1×动态误差 D + 临时 d 正则 | 第二次真实 UniPC 更新后的 latent |

联合模式的干净估计误差，采用未知 latent 区域的 GT MSE，再除以当前 σ 的平方；σ 下限为 0.05，并只选满足该范围的调用。这个归一化在固定输入上使它具有 velocity 误差的尺度，**不把学生轨迹状态冒称标准 FM 加噪样本**。

临时正则沿用 0.001×mean((d/H_RMS)²)，H_RMS 停止梯度、下限 1e−4。联合模式分别计算 cond/uncond 分支正则后取平均。GT 重建误差和该正则只用于搜索教师，不另加入学生总损失。

**联合 Oracle 的动态误差参与求 d 的梯度。** 不能仍只按 FM 搜索、最后打一个动态分数，就声称教师学了动态正收益。

### 5.2 搜索、回溯及候选接受

首版沿用有限步局部搜索的基本规模：

| 参数 | 初值 | 含义 |
|---|---:|---|
| inner_steps | 2 | 临时 d 的优化迭代数，不是去噪步数 |
| relative_step | 0.01 | 提议更新 RMS 相对当前 H RMS 的比例 |
| regularization | 0.001 | 临时 d 的幅度正则 |
| max_backtracks | 4 | 每轮最多尝试 4 个回溯步长 |
| backtrack_factor | 0.5 | 回溯时将步长减半 |
| armijo | 1e−4 | 内层目标下降的回溯条件系数 |
| min_relative_gain / min_absolute_gain | 1e−5 / 1e−8 | 排除舍入噪声大小的“改善” |
| gradient_floor | 1e−20 | 梯度 RMS 的数值下限 |

内层只调用 autograd.grad(objective, d)，不执行学生 optimizer.step，不保留穿过优化器的高阶图。临时 d 的方向使用有效 token mask；联合模式同时优化选中写入点的 d_cond、d_uncond，经过真实 CFG 合成后评价，不能只改条件分支却按双分支学生处理。

基础模式继续要求真实 FM 严格改善，同时满足正则目标的回溯下降条件。

联合模式修改原来的“FM 必须严格下降”规则：

1. 候选值及梯度有限，带正则的联合内层目标满足回溯下降。
2. 相对本次搜索的初始学生，干净估计误差不恶化，动态误差也不恶化；数值容差按 max(1e−8, 1e−5×参考误差) 定义。
3. 干净估计误差或动态误差至少一项超过容差地改善。允许重建基本持平、动态明确改善的候选。
4. 若还要为 L9 提供正 margin，候选动态必须同时优于当前学生与同状态 local_off，且差值超过各自容差。

接受教师与拥有动态正收益是两个独立标志。教师只改善重建时可以参与 Oracle 蒸馏，L9 则使用零 margin 的负注入保护。零写入也可作为候选，但必须通过同样规则；搜索失败不自动把学生目标设成零 ΔH。

候选续算必须从同一入口、同一求解器历史的副本开始。拒绝的候选不能污染下一次回溯或其他样本的历史。

这些约束定义“什么样的教师可以教学生”，不保证两轮搜索对所有样本都找到有效教师。失败样本仍计算 FM、STRUCT 和相应收益项；不将搜索失败变成整条训练图无梯度。

### 5.3 外层蒸馏才更新共享能力

基础模式使用学生 velocity 与停止梯度的教师 velocity 的 MSE，未知 latent mask 与 FM 相同。联合模式使用第 6 节的采样状态蒸馏。两种模式按微批择一，**均替换原隐藏 ΔH 回归**。

这里明确替换学生训练目标的计算位置：学生侧必须重新执行正常 writer，使用自己预测的 ΔH 进入 Wan 后缀。不能先将 Oracle ΔH* 填进学生 H，再计算学生 loss；那样训练时走的是教师修正，推理时学生仍不会生成它。也不能将教师搜索得到的 FM 降幅作为一个脱离学生图的 scalar 加入总 loss。

基础模式的实际改动是：

~~~text
V4.3：LOracle = 距离(学生 ΔH，Oracle ΔH*)
V4.4：LOracle = 距离(Wan 后缀(H＋学生 ΔH)，停止梯度的 Oracle 更优输出)

学生侧沿真实 Wan 运算回传，最后更新学生 writer/step/交互参数。
教师侧输出停止梯度；不要求反传穿过 Oracle 的优化迭代。
~~~

~~~text
内层：当前学生状态 → 临时 d 搜索 → 更优输出/采样状态
                                      ↓ 停止梯度的教师目标
外层：学生正常生成 ΔH → 真实后缀 → 学生输出/采样状态
                                      ↓ 与教师比较
                       backward → 更新共享 writer、step、P/H 交互
~~~

教师损失按选中样本数归约，拒绝样本贡献 0，不按接受数量重新放大权重。多 rank 使用一致的前向/回溯调用安排，接受 mask 可逐样本不同。

对于固定的标准 FM 输入，如果输出确实沿当前预测到更优教师预测的插值方向移动，MSE 会下降。因此这里直接蒸馏 Oracle 的输出作用，比只回归隐藏 ΔH 的数值更贴近原目标。但共享神经网络的参数更新不等于逐样本独立插值，不能承诺每个训练 step 的 FM 都单调下降，或学生必然复现全部 Oracle 收益。

## 6. 两步去噪与 Oracle 的联合设计

### 6.1 固定训练和部署共用的采样配置

本版以已有 96GB 推理入口使用的配置为对齐目标：

| 配置 | 首版约定 |
|---|---|
| solver | FlowUniPCMultistepScheduler |
| sampling_steps / shift | 50 / 5 |
| CFG | 5，空字符串作为 negative prompt |
| solver_order / predict_x0 | 2 / true |
| solver_type / lower_order_final | bh2 / true |
| thresholding / solver_p | false / none |
| P 状态 | 每次 Wan 调用重置，cond/uncond 分开 |
| I2V 条件 | 每次采样更新后恢复已知首 latent |
| 时序视图 | 对齐训练视频的真实时间坐标；部署参考为 121 帧、24fps、约 5 秒 |

依据为 [当前推理说明](../../inference/README.md)、[96GB 入口配置](../../inference/infer_flow_oracle_1x96g.yaml) 及 [推理实现](../../inference/infer.py)。通用 run_inference.sh 的默认 solver 仍是 Euler，不能误写成所有现有入口都默认 UniPC。V4.4 应显式保存并共用上述 profile，避免隐式默认值不同。

直接复用 scheduler 返回的 float sigmas；不能用已经量化为整数的 timestep/1000 代替。每次预测保持 cond、uncond 两条真实路径，并采用：

~~~text
guided_velocity = uncond_velocity + 5 × (cond_velocity − uncond_velocity)
~~~

UniPC 包含预测、校正和历史输出，本版训练必须复现当前实现的状态语义。其通用方法背景见 [UniPC 原论文](https://arxiv.org/abs/2302.04867)；具体实现以本地 Wan 调度器为准，论文结果不是本项目效果证据。

### 6.2 先建立有效历史，再展开相邻两步

不从任意 σ 上凭空制造 UniPC 的历史。第一版使用有配对 GT 的局部重建轨迹：

1. 在 50 步真实 schedule 中选择窗口起点 j。候选满足 j≥2、j+1<50、0.1≤σ[j]≤0.8、σ[j+1]≥0.05；在候选中均匀取样。
2. 令 a=j−2，以 GT latent 和随机噪声构造 σ[a] 时刻的配对加噪输入，恢复已知首 latent。
3. 在索引 a 初始化求解器，设置正确 begin_index；从这个重建起点按真实 UniPC 引导流程运行 **两次无梯度学生采样更新**，建立合法历史。
4. 得到窗口入口 x[j] 及 history[j] 后统一 detach。之后连续执行 j、j+1 两次有梯度调用。
5. 两次调用之间的 latent 和新增 history 张量均不得 detach，也不重新从 GT 加噪。

~~~text
GT 加噪到实际 σ[a]
  → 两次无梯度 UniPC 更新，建立有效历史
  → x[j]、history[j]（窗口入口停止梯度）
  → 学生调用 1 + 真实 UniPC 更新
  → x[j+1]、history[j+1]（保留梯度）
       ├─ 学生调用 2 + 真实 UniPC 更新 → x_student[j+2]
       └─ 同入口/历史的末步 Oracle     → x_teacher[j+2]（停止梯度）

Oracle 蒸馏：学生/教师的 x[j+2] 差异
动态收益：第二次调用的干净估计经过 VAE/JEPA 后的误差
两项都沿学生图反传到调用 2 和调用 1
~~~

此处“两步”专指有梯度窗口的两次连续去噪。它和两个内部 H writer、Oracle 的两轮 d 搜索、窗口前的两次历史预热都不是同一个次数。

该轨迹使用学生真实预测建立历史，没有用 GT velocity 伪造教师历史；但它从 GT 部分加噪重建起步，**不等同于从纯噪声运行完整 50 步的自由生成分布**。这样选择是为了保留合法的配对重建目标，同时训练真实采样转换，不能声称已经覆盖整条部署轨迹。

### 6.3 三种对象必须分清

| 对象 | 可以怎样监督 | 不能怎样处理 |
|---|---|---|
| 新鲜的 GT/noise 标准加噪输入 | 使用 noise−GT 的 FM 真值 | 与其他轨迹的入口混用 |
| 第二次调用的干净估计 | 与配对 GT latent/JEPA 动态比较，用于教师搜索和 L9 | 称为已完成完整采样的视频 |
| 第二次真实更新后的 x[j+2] | 同噪声时刻学生/教师状态蒸馏 | 仍有噪声时直接与干净 GT 做 MSE |

因此，联合微批也要保留一个**独立的标准 FM 分支**，在那里计算 1、2、8、10。其视频可以和联合窗口相同，但 σ、噪声和基准单独匹配。窗口经过学生更新后的状态，不继续沿用原始 noise−GT 作为“标准 FM 标签”。

教师只在联合窗口第二次调用的一个选中写入点求解。局部 off 也从同一个 x[j+1]、history[j+1] 出发，关闭 cond/uncond 对应的选中写入，其他部分按真实后缀重新计算。标准分支的 FM off 不能拿来充当此处的动态 off。

### 6.4 蒸馏实际采样状态，并规范化尺度

联合 LOracle 比较学生和教师的 x[j+2]，均为同一真实 schedule 时刻。只在未知 latent 区域计算 MSE，教师状态停止梯度。

不同采样步长下，状态残差的天然量级不同。本版用 **当前 UniPC 更新对本次 guided velocity 的响应系数 b** 规范化：

~~~text
LOracle_joint = accepted × mean_unknown(
    ((x_student[j+2] − stopgrad(x_teacher[j+2])) / abs(b))²
)
~~~

在本版 thresholding=false、solver_p=none 的配置下，固定第二次调用的输入和历史后，UniPC 更新对当前 velocity 是仿射映射；未知 latent 坐标共用该标量响应系数。b 必须由实际更新函数计算，不能直接假定等于 Euler 的 Δσ。

简便实现：在相同索引、有效历史长度、校正开关及阶数条件下，用小尺寸标量张量令当前 velocity 分别为 1、0，执行两次纯调度器更新，其结果差即为 b。历史/输入采用一致的零张量，保持 None 与有效历史的位置关系。此过程不调用 Wan，可按调度器元数据缓存，计算用 FP32。排除非有限或 abs(b)<1e−4 的窗口，不靠除一个极小数制造大梯度。

当入口和历史固定时，这个归一化使状态匹配具有 velocity MSE 的尺度；联合学生入口本身仍带梯度，因此保留额外的跨步学习作用。它不是新的学生损失项。

### 6.5 必须显式传递求解器状态

当前推理的 sample_latents 带 no_grad，不能直接拿整个包装函数训练。需抽出训练/推理共用的可微更新核心：

~~~text
next_latent, next_state = solver_step(
    current_latent, guided_velocity, current_state, schedule
)
~~~

state 包含 model_outputs、timestep_list、last_sample、step_index、lower_order_nums、this_order 等实际状态。当前实现先根据输入 sample 计算 clean prediction，再执行 UniC 校正、更新历史和 UniP 预测；可微版本保持此顺序。

要求：

- 学生步骤返回新状态，不在 checkpoint 重计算时悄悄修改外部 scheduler 对象。
- 窗口内第一次更新写入 history 的张量保留梯度；只保留 latent 梯度、把 history 全 detach 仍是不完整的跨步训练。
- Oracle、off 与每个回溯候选各用独立的停止梯度状态副本。不能用同一个被原地修改的 scheduler 连续评价不同候选。
- 学生与教师共用相同时间索引、CFG、首 latent 保护及更新代数。生成代码不保留另一份不同的训练求解器。

## 7. 一次微批到底怎样更新参数

### 7.1 调度与执行顺序

每个微批都有标准 FM 分支。阶段 A 只运行基础模式；阶段 B/C 每 4 个微批中的 1 个另外启用联合窗口及第 9 项。0.1 是 L9 在启用微批上的最终系数，不再乘 4 补偿频率。阶段 B 的窗口第一步仍无梯度，阶段 C 使用第 6 节完整跨步图。

普通微批和联合微批的选中写入点使用独立循环计数器，分别覆盖 3 个位置×2 个轮次。不能直接用同一个 micro_step%6 再每 4 次取样，否则联合模式可能永远只覆盖部分轮次。标准分支与联合分支的比较基准也分别绑定各自输入和选中点。

先完成教师准备，再建立学生反传图，避免同时保留内层搜索图和两步学生大图：

1. 固定当前参数、数据、噪声及随机设置，准备标准 FM 的 local_off/Wan 基准。
2. 普通微批：生成基础 Oracle 教师。
3. 联合微批：建立无梯度历史前缀，预走窗口第一步，捕获第二步入口；生成末步 Oracle 及动态 off 基准，保存教师状态、动态目标和接受 mask，释放内层图。
4. 在参数尚未更新的情况下，重新运行有梯度的标准分支；联合微批再从保存的窗口入口及历史重跑学生调用。阶段 B 第一次调用无梯度、第二次有梯度；阶段 C 两次都有梯度。
5. 计算对应分量，将 8/9/10 组装为一个 Gain，再形成 FM、STRUCT、Gain、Oracle 四项总目标，统一 backward；按原训练器规则累积梯度、裁剪和执行 optimizer.step。

重跑期间不插入 optimizer 更新，不改变 dropout/条件/噪声。教师快照只作目标，不能拿 detach 后的学生预测代替有梯度前向。

### 7.2 训练伪代码

下列内容是文档中的待实现规格，不是已经写入训练器的代码。四个主损失必须以仍连接学生图的 Tensor 返回；展示和日志只能使用另行 detach 的副本。

~~~python
phase, phase_step = training_phase(optimizer_step)  # A / B / C，见第 8 节
joint = phase != 'A' and (micro_step + 1) % 4 == 0
# prepare 内部：基准无梯度；Oracle 只对临时 d 求梯度。
# 不在整个 prepare 外包 no_grad，以免把 d 的搜索图也关掉。
refs, teacher, window = prepare_current_teacher_and_references(
    batch, joint=joint, fm_site=fm_site, joint_site=joint_site
)

pred, p_states = student_standard_fm(batch)  # 正常有梯度路径
fm = fm_error_per_sample(pred, batch.flow_target)
l1 = fm.mean()
l2 = (
    struct_per_sample(p_states, batch.gt_jepa)
    * ((1 - batch.sigma) / 0.2).clamp(0, 1)
).mean()
l8 = relu(fm - refs.local_fm.detach()).mean()
l10 = relu(fm - refs.wan_fm.detach()).mean()

if joint:
    # B：第一调用及其新 history 停止梯度；C：窗口内全部保留梯度。
    end_state, second_clean_estimate = student_two_step_window(
        window, grad_first_step=(phase == 'C')
    )
    dynamic = jepa_change_error_per_sample(second_clean_estimate, batch)
    gain = where(
        teacher.positive_dynamic,
        (refs.local_dynamic - teacher.dynamic).clamp_min(0),
        0
    ).detach()
    target_dynamic = (refs.local_dynamic - 0.5 * gain).detach()
    l9 = masked_batch_mean(relu(dynamic - target_dynamic), refs.dynamic_valid)
    lo = accepted_mse(
        end_state, teacher.end_state.detach(),
        accepted=teacher.accepted, scale=window.response_scale.detach()
    )
else:
    l9 = 0
    lo = accepted_mse(pred, teacher.velocity.detach(),
                      accepted=teacher.accepted, scale=1)

r = min(1, (optimizer_step + 1) / 200)
# B 阶段新增动态/联合教师分支独立预热，其他已有目标不重置。
q = min(1, (phase_step + 1) / 100) if phase == 'B' else 1
joint_ramp = q if joint else 1
# Gain 已含三个分量的内部权重，总目标中只加入一次。
loss_gain = 0.5*l8 + 0.1*joint_ramp*l9 + 0.5*l10
loss_terms = {
    'fm': l1,
    'struct': 0.1*r*l2,
    'gain': r*loss_gain,
    'oracle': r*joint_ramp*lo,
}
loss = sum(loss_terms.values())  # 不能对训练用的项 detach/item/转 float
(loss / accumulation_steps).backward()

if accumulation_boundary:
    clip_student_grad_norm_(1.0)
    optimizer.step()
    lr_scheduler.step()
    optimizer.zero_grad(set_to_none=True)
~~~

这里 accepted_mse 用真实未知 latent mask，按选中样本总数归约；masked_batch_mean 同样将无效样本置零后除以 batch 总数，不因有效样本变少而放大剩余项。第一次累积前先清空梯度。伪代码省略分布式封装，不省略任何教师接受条件或时间/视图对齐约定。

### 7.3 哪些参数会收到更新

下表是全部解冻后的职责；阶段 A 只训练新 writer/step，阶段 B/C 按第 8 节解冻。冻结权重与停止输入梯度是两回事。

| 模块 | 是否更新权重 | 主要梯度来源 |
|---|---|---|
| 两轮 writer、步长头 | 是 | FM、8/9/10、Oracle 蒸馏 |
| JointPHBlock、初始化器及相关条件映射 | 是 | STRUCT 及经过真实写入回传的生成目标 |
| 原 P JEPA 解码头 | 是 | STRUCT |
| Wan、VAE、JEPA、文本编码器 | 否 | 需要的输入梯度仍通过其运算传播 |
| 临时 Oracle d | 仅搜索期间优化 | 教师内层目标，随后释放 |
| GT、off/Wan 基准、最终教师目标 | 否 | 全部停止梯度 |

末端 P 更新未必有通往同轮 H 的生成梯度，不能把“同时交互”写成 H 读取了刚更新的 P。保留原 STRUCT 监督该 P，H 写入则由其真实输出效果监督。

首轮优化器沿用 AdamW：新 writer/step 的峰值学习率 5e−5，迁移参数解冻后的峰值学习率 1e−5；betas=(0.9,0.999)，weight_decay=0.01，梯度范数上限 1。各参数组开始训练后的学习率预热为 100 optimizer step，辅助损失总预热为 200 step，阶段 B 新分支另预热 100 step，三者分别实现。新增 writer/step 和待解冻参数明确加入参数组，不能只定义模块而漏进优化器。

### 7.4 成本边界

“有梯度展开两步”不是整个联合微批只调用两次 Wan。CFG 使窗口本身包含四次 Wan 网络求值，此外还有无梯度历史预热、教师预走/后缀搜索、标准 FM 分支和 VAE/JEPA 的计算。

首版通过每 4 微批一次联合、一次只选一个写入点、释放教师搜索图、冻结权重和激活重计算控制成本。冻结参数不等于免除输入反传的显存。算力不足时应调整联合频率或有效 batch，并明确记录配置；不能悄悄 detach 第一调用，或长期将 L9 置零后仍称本方案已完成。

### 7.5 每个主损失必须对应学生参数更新

这里规定后续实现的计算职责，不能用“算出了数值”代替接通训练。

| 主损失 | 必须使用的学生 Tensor | 必须保留的反向路径 | 更新的参数 |
|---|---|---|---|
| FM | 正常学生写入后的 velocity | 输出→Wan 后缀→H＋学生 ΔH | 已启用的 writer、step、交互和初始化器 |
| STRUCT | 正常学生 P 经原解码器的特征 | 特征→P 解码及产生 P 的计算；写入影响后续 P 时也沿 H 传播 | 阶段允许训练的 P 路径、解码器及相连的写入参数 |
| Gain 中的 8/10 | 与 FM 共用的、未 detach 的正常学生误差 | 活跃 hinge→学生 FM 误差→真实后缀→写入 | 同 FM，按负作用样本改变权重 |
| Gain 中的 9 | 学生生成干净估计经 VAE/JEPA 得到的动态误差 | 活跃 hinge→JEPA→VAE→velocity→Wan 后缀→写入 | writer、step、相连的交互参数；C 阶段还经采样状态回到第一次调用 |
| Oracle | 学生正常 forward 的 velocity 或两步采样状态 | 学生/教师输出差异→学生真实后缀；联合 C 阶段贯穿两次调用及 history | 产生学生修正的共享参数，而不是只更新临时 d |

各项必须同时满足以下实现约定：

1. **损失依赖正常学生输出。** 学生 ΔH、写后 H、velocity、预测视频、JEPA 输出与所需采样状态保留梯度。禁止用教师快照、缓存分数或重新构造的常量 Tensor 充当这些节点。
2. **停止梯度的位置明确。** GT、off/Wan 比较基准、接受判定、收益 margin、最终教师目标停止梯度；Oracle 内层只对临时变量求导。学生 Wan/VAE/JEPA 的输入梯度不停止。阶段 B 截断第一步、阶段 C 保留跨步链，严格按阶段执行。
3. **四个 Tensor 实际参与训练总和。** FM、STRUCT、Gain、Oracle 从 loss 函数返回同一训练总目标，进入 backward。metrics 中同名数值、teacher 的 loss 降幅及单独打印的收益都不能充当这一项。
4. **梯度有实际更新对象。** writer/step 必须在 optimizer 参数组内；B/C 解冻的交互参数也必须有正确学习率和同步路径。不能把唯一可训练对象变成一个读出器，让它适应错误视频而生成部分不变。
5. **更新后推理使用同一学生模块。** 保存实际更新的 writer、step、交互和初始化器；正常推理加载这些权重并运行相同写入路径。推理不依赖 Oracle ΔH*、训练 GT 或训练专用纠正分支。

以活跃项说明其训练含义：若局部关闭写入时 FM 为 0.30、正常学生为 0.34，L8=0.04，其对学生 FM 的导数为 1，再乘实际系数 0.5×r。若动态 off 为 0.30、有效教师为 0.10、学生为 0.24，目标为 0.20，L9=0.04，其梯度沿预测视频链进入写入参数。这两个差值必须由学生 Tensor 计算，而不是从已 detach 的日志数值计算。

Gain 是整体输出训练目标，不是仅作用于选中 writer 的局部优化器。正常 on 分支中所有可达且可训练的参数都可能更新，不能据局部 off 的定义宣称某一步必然只修好了选中的 writer。teacher/off 基准每次从当前学生重建，避免用其他参数状态的对照冒充当前注入收益。

**不能宣称每一项、每一个 step 都有非零梯度。** hinge 达标、教师拒绝、非联合微批、已知区域 mask 或阶段冻结都可能合法地给出零贡献；writer 零初始化时上游/step 的部分梯度也会暂时为零。实现必须区分这些明确条件与意外断图、遗漏权重、遗漏参数组。有效教师与活跃任务下，若一条链始终无法影响其负责的参数，必须修复计算图或执行模块，不能只保留日志然后称为已经完成。

后续实现只需针对有效样本和激活条件确认各目标的参数梯度贡献与优化器接入；“总 loss 有梯度”或“writer 在变化”都不够，因为这些也可能仅由 FM 或权重衰减产生。该核对用于完成上述修改，不另设大批监控/诊断阶段。损失进入更新链是实现要求，最终视频是否改善仍要由实际训练结果回答。

## 8. 推荐分阶段训练：先建立写入，再学动态，最后跨步联合

### 8.1 一起训练是否会梯度冲突

**存在这种可能，因此推荐分阶段；但四个主损失展开后的六个计算分量不等于六个彼此冲突的方向，也没有证据说明它们必然把梯度抵消到零。** 这里是根据目标及计算图作设计判断，尚未测得本版真实梯度。

| 组合 | 冲突判断 | 原因 |
|---|---|---|
| FM 与 8/10 | 对同一样本、同一正常输出，在 hinge 激活时是同向梯度 | off/Wan 已停止梯度，8/10 只是给 FM 加权；batch 重加权可以改变总体方向，但不是另一个拟合目标 |
| STRUCT 与生成目标 | 可能冲突 | P 越接近教师语义特征，不代表该表示越容易帮助 H 去噪；共享交互参数同时承担表示和控制作用 |
| FM 与动态 L9 | 可能冲突 | 降低 JEPA 时间变化误差与降低 latent velocity MSE 并非同一任务；单独追动态也可能带来错误的纹理变化或相机运动 |
| 基础 Oracle 与 FM | 教师方向通常更有针对性，但参数梯度仍不保证同向 | 更优教师保证的是当前输出的 FM 改善；映射到共享参数、其他样本和其他位置后，不保留逐样本改善保证 |
| 单次目标与两步 Oracle | 可能冲突，且数值尺度不同 | 跨步梯度包含后续网络、CFG、历史状态和采样更新；降低当前误差不必然降低下一步误差 |

多任务研究区分了梯度方向冲突与梯度量级失衡：PCGrad 针对冲突方向做投影，GradNorm 调整任务梯度量级；这些是通用工具，不是本项目已经出现冲突的实验证据。[PCGrad 原论文](https://arxiv.org/abs/2001.06782)、[GradNorm 原论文](https://proceedings.mlr.press/v80/chen18a.html)。

本方案最明显的训练依赖是：新 writer 初始为零，动态编码看到的输出尚未体现新交互，而两步反传又会同时推动前后两次修正。直接从第一步同时打开全部路径可以训练，但会让“写入接口尚未学好”和“目标之间不一致”同时发生。分阶段先建立有效写入，再增加后续约束，更容易明确每一阶段在学什么。

### 8.2 三个阶段的明确划分

推荐以三个阶段作为首轮默认训练日程。阶段不是三套模型，也不要求三个数据集；模型权重连续继承，保留同一套最终四项总目标。本文 A/B/C 是训练日程，需用独立 curriculum_phase 字段表示；现有配置 stage=A 指 Corrector 类型，不能直接调用旧 set_stage('B') 来实现第二阶段。

| 阶段 | 主要目的 | 启用目标 | 更新哪些参数 | 训练状态 |
|---|---|---|---|---|
| A：去噪写入起步 | 让新 writer 学到 Oracle 对 FM 有用的写入 | 1、2、8、10、基础 Oracle；9 暂不开 | 新 writer 和 step；迁移的初始化器、交互块、P 解码器冻结 | 标准配对加噪输入，单次 Wan 任务 |
| B：局部动态正收益 | 让实际输出的动态改善进入 writer/交互参数 | 普通微批同 A；每 4 微批一次开启 9 和联合 Oracle | writer/step 用 5e−5；迁移参数解冻，用 1e−5 | 真实 UniPC 历史及窗口第一步无梯度，仅第二次调用保留梯度 |
| C：完整两步联合 | 让前一次写入对后一次去噪负责 | 同 B，四个主损失及其内部计算定义不变 | 保持 B 的两组学习率及全部 Corrector 可训练 | 两次调用及中间 latent/history 全部保留梯度 |

以总计 1000 optimizer step 的试运行日程为例，可以安排 A=200、B=200、C=600。该数值只是可执行的初始日程，不能声称 200 step 必定足以学好；实际总预算不为 1000 时应显式重设阶段长度，不能沿用旧 800-step 配置后默认第三阶段仍有 600 步。

阶段 A 的冻结以前提“迁移的 V4.3 P/交互已有可用训练权重”为基础。如果从随机 P 开始，A 阶段必须让初始化器和交互块一起学习，不能把随机语义网络永久固定。这里无需另外开展一轮只训练 P 的预训练。

**阶段 A 保留 L2 仍有作用。** P/H 权重虽冻结，第一轮写入会影响第二轮及后续位置读取的 H，因此部分 STRUCT 误差仍可经冻结交互运算回传给 writer。要冻结的是参数，不能给整个 Corrector 套 no_grad。新 writer 的 FM/Oracle 梯度是这一阶段的主学习信号。

**阶段 B 不是普通离线单步拟合。** 仍由当前学生在线建立真实历史及第一步状态，只是暂时截断第一步的梯度，让第二次写入先承担可解释的局部任务。教师、动态 off、正收益 margin 与阶段 C 完全相同。此时不能宣称已完成完整跨步训练。

**阶段 C 必须重新计算两次有梯度前向。** 不能只在原来 detach 的张量上设置 requires_grad，就声称梯度已接回第一次调用。基础 FM 分支及每四微批中的三个基础 Oracle 微批继续保留，避免后期只优化动态/轨迹而丢掉原去噪任务。

### 8.3 阶段切换怎样实际降低干扰

首版采用这些实际更新安排：

1. A 阶段冻结已学表示，只让新写入接口适应生成任务，避免随机新 writer 同时推动整套语义表示重排。
2. B 阶段解冻的旧参数使用 writer 学习率的 1/5，保留 STRUCT；新增动态和联合 Oracle 分支在前 100 个阶段 step 线性预热，已有 FM/基础 Oracle 不重新归零。
3. B 到 C 只增加跨步梯度，不换教师口径、不叠加新损失、不改变 loss 权重定义。
4. FM、8、10 始终存在；联合教师要求重建/动态不恶化，减少直接相互矛盾的目标进入学生训练。
5. 参数组从创建优化器时明确登记。冻结期间不更新这些参数及其动量；解冻后正常创建/延续各自 Adam 状态，阶段切换不重置已训练 writer 的优化器。现有手动梯度同步也要识别冻结组，不能给其填零梯度后仍执行 AdamW 权重衰减；各 rank 的冻结/解冻日程必须一致。

这可以减轻早期相互干扰，但不从数学上消除阶段 C 的目标冲突。交替计算不同微批同样不是“保证没有冲突”；它只是安排任务频率。梯度裁剪限制总范数，也不能修复方向相反。

首版不默认增加逐损失梯度投影和 GradNorm，以免同时引入新的优化机制及多次反传成本。若后续决定直接约束冲突更新，可只分成“FM＋8＋10 主梯度”和“其余辅助梯度”两组：在共享参数上移除辅助梯度中反对主梯度的分量，再合成更新。这是改变参数更新的备选方案，不是再增加一条损失或只做监控；它只能给局部一阶方向约束，Adam 预条件和有限步长之后仍没有逐样本效果保证。启用它需另改优化器流程，不与本文默认一次合并 backward 混称。

必要的实现核对限定为直接影响方法正确性的几件事：同入口新旧采样更新数值一致；关闭分支使用正确的基准；教师搜索不更新学生；一次实际 backward/optimizer.step 能更新 writer；联合模式的第一步与 history 保留梯度。它们服务于接通训练，不以大批诊断报告替代上述代码改动。

## 10. 对“这样能否提升最终效果”的明确回答

**这套设计为已指出的缺口提供了对应的参数更新路径，比仅监督 P 或仅回归隐藏 ΔH 更直接；目前不能将它表述为已经证明提升最终视频。**

具体改善机制是：

- 标准 FM 保持去噪任务本身的学习；8/10 对负作用写入增加同向纠正。
- 第 9 项看到 H 写入后的实际预测视频动态，并以教师可达到的正收益作为目标，减少“什么也不写就满足约束”的情况。
- Oracle 不只展示自己能降误差，而是提供会进入学生 backward 的更优输出/状态目标。
- 两步训练使用实际 CFG、UniPC 更新及学生历史，让前一次修正接受后一次结果的梯度。

其边界也应准确：JEPA 时间变化仍是动态代理；部分加噪的两步重建不能证明完整自由生成改善；FM 保护不是画质保证；使用完整 GT 的 Oracle 也可能包含学生仅凭部署条件无法完全预测的个体细节。因此不能保证任意样本都改善、每步 FM 单调下降、或全部恢复 Oracle 上限。

最终有效的含义是：**关闭 Oracle、使用正常学生推理时，未见视频上的去噪和动态/物理表现得到改善。** 这需要后续实现及训练结果支持。本次交付已经明确结构、损失、教师目标、数据来源和实际梯度路径，不把这些方法选择继续留作待监控事项。
