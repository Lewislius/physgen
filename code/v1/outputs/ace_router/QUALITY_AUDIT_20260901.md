# PhysGen V1 / Wan–ACE Router：100 个视频的严格质量审计

审计日期：2026-09-01  
审计范围：outputs/ace_router 下 M0–M4、P01–P20、seed 42，共 100 个视频  
结论口径：把“物理任务是否完成”置于“单帧是否好看”之前；新物体凭空出现、主体复制/消失、动作未闭环、终态不保持，均不能判为高质量。

## 1. 最终结论

这批结果整体确实很差，而且“约 90 个低质量”的直觉并不夸张，甚至偏保守。

| 等级 | 定义 | 数量 | 占比 |
|---|---|---:|---:|
| A | 动作闭环、因果和物体守恒基本正确、无明显伪影，可称高质量 | 0 | 0% |
| B | 任务基本完成，仅有轻微瑕疵，勉强可用 | 3 | 3% |
| C | 能看出题意，但缺步骤、违背守恒、终态不完整或有明显形变，不能用于严格评测 | 33 | 33% |
| D | 主体/动作严重错误、对象增生消失、拓扑突变、事件未发生或场景跑偏 | 64 | 64% |

因此：

- 真正高质量 A：0/100。
- 宽松到“勉强可用”B：3/100，仅 P20 的 M1、M2、M3。
- 应计入低质量的 C+D：97/100。
- 严重失败 D：64/100。
- 所有 100 个任务在程序层面都成功写出了视频，但“技术成功率 100%”与“语义/物理合格率 3%”完全是两回事。

### 各模式严格评级

| 模式 | A | B | C | D | 严格合格率（A+B） | 总体判断 |
|---|---:|---:|---:|---:|---:|---|
| M0：T2V Wan | 0 | 0 | 6 | 14 | 0% | 构图和实体数量不受控，常从事件中段开始 |
| M1：I2V Wan | 0 | 1 | 7 | 12 | 5% | 初始构图较稳，但后续身份、守恒和动作闭环仍大量失败 |
| M2：I2V + cplus | 0 | 1 | 7 | 12 | 5% | 没有显示出总体收益，额外出现形变和语义过冲 |
| M3：I2V + ACE 对比残差 | 0 | 1 | 7 | 12 | 5% | 未证明优于 M1；对比方向没有转化为可靠因果控制 |
| M4：T2V + ACE | 0 | 0 | 6 | 14 | 0% | 缺少首帧布局约束，ACE 无法补回空间和身份控制 |

结论不是“某个模式偶尔不好”，而是当前基础模型、时长、条件设计、注入强度和评测流程同时存在问题。M2/M3 的路由残差没有解决 Wan 本身的物体恒常性和复杂动作能力，某些样本反而放大了纹理/形状幻觉。

## 2. 审计方法与严格标准

### 2.1 实际审计内容

- 核对了 100/100 个 video.mp4、manifest、resolved config、contexts、diagnostics 和 run summary。
- 对全部 100 个视频统一抽取第 0、8、16、24、32、40、48 帧，按模式横向比较。
- 对边界样本 P04、P06、P07、P08、P09、P12、P13、P14、P15、P18、P20 加密检查第 0、4、8……48 帧。
- 单独对 P12/M2 做 4 帧间隔的加密时序检查，并核对残差诊断。
- 检查关键 I0 输入图、I0 元数据、cplus/cminus 文本，以及实际进入模型的条件分支。
- 计算同提示词、同 seed 模式间的逐帧 SSIM，判断 ACE 是否真正改变了行为。

### 2.2 高质量硬门槛

一个视频必须同时满足以下条件才能进入 A/B：

1. 初态正确：规定实体齐全、数量正确、位置关系可支持事件。
2. 触发可见：碰撞、推动、风、倾倒、按压等原因必须出现。
3. 因果顺序正确：不能先出现结果，随后才出现原因。
4. 同一实体连续：不能复制、消失、换物、突然变成别的形状。
5. 物理状态合理：碰撞传递、体积/液位/碎片/颗粒数量至少近似守恒。
6. 动作闭环：必须到达提示要求的终态。
7. 终态保持：最后约 20% 帧不能回退、复原或换景。
8. 无严重伪影：不能凭空出现树枝、手、球杆、容器、叶片等未要求实体。

“画面清晰”“主体看起来像目标”“中间某一帧有运动”都不足以判为高质量。

### 2.3 问题代码

| 代码 | 含义 |
|---|---|
| AC | 动作不完整或关键阶段缺失 |
| END | 终态缺失、不保持或最后回退 |
| ID | 主体身份丢失、复制、消失或换物 |
| EX | 凭空出现未要求的新实体 |
| DEF | 严重形变、拓扑突变、物体融成错误形状 |
| PHY | 接触、因果、速度、物质或数量守恒错误 |
| SRC | 流体/颗粒从错误来源出现，源端与汇端断开 |
| TMP | 时间顺序错误或状态非单调回退 |
| STA | 接近静止，任务没有真正发生 |
| CAM | 镜头/裁切替代了物体运动，关键实体出框 |

## 4. P12/M2 专项复核：绝对不能叫“效果好”

### 4.1 画面上发生了什么

P12/M2 的实际序列是：

1. 开始几帧是一颗完整、饱满的蒲公英。
2. 中前段花头右侧突然长出数条粗黑/棕色分叉结构。
3. 分叉继续拉长并形成蛛网/树枝状长丝。
4. 空中出现若干尺寸过大的“种子/结点”。
5. 原花头并没有按要求渐进耗尽，末帧仍保持大部分饱满结构。

它同时触犯了 EX、DEF、ID、END 四个硬失败条件：

- EX：出现不属于场景的树枝/网状物。
- DEF：细小冠毛被错误发展成粗枝拓扑。
- ID：被吹走的种子不再可追踪为原花头上的同一批种子。
- END：花头没有明显、持续地耗尽。

因此评级只能是 D，不是 C，更不可能是 A/B。

### 4.2 为什么 M2 特别容易出现这种错误

M2 的实现不是一个对象级或粒子级物理控制器，而是在 16 个中层 Transformer block 中加入：

semantic + scale × (positive − semantic)

当前 positive 又是“原始提示词 + 一句重复描述种子脱落/漂走的 cplus”。这带来几个问题：

1. 重复强化了 dandelion、seeds、detach、drift 等词，但没有空间掩码告诉模型“只能减少花头上的既有细种子”。
2. cross-attention 残差是整幅 latent 的全局语义扰动，不具备对象计数、附着关系和粒子轨迹约束。
3. 蒲公英冠毛本来就是细长放射纹理；中早期全局语义扰动容易把“细长、向外漂移”错误完成成枝条、根须或蛛网。
4. 输出仅 640×352。单根种子在 VAE latent 中分辨率很低，许多细粒子会被压成线状/块状结构。
5. 总时长只有 49 帧 / 24 fps = 2.04 秒，难以同时建立风、逐步脱落、漂移、显著耗尽和终态保持。
6. 通用负面提示主要针对低清、人体畸形、杂乱背景，没有禁止新植物、树枝、叶片、物体复制或拓扑增生。

### 4.3 数值诊断也不支持“它很稳”

P12/M2 的 diagnostics 显示：

- scaled_delta / semantic 的最大采样值为 0.141，即单个被记录 block 的残差范数达到语义分支的 14.1%。
- raw delta L2 在记录点间约 26.1–186.2。
- 残差被注入第 8–23 层，共 16 层。
- 前 40/50 个去噪步仍有注入，覆盖前 80% 去噪过程。
- 该残差位于 conditional 分支，之后 prediction 又使用 guide scale 5 做 CFG。不能简单把它等价成线性 5 倍，但它的影响会随 conditional 分支被 CFG 放大。

diagnostics 的 all_finite 只表示没有 NaN/Inf，不表示物体守恒、拓扑正确或动作完成。当前记录也只抽查少量层/步，没有衡量累积残差、对象数量和时序因果。

## 5. 各模式分别存在的问题

### 5.1 M0：纯 T2V Wan

主要问题：

- 没有首帧约束，实体数量、布局、尺度和拍摄角度由模型自由决定。
- 很多视频从事件中段或结果态开始，例如 P11 直接出现碎瓶。
- 常用镜头推进/特写冒充动作，P01、P05、P07 只剩局部主体。
- 多实体关系任务尤其差：碰撞、倒水、撕裂都需要持续绑定两个以上对象。
- 偶尔能生成“像某种动作”的局部片段，但不满足完整物理任务。

定位建议：只保留为弱 T2V 基线，不应作为当前主要研发方向。

### 5.2 M1：纯 I2V Wan

优点：

- 首帧布局比 M0 明显稳定。
- P20 说明当构图简单、物体大、动作先验强时，基础 I2V 能完成短动作。

主要问题：

- 代码每步只重新锚定首帧对应的 known latent，并没有约束后续帧里的同一对象身份。
- 结果中大量出现对象复制/变形：P06 书本一度同时留在架上和空中，P18 球变成多个/异色物。
- 静态源容器不愿整体移动，于是模型选择从画外“凭空生成水流”，P13/P14 最明显。
- 对扩散、融化、回弹、衰减弹跳等状态变量理解很弱。

定位建议：把 M1 作为所有 I2V 改动的核心基线；任何路由方法必须显著、跨 seed 地超过它。

### 5.3 M2：I2V + cplus-only residual

当前没有证据证明 M2 优于 M1：

- A/B/C/D 分布与 M1 相同。
- 20 个样本中，M1–M2 有 11 个逐帧 SSIM 大于 0.90，说明很多任务的行为几乎没有实质变化。
- 没变化的样本没有修复基础失败；变化较大的样本又容易变成错误形变，例如 P12 树枝、P03 巨型网球。

设计问题：

- positive−semantic 同时混入“提示长度差、重复实体词、额外动作词”，并不等于纯净的因果方向。
- 没有 counterfactual，无法明确压低错误时间顺序。
- raw delta 不做归一化、范数裁剪或逐样本自适应；所有事件统一 lambda0=0.5。
- 同一强度同时用于碰撞、融化、粒子、液体、破碎，缺乏合理性。

定位建议：暂停把 M2 当成“增强版本”；先作为消融项，降低并归一化残差后再判断是否保留。

### 5.4 M3：I2V + positive−counterfactual

M3 的想法比 M2 更接近因果对比，但当前实现仍未成功：

- 评级仍与 M1/M2 相同，仅 P20 勉强可用。
- M1–M3 有 11/20 个样本 SSIM 大于 0.90；M2–M3 有 10/20 大于 0.90。
- P13–P16 的相似度普遍约 0.97–0.98，说明对守恒/扩散类任务几乎没有改变核心失败行为。
- positive 和 counterfactual 通常共享所有实体与动作，只差 before/after、unchanged/decrease 等关系词。文本编码/交叉注意力差值未必能把这种逻辑差异稳定映射成视频时间方向。
- 两个分支都先拼接完整原始提示，再重复一次事件，公共语义很强，关系差异相对弱。
- 最后 20% 去噪步的 step gate 为 0，终态形成/稳定阶段反而没有任何 ACE 修正。

定位建议：保留为研究主线候选，但必须加入“普通完整提示基线”、残差归一化、层/步消融和多 seed 评估，否则无法证明改进来自 ACE。

### 5.5 M4：T2V + ACE

主要问题：

- 没有 I0 图像进入模型，ACE 只有文本方向，无法固定主体数量和空间关系。
- M0–M4 有 6/20 个样本逐帧 SSIM 大于 0.90，许多输出与基础 T2V 接近。
- 对细粒子、容器守恒、撕裂等任务，文本残差无法补回对象级控制。
- 与 M0 相同，常出现局部特写、事件从中段开始、主体缺失。

定位建议：当前优先级最低。先把 I2V 的 M1/M3 做到可靠，再考虑 T2V ACE。

## 6. 代码和实验设计层面的根因

### 6.1 视频时长统一为 2.04 秒，无法覆盖多阶段事件

所有视频都是 49 帧、24 fps。它对单次快速接触尚且紧张，对以下任务明显不够：

- P08/P09：逐步融化并形成稳定液池。
- P10：先持续充气、达到最大、再爆裂并留下碎片。
- P12：风到达、渐进脱落、漂走、花头耗尽。
- P16：染料进入后边界持续扩散。
- P17：按扁、手离开、逐渐回弹。
- P18：多次弹跳、峰值逐次降低、最后静止。

只把 fps 从 24 改小会让播放变慢，但不会增加模型生成的状态数；核心是增加 frame_num，并按事件类型分配时长。

### 6.2 细粒子/液位/裂纹与当前空间分辨率不匹配

80 个视频为 640×352，20 个为 352×640。对普通大物体尚可，但：

- 蒲公英单根冠毛、碎玻璃、染料边界、杯中液位只占少量像素。
- VAE 再次下采样后，粒子会合并为线条/块状，容易产生枝条和网状拓扑。
- 提高全局分辨率会增加显存，应优先改善构图，让关键状态占据更大画面，同时保留必要运动空间。

### 6.3 I0 元数据写得很细，但根本没有用于条件生成

Pxx-i0.json 中有：

- required_visible_entities
- protected_scene_properties
- transition_variables_not_to_freeze
- reject_if
- layout_requirements

当前 schema.py 只校验这些字段是非空字符串列表；真正调用生成时，infer_ace_router.py 只传入 original prompt、图像和 cplus/cminus。上述约束没有进入 positive prompt、negative prompt、mask、轨迹或 post-check。

结果是“元数据看起来很严格，但模型完全不知道这些约束”。

### 6.4 60/60 个 I2V 结果都缺 selection manifest

M1/M2/M3 的 manifest 全部带 selection_manifest_missing；YAML 又设置 REQUIRE_SELECTION_MANIFEST=0。

虽然本批 I0 图整体构图不算差，但流程上没有强制人工/自动审核 I0 是否满足 reject_if。后续更换 I0 时，这会让不合格首帧直接进入整批推理。minimum_confidence 只是 cplus/cminus 元数据的文本置信度，不是图像或视频质量分数。

### 6.5 固定残差强度，没有归一化或安全上限

当前 M2/M3/M4 均使用：

- lambda0=0.5
- mvp_mid16：第 8–13 层权重 0.4，第 14–23 层权重 1.0
- step gate：前 30% 为 1.0，30–60% 为 0.7，60–80% 为 0.3，最后 20% 为 0

20 个样本的诊断汇总：

| 模式 | 每样本 scaled/semantic 最大值的范围 | 中位数 |
|---|---:|---:|
| M2 | 9.25%–15.87% | 11.72% |
| M3 | 9.40%–15.42% | 11.02% |
| M4 | 8.40%–14.18% | 10.29% |

这是单个被采样 block 的比值，不是 16 层累积后的总效应。不同提示的 raw delta 最大值跨度也很大，却统一乘同一个 lambda，容易出现有的样本几乎不变、有的样本语义过冲。

### 6.6 残差方向不够“纯”

当前 positive_text 和 counterfactual_text 都是：

原始完整提示 + 另一句完整事件描述

问题包括：

- 同一对象和动作被重复一遍，可能强化纹理/实体而非关系。
- M2 的 positive 与 semantic 长度差很大。
- M3 两个分支长度和句法并不严格匹配。
- cross-attention 输出差不是一个经过训练验证的“因果向量”；它还包含句长、构词和注意力分配差异。
- counterfactual 不是 CFG negative；代码明确只对 conditional block 做残差，然后仍用通用 negative prompt 做 CFG。

### 6.7 通用 negative prompt 与当前失败类型不匹配

实际 negative prompt 主要抑制：

- 低质量、模糊、过曝、字幕。
- 人手、人脸、肢体畸形。
- 杂乱背景、倒着走。

本任务最常见的失败却是：

- 新对象出现。
- 主体复制/消失。
- 接触前后顺序错误。
- 物体变成树枝/花瓣/香蕉。
- 水流从画外生成。
- 终态回退。

这些几乎都未被覆盖。

### 6.8 只用一个 seed，且没有后验筛选

100 个视频全是 seed 42：

- 不能区分“方法稳定差”与“这个 seed 恰好差”。
- 无法报告方差或 pass@N。
- 当前程序生成一个就无条件保存，没有严格 VLM/规则/人工 reject 和 rerank。
- 即使未来使用 best-of-N，也必须同时报告 pass@1，不能只展示最好样本来掩盖方法不稳定。

### 6.9 现有 diagnostics 只检查数值，不检查视频质量

all_finite、L2、cosine 等只能发现数值爆炸。它们不能发现：

- P12 树枝。
- P13 水流来源错误。
- P04 多米诺倒下后复原。
- P18 球复制。
- P20 是否真的倒进杯中。

必须增加对象、状态、因果和终态层面的 postflight。

## 7. 建议的解决方案

### 7.1 先建立严格评测，不要继续凭观感挑好帧

建议每个视频输出 quality_audit.json，至少包含：

- entity_count_ok：主体数量是否正确。
- identity_preserved：同一主体是否连续。
- trigger_visible：原因/接触是否可见。
- order_correct：关键阶段顺序是否正确。
- terminal_state_reached：是否到达目标终态。
- terminal_state_persistent：末段是否保持。
- conservation_ok：物体/液体/颗粒是否近似守恒。
- foreign_object_free：是否无外物闯入。
- camera_stable：是否无不必要镜头漂移。
- strict_grade：A/B/C/D。
- reject_reasons：上述问题代码列表。

自动评估可以先用关键帧 VLM + 任务专用规则，但最终正式表格至少要人工复核所有候选 A/B。任何 EX、ID、严重 DEF、END 都应直接拒绝。

### 7.2 真正使用 I0 元数据

将 I0 JSON 的信息用于三个位置：

1. 正向条件：精确对象数量、固定镜头、保留场景属性。
2. 负向条件：把 reject_if 转成简短的样本特定 negative prompt。
3. 后验检查：用 required_visible_entities 和 initial_states 审核 I0；用 changed_state_variables 审核视频。

P12 的样本特定约束应明确包括：只有一颗蒲公英；不出现叶片、树枝、手或第二朵花；既有细种子只能从同一花头脱落；背景和相机固定。

### 7.3 增加“完整正向提示直接生成”这一关键基线

当前没有回答一个最基本的问题：把 causal_positive 改写成一条自然、完整、无重复的普通 prompt，直接交给 Wan，会不会已经比 ACE 好？

必须比较：

1. M1-short：当前原始短提示。
2. M1-full-positive：一条完整正向提示，直接作为 semantic，不注入残差。
3. M2-normalized：正向引导残差。
4. M3-normalized：正向减反事实残差。

若 M1-full-positive 已经达到同等或更好效果，则当前收益不是路由创新，而只是 prompt 更详细。

### 7.4 重写 positive/counterfactual，避免重复和句长污染

不要再拼接“原始提示 + 重复描述”。建议每个分支都是一条独立、完整、长度接近、句法匹配的事件描述：

- 正向和反事实使用完全相同的实体词。
- 只改变一个因果关系或状态转移。
- 尽量保持相同词数和语序骨架。
- 对 M2，positive 应是完整重写 prompt，而非比 semantic 多一整句。

### 7.5 给残差加归一化、裁剪和自适应强度

建议先把每个 block 的残差安全上限控制在 semantic 范数的约 1%–3%，而不是当前常见的 10% 以上。可采用：

- 按每样本、每层、每步计算 delta/semantic 范数比。
- 对 delta 做 norm clipping。
- lambda0 先扫 0.05、0.10、0.20、0.30，不再直接把 0.5 当统一默认值。
- 分别记录 unclipped ratio、clipped ratio 和累积影响。

这不能自动解决因果理解，但能显著降低 P12 这类拓扑过冲风险。

### 7.6 重做层和步调度消融

当前 mvp_mid16 是未经本批任务验证的固定选择。至少比较：

- mid_b：只注入 14–23 层。
- late：只注入 20–29 层。
- 低强度 mid + late。
- 前段弱、后段保留小门控的 schedule。

现在最后 20% 完全关闭 ACE，可能导致终态约束丢失；但过强 late injection 也可能破坏细节，所以必须实测，而不是凭理论选定。

### 7.7 按事件类型设置 frame_num/fps

建议先做显存 smoke test，再逐类使用：

| 事件类型 | 样本 | 初始建议 |
|---|---|---|
| 快速刚体接触/倾倒 | P01–P07 | 65 帧，16 fps，约 4.1 秒 |
| 慢变化/扩散/回弹 | P08、P09、P12、P16、P17 | 81 帧，16 fps，约 5.1 秒 |
| 液体/沙子转移 | P13–P15、P20 | 65 或 81 帧，16 fps |
| 多次弹跳 | P18 | 97 帧，16 fps，约 6.1 秒 |
| 爆裂/破碎/撕裂 | P10、P11、P19 | 65 帧，16 fps，并明确预留末段保持终态 |

65、81、97 都满足 4n+1。若 48 GB 显存压力过大，先用 65 帧验证时序，再考虑分段生成；不要只降低 fps 假装增加动作完成度。

### 7.8 对不同物理类别使用更强的显式控制

文本 cross-attention 很难独立解决所有任务：

- 刚体碰撞/多米诺/弹跳：对象 mask、轨迹、关键点或光流控制。
- 液体/沙子：源容器与目标容器 mask、液位/堆面积的单调约束。
- 蒲公英：花头 mask + 粒子轨迹/粒子数量递减。
- 融化/扩散：初末状态或多关键帧控制。
- 破碎/撕裂：首末帧、裂纹路径或外部简单模拟。

若目标是“物理正确”而非“看起来像视频”，最稳的路线是先用简单模拟/程序动画得到运动骨架，再做 video-to-video 外观增强。纯文本残差更适合作为轻量语义引导，不应承担对象守恒和动力学本身。

## 8. 下一步操作方案

### 阶段 0：立即停止下一轮全量 100 视频

先不要用当前 lambda0=0.5 和固定 49 帧再跑一次全量。那大概率只会得到另一批不同形式的失败。

### 阶段 1：完善输入和评测闸门

1. 为 20 个 I0 建立并强制要求 Pxx-i0-selection.json。
2. 设置 REQUIRE_SELECTION_MANIFEST=1。
3. 加入 quality_audit.json 和 A/B/C/D 硬门槛。
4. 将 I0 元数据中的保留项、reject_if、状态变量用于条件和 postflight。
5. 每次运行输出按模式/样本/seed 的汇总表，不能只看技术 success。

### 阶段 2：做 40 视频诊断性小实验

先选：

- P02：双球碰撞和动量传递。
- P08：连续融化。
- P12：细粒子和对象耗尽。
- P13：源—流—目标守恒。
- P20：当前唯一正向对照。

四个配置：

1. M1-short。
2. M1-full-positive。
3. M2-normalized，残差目标比约 1%–3%。
4. M3-normalized，残差目标比约 1%–3%。

使用 seed 42 和另一个固定 seed，共 5×4×2=40 个。先统一 65 帧/16 fps；慢变化样本若动作仍未完成，再单独升到 81 帧。

### 阶段 3：通过闸门后才扩大

进入全量前至少满足：

- P12 所有候选 seed 都不能出现树枝、叶片、第二主体或花头增生。
- EX/ID/严重 DEF 率不得高于 M1。
- M2/M3 对 M1-short 的严格合格率至少有明确提升，且不只在 seed 42 上成立。
- M3 必须优于或至少显著区别于 M1-full-positive，否则不能声称是 ACE 带来收益。
- 末段终态保持率必须单独统计。

### 阶段 4：正式评测

- 每个模式至少 4 个固定 seed。
- 同时报告 pass@1、平均通过率、最差 seed 和 pass@4。
- 不能只展示 best-of-N。
- 正式候选 A/B 全部人工复核。
- 保留 M0/M4 作为弱 T2V 对照，但研发资源优先投向 M1/M3。

## 9. 最重要的优先级

| 优先级 | 动作 | 原因 |
|---|---|---|
| P0 | 建立严格 postflight 与 A/B/C/D 判定 | 当前最大问题之一是把“有运动”误判成“质量好” |
| P0 | 将 49 帧改为按事件类型的 65/81/97 帧 | 2.04 秒无法完成多数多阶段任务 |
| P0 | 降低并归一化 ACE 残差 | 当前单层可达 semantic 的 10%–16%，P12 已出现明显过冲 |
| P1 | 加 M1-full-positive 基线 | 判断收益到底来自详细 prompt 还是 ACE |
| P1 | 真正使用 I0 元数据与 selection manifest | 目前大量严格约束只存在于 JSON，模型和审核都没用上 |
| P1 | 多 seed + 严格拒绝/重排 | 单 seed 不能说明稳定性 |
| P2 | 任务专用 mask/轨迹/初末帧控制 | 文本残差不足以保证对象和物质守恒 |
| P3 | 再考虑扩大 M4/T2V ACE | 当前无首帧布局，严格合格率为 0 |

## 10. 一句话判断

当前 M0–M4 的核心问题不是“画面不够精致”，而是模型没有稳定完成物理事件；M2/P12 是明确的严重失败。下一步应该先修评测门槛、时长、条件使用和残差安全性，完成小规模多 seed 消融，再决定 ACE 路由是否值得继续扩大，而不是立刻重跑下一批 100 个。
