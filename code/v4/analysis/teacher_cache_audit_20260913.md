## 2. 稀疏时间监督：存在实质盲区，但不能据此单独认定崩坏根因

实际配置 `teacher_frames:16`，所有通常长度视频只得到 8 个时间 tubelet。101 帧视频选取：

```text
0,7,13,20,27,33,40,47,53,60,67,73,80,87,93,100
```

`coordinates.py:23–25` 均匀抽样后，`encoders.py:61–66` 仅将这 16 帧送入教师；101 帧中其余 85 帧没有直接进入这个教师目标。短时接触、反弹前后速度、液滴破裂、手/脸短时形变等可能落在抽样间隙中。即使以后打开 output teacher loss，同一抽样方式依然不能直接看到所有输出帧。需要区分：**FM loss 仍然覆盖全部未来 latent 时间位置**（`losses.py:68`），所以不能说全模型只监督 16 帧。

教师本身没有接收实际秒数参数；它以抽样后的序号构建时空位置。v4 P 查询使用实际秒数，这解决了模型内部坐标对应，但不等于教师已明确辨识物体每秒速度。不同长度/源 fps 视频压成相同 16 帧，教师所见运动时间尺度随输入变化。本地 V-JEPA 2.1 配置 `configs/train_2_1/vitG16/cooldown-256px-64f.yaml:19–23` 使用 64 帧、4 fps，说明存在不同的预训练时间采样设置；不能仅凭这一个本地配置认定当前 384 checkpoint 必须采用唯一帧率，也不能把 16 帧调用本身判为接口错误，教师实现支持动态 T。

解决方向：先保证训练/推理的物理时长定义一致；在固定少量代表案例上比较 16 帧全局教师与更密的局部窗口教师，保留接触前/接触时/接触后三段。不要直接将 16 增到 64 后继续沿用旧缓存和权重，并期待仅靠增加目标 token 就自动解决现有生成崩坏。

## 3. 结构 MSE 与 prior pooling 更容易强调静态、全局内容

`losses.py:40–62` 采用所有内容 token、所有特征通道均匀平均 MSE。`losses.py:28–37` 的 prior loss 更进一步：先对每个时间 slot 的全部空间 token 求内容加权均值，再比较 prior 与 teacher。这样每个时间点的空间配置可以改变而不影响 prior loss，只要均值不变。prior 同时还间接受到后续结构/FM loss 约束，故不能说整个 prior 完全没有空间监督。

统计定义：令 `z[t,s,c]` 为教师输出、`w[s]` 为内容权重。

- 总能量 `E=mean_w(z²)`。
- 每视频常量基线：用该视频全部时空 target 的一个均值向量替代所有 token，其 oracle MSE 为 `C`。
- 逐空间位置静态模板：用 `mean_t(z[t,s,c])` 替代每个时间点，其 oracle MSE 为 `Vt`。
- 这些基线均读取了完整 GT，**不能作为可部署预测器，也不能用来证明学生实际预测成常量**；它们只描述目标能量分布和评价难度。

验证 index 12 的时空常量 MSE `1.267448902` 与 checkpoint `metrics.json` 完全一致。该样本的逐位置静态模板 MSE 仅 `0.453118`；空间平均后，剩下的时间变化能量仅 `0.034863`，约为池化目标总能量的 1.73%。因此 **prior loss 很低或全局 cosine 很高，都不足以说明模型学到了运动、时序因果或物理现象**。这九个样本不是随机总体抽样，不能把百分比直接推广为整个 WISA 的比例。

本地教师输出经过带权重/偏置的 LayerNorm，RMS 不必为 1；实测约 1.8 是一致行为，并非“忘记归一化导致缓存损坏”的证据。本地 V-JEPA 自身训练的 `app/vjepa_2_1/train.py:591–610` 对 target 另做无仿射 `F.layer_norm`；v4 直接回归官方推理表示。这是目标定义选择，与照搬原 JEPA 预测任务不同，应做可控对照，不能断言必须加 LN 才正确。

解决方向：

1. 将动态残差/相邻时间差目标、局部空间目标与现有全局目标分别报告，确保运动误差没有被静态内容平均掉；使用运动区域或事件局部加权时，要核对遮挡和相机运动，避免把大运动一律当正确。
2. prior 除空间均值之外增加有限的空间分区/对象局部监督或时序差分监督；不是盲目放大现有 pooled loss。
3. 归一化或通道白化只能作为新 target 定义的实验，必须版本化缓存并重新训练/显式迁移。直接对现有推理 P 归一化会改变已训练 writer 的输入分布。
4. 用真正的生成视频检查事件发生、物体身份与形状、接触前后轨迹、颜色/曝光稳定性，而不是将教师 MSE/cosine 当作物理正确率。

## 4. 已证实的小范围几何监督/读取不一致

`data.py:37–45` 的 `teacher_content_weights` 计算两次 letterbox 后真实源图像的内容范围；`coordinates.py:93–100` 的 `process_valid_indices` 仅按第一阶段 canvas 在教师 384×384 中的外部 letterbox 计算，没有使用源图像在 canvas 内部的 padding。

对本次实际训练前 1000 条 record 的保存元数据逐条审计，有 **6/1000** 条会把权重为零的 P token 纳入 H 读取 P 的集合。这些样本每个时间 slot 包含 24 个额外完全无监督的边缘 token，占各自允许读取集合的 5.56% 或 7.14%；例如 index 255、513、536、637、770。`corrector.py:445–449` 确实将这个集合交给 write attention。进一步 CPU 读取 index 255 和 637 的真实 VAE 缓存，分别确认可读 3456/2688 个 P token 中均包含 192 个 `target_weight == 0` 的 token（8个时间 slot × 24）。

这是有直接代码/几何证据的实现缺口，但样本占比很小，**不能把整批人脸形变/闪色归因于它**。对于有部分有效内容的边缘 patch，teacher 会把内容与黑边共同编码，内容面积权重也不能完全消除这种边缘效应。

解决：训练时用与 `target_weight > 0` 一致的真实内容几何定义可读 token；推理在有 source image/canvas transform 时沿用同一定义，无图推理采用满 canvas。对额外边缘 token 是直接剔除还是连续加权，需要与训练保持一致。这应属于后续实现修正，不能靠本次报告悄悄改现有 checkpoint 推理行为。

## 5. 缓存之外的证据边界

这个 checkpoint 的 A1 配置明确 `out_weight:0.0`，因此当前训练完全没有通过解码视频的教师输出施加 output loss（`losses.py:80–87`）。现有结构 target 是教师表示约束，不能直接强制解码后的颜色/人脸/刚体性质符合视觉或物理要求。FM 才是当前唯一直接关联生成输出的训练主目标。是否是训练导致 writer 破坏冻结 Wan、GT 条件依赖、CFG 放大或推理分布差异，应结合主报告中的参数/日志/50步实际结果来判断；本附件不把“教师局限”提升为未经对照的唯一根因。
