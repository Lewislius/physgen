2. 总损失为什么没有下降，以及哪些部分确实没有改善。

以一条样本写，本次目标是：

L_total = L_FM + 0.1 × a(s) × w(σ) × L_struct + 0.02 × a(s) × L_prior。

a(s) = min(1, s/200)，w(σ) = clip((1−σ)/0.2, 0, 1)，其中 s 是从 1 开始的优化器步数。L_struct 是六次提交 P 的 MSE 的平均值，并非六项不归一化相加；不能因为有六个 A 就认定结构损失被乘了六倍。L_FM 比较未来 latent 槽的预测速度与 noise−clean，首帧槽不参与该 MSE。

损失实现见 [losses.py](/home/liuzhirui/Project/physGen/code/v4/physgen_v4/losses.py:65)。旧版和当前版对此实验适用的权重及归约公式相同。

|---|---:|---:|---:|---:|---:|---:|
| 1–50 | 0.31018 | 0.28085 | 2.49315 | 0.02520 | 1.74571 | 0.00412 |
| 51–100 | 0.31782 | 0.25195 | 1.78059 | 0.06048 | 0.74687 | 0.00538 |
| 101–150 | 0.38612 | 0.28304 | 1.70897 | 0.09661 | 0.51659 | 0.00647 |
| 151–200 | 0.42733 | 0.28409 | 1.65962 | 0.13465 | 0.49029 | 0.00860 |
| 201–250 | 0.40595 | 0.25222 | 1.62598 | 0.14435 | 0.46837 | 0.00937 |
| 251–300 | 0.40519 | 0.25275 | 1.59842 | 0.14351 | 0.44624 | 0.00892 |

前 200 步的总损失不能直接横向比较，因为辅助损失权重不断增加。原始 struct 已下降约 35.9%，prior 已下降约 74.4%，而加权 struct 反而从 0.0252 增大到 0.1435。若只在记录值上消除辅助权重 warmup，使用相同满权重重新汇总，前 50 步为 0.53726、251–300 步为 0.40519。这是一个观测口径修正，不能解释为“从第一步用满权重训练也会得到同样结果”。

但第 200 步之后 warmup 已结束：201–250 与 251–300 的 FM 分别为 0.25222、0.25275，总损失分别为 0.40595、0.40519。用户观察到的近期平台是真实的，不能全部归因于 warmup。

FM 本身也有较大的抽样噪声。306 步间 FM 标准差约 0.0742，step 平均 σ 与 FM 的相关系数约 −0.639。逐样本分桶后，251–300 步在 σ∈[0,0.2)、[0.2,0.4)、[0.4,0.6)、[0.6,0.8)、[0.8,1) 的 FM 均值依次为 0.5280、0.2593、0.1834、0.1357、0.1762。低噪声与中噪声样本的损失量级不同，不能把随机 batch 的涨跌直接当成视频质量涨跌。

部分桶相对早期有改善，例如高噪声桶从前 50 步的 0.2279 到最近 50 步的 0.1762；这说明不能说 FM 从未学习。不过各窗口的视频和桶内 σ 分布不同，这些数字不是配对验证收益。FM 是速度回归目标，随机条件训练 MSE 也不要求收敛到零；需要比较相同样本、噪声及条件下的基线与 checkpoint。[Flow Matching 原论文](https://arxiv.org/abs/2210.02747)

3. 更严重的事实：P 的更新路径已经退化。

校正器的实际提交关系是：

P_after = P_before + η × sigmoid(state_logit) × delta。

本次 A 的 state_strength 为 0.2。高噪声早期抑制只作用于写回 H 的幅度；B 未启用。A 状态门极小不能解释成 B 尚未启用，也不能解释成高噪声的正常旁路。[状态更新代码](/home/liuzhirui/Project/physGen/code/v4/physgen_v4/corrector.py:411)

| 位置 | 251–300 步平均状态门 | 平均实际 ΔP RMS | 平均写回 RMS / H RMS |
|---|---:|---:|---:|
| A@5 | 8.59×10⁻⁸ | 1.09×10⁻⁸ | 20.76% |
| A@10 | 4.18×10⁻⁸ | 3.59×10⁻⁹ | 21.89% |
| A@15 | 1.19×10⁻⁷ | 1.40×10⁻⁸ | 14.76% |
| A@20 | 9.68×10⁻⁶ | 1.32×10⁻⁶ | 8.45% |
| A@25 | 6.22×10⁻⁷ | 8.63×10⁻⁸ | 11.67% |
| A@30 | 4.07×10⁻⁶ | 5.20×10⁻⁷ | 0.31% |

六个门的 mean 从第 100 步开始一直低于 0.001；最近 50 步所有位置 state_gate_low_fraction 都为 1，即全部 token 的门均低于 0.05。candidate_rms 仍约 0.65–0.75，实际更新却只有 10⁻⁹–10⁻⁶：直接阻断更新的是乘法门。第 25 步这些门曾经约为 0.99，因此这不是初始设计就把 A 永久关闭。

第 101–306 步，记录的 initial P MSE 与平均更新态 struct MSE 的最大差只有 1.67×10⁻⁶，最近 50 步的平均 struct_gain 约为零。这里还有一个比门均值更有力的交叉验证：在第 250 步唯一验证视频上，五个 σ 下的初始 P MSE、六个更新态 P MSE 都是 1.54359865，末端 target cosine 都是 0.72486866。P₀ 不接收 σ，各层又不再改变它，所以出现了这个结果。

实际功能因此接近：

文字＋首帧 → P₀ → 六个位置各自用 H 查询这个几乎不变的 P₀ → 写回 Wan。

P₀ 本身仍可以含有时空变化；“静态”在这里特指它在校正层和去噪进程中几乎不更新，不意味着 P 的所有时间 token 都一样，也不意味着生成视频必然静止。写回仍依赖 H、位置和 σ，因此生成分支并非完全停止工作。问题在于设计所期望的“从不断变化的 H 提取新观察，逐步修正物理状态”没有在这些指标中实现。

FP32 状态存储不能修复这个优化问题。sigmoid 接近 0 时，delta 分支梯度乘以 gate，gate 自身导数 gate×(1−gate) 也很小。部分实际增量已接近 FP32 在当前状态量级的分辨率，门饱和会使这一路更难恢复。所有训练标量均有限，全局梯度最大约 0.2195，梯度裁剪从未触发；没有证据把平台归因于 NaN、全模型没有梯度或 grad_clip=1 太严格。

4. “P 监督太强而 hacking”这个想法，哪些部分成立。

可以确认的是一种绕过动态校正的行为；不能确认的是它完全由 struct_weight=0.1 导致，或它已使生成结果劣于原 Wan。

从损失数值占比看，251–300 步 FM 占 62.38%、struct 占约 35.42%、prior 占约 2.20%。因此不能拿原始 struct=1.6 与 FM=0.25 比较，得出 P 目标比 FM 强六倍；训练使用加权值。但损失数值比例也不能决定梯度主导关系，不同路径的 Jacobian 和参数量不同。

结构上确实存在容易降低辅助误差的路径：

- P₀ 有约 2,059 万参数，从首帧、文字和位置预测完整教师坐标系中的 P；
- 每一处 dense L_struct 都能经残差恒等路径反传至 P₀，不只有那个权重 0.02 的 pooled L_prior 在训练初始化器；
- 当 P₀ 提升后，校正器若尚未学会提供有用增量，关闭状态门就能避免增加 MSE；
- writer 即使用不变的 P₀ 也能通过 H 查询继续拟合 FM，因此 FM 不要求状态门必须打开；
- 这样形成“初始化器承担表征拟合，writer 承担生成适配，动态更新核心退出”的局部解。

梯度记录与参数训练集中到初始化器的现象相容：201–300 步普通单前向更新中，初始化器占全局梯度平方范数的平均比例约 84.5%；双噪声暖起步约为 17.8%，后者的 carried P 已 detach，初始化器只接受重新计算 P₀ 的 prior 监督。注意这只是按参数组统计，不是按 loss 来源统计，不能把 84.5% 解释成“84.5% 的梯度来自 JEPA”。

原生同维度 P、固定教师以及 writer 消费实际提交 P，能避免一部分任意匹配头的作弊空间，但不能排除上述门关闭路径。“P 更接近教师”与“视频生成的因果过程更正确”不是同一项验收结果。

还有一个弱证据需要谨慎看待：最近 50 步 P MSE=1.5984，而每段 GT 自己的全时空平均教师向量对应的常量 MSE=1.2436；验证视频对应 1.5436 与 1.2674。它提示 dense 细节学习仍不理想，但 GT 均值本身使用了未知未来，是 oracle 诊断，不能当成可部署基线，也不能据此断言 P 已严格塌缩为全局常量。要确认语义均值捷径，需要进一步测 P 的时空方差、条件敏感性，以及屏蔽 H 观察后 P/输出是否改变。

最合理的归因顺序是：状态门饱和是已观测事实；初始化捷径与目标耦合是有代码依据的机制解释；辅助梯度是否压制 FM，以及学习率/双噪声训练分别贡献多少，仍需实验。

当前验证 every=250、samples_per_rank=1、world_size=1，因此每次实际只检查 1 条视频的 5 个噪声水平。启动时显示 validation_samples=200，是验证池大小。报告中的 validation_loss=0.19020676 是五个 FM 值的算术平均：

| σ | 第 250 步验证 FM |
|---:|---:|
| 0.10 | 0.412046 |
| 0.35 | 0.157143 |
| 0.60 | 0.096030 |
| 0.85 | 0.070159 |
| 0.98 | 0.215656 |

该运行没有训练前的相同验证值，也没有原 Wan 在相同视频/噪声上的值。不能把 0.1902 直接与随机训练集 FM=0.25 比较，推断泛化良好或训练收益成立。[验证实现](/home/liuzhirui/Project/physGen/code/v4/train/train_native_p.py:123)

已有 evaluation 目录中没有发现可归属于此次 checkpoint 的完整生成视频、配对评分或 writer 归因结果。现有 CPU/运行契约检查只验证代码能否按预期计算，不能替代生成质量验证。

L_out 在 A1 为 0 并不意味着没有视频生成监督，FM 本身就是生成训练目标。但当前确实没有额外通过解码视频回传的约束。A3 的 L_out 会把单步端点解码后送同一 JEPA 教师计算特征距离，它仍是代理目标，并非完整 50 步采样的视频质量或物理正确性指标。每四步才开启且 σ 范围变为 0.05–0.4，也会改变 FM 的采样分布，跨阶段的总损失不能直接拼接比较。

V-JEPA 2.1 官方目标是学习高质量、时间一致的稠密表征，并未把特征距离定义为生成画质或物理正确性概率。由此推断，降低这项特征损失无法单独给出生成质量保证。[V-JEPA 官方实现说明](https://github.com/facebookresearch/vjepa2#v-jepa-21-pre-training)

表征辅助监督本身也不能一概否定。REPA 在图像 diffusion/flow Transformer 上显示过生成收益，并报告对齐较早层比把对齐放到更深层更有利；它的经验不等于“六个位置原生 P MSE 越强越好”，也不能直接推广成当前冻结视频骨干方案的收益保证。[REPA 论文及对齐深度实验](https://arxiv.org/html/2410.06940v2)

训练与推理还存在状态分布差异。本次大部分训练步从 P₀ 开始，1/3 使用同视频另一标准加噪视图的 detached P；高噪声预测没有经过 sampler 产生第二个训练 latent。推理则默认在整个去噪链中携带 cond/uncond 各自的 P。这不是完整采样展开训练，不能保证恢复状态更新后长期不会漂移。当前门几乎关闭使漂移较小，也意味着持久状态的预期收益可能很小。

最后，当前 A1 训练约 8.379 亿个新增参数，却只有 1,000 条训练视频；300 步约对应 2.4 遍样本，既不能仅凭步数认定充分收敛，也不能用“还早”忽略门已饱和。规模与数据量的组合增加优化和泛化风险，但仅凭这些记录不能诊断已经过拟合。

6. 建议按以下顺序解决，而不是先堆更多阶段或损失。

第一步，保留第 250 步 checkpoint，建立它与原 Wan 的真实配对比较。先做 16–32 条固定留出视频、固定首帧/文字/噪声、按 σ 分桶的端点 FM；再对 8–16 个代表性场景各取 2–3 个种子完成相同步数采样。比较原 Wan、当前 A，以及当前 A 的 reset-state。评价清晰度、主体一致性、运动、接触/碰撞/遮挡关系、提示词遵循和失败率，不只评价 JEPA。

已有 [attribute_correctors.py](/home/liuzhirui/Project/physGen/code/v4/evaluation/attribute_correctors.py:70) 能做相同 H/P 起点的 on / writer_off / off 后缀比较，[generate_cases.py](/home/liuzhirui/Project/physGen/code/v4/evaluation/generate_cases.py:10) 能做固定条件生成。A1 的 full 和 A 实际都只有 A，优先比较 wan 与 A，避免把重复变体当成两个独立实验。

应记录配对 ΔFM = FM_corrector − FM_wan；负值表示该配对端点误差改善。逐位置 writer_gain = FM_writer_off − FM_on，正值表示该位置的写回有帮助。端点收益与完整视频收益分别汇报。若 P 误差下降、上述生成指标没有改善，就不应把该 checkpoint 判为有效进展。

第二步，直接测损失分项梯度，确认用户的权重假设。在固定小验证批上分别计算 g_FM、g_struct、g_prior，保留实际损失权重；分别检查初始化器、状态更新核心、read 分支和 writer 的范数及夹角。观察 R = ||g_struct+g_prior||/(||g_FM||+ε)，并记录与 g_FM 的余弦。长期较大的辅助梯度且与 FM 方向冲突，才是“辅助任务压制生成”的直接证据。总梯度 norm 或 loss 百分比不能替代这个检查。

第三步，先做清楚的权重消融。建议从同一新初始化、同样样本顺序/训练预算开始，固定旧 image_text 和双噪声设置以避免同时改多个因素：

| 对照 | fm_weight | struct_weight | prior_weight | 用途 |
|---|---:|---:|---:|---|
| 原设计 | 1 | 0.1 | 0.02 | 可复现基线 |
| 较弱辅助 | 1 | 0.01 | 0.002 | 检查辅助强度是否导致门饱和/生成退步 |
| FM-only | 1 | 0 | 0 | 检查新增容量单独拟合生成目标的效果 |

这些值是建议的诊断起点，不是已经验证的最优超参数。若 only-FM 与较弱辅助都有更好生成收益，且原设计门更容易关闭，才能较强地支持原权重不合适。

不要只从已经关门的第 250 步继续调小权重，就据结果否定权重假设：饱和门可能已经难以恢复。没有较早 checkpoint 时，短程重启 A1 更适合做干净归因。

第四步，处理状态门的不可恢复饱和。可先做一个独立实验：初期固定 state gate 为温和常数，例如 0.1–0.2，delta 输出层从零或小值开始；之后再释放门学习，且门参数使用约主学习率的 1/10。另一种方案是给 gate 加小正下限，例如 g=0.05+0.95×sigmoid(logit)，使 delta 分支仍可获得梯度。下限不能阻止 delta 自己趋近零，也不保证物理收益；其作用是排除“门一关便几乎不可恢复”的路径。

不能直接在推理时强行打开当前 checkpoint 的门：delta 与 writer 已适应该门状态，突然放大增量可能破坏现有生成。任何修复均应放在独立训练分支里，先验证 P 更新确实带来正的 struct_gain 或端点/生成收益。非零更新本身不是成功标准。

第五步，调整 P₀ 与动态校正器的责任分配。当前只降低 L_prior 不够，因为 dense L_struct 仍能通过全部恒等路径训练 P₀。可先把 P₀ 用粗 prior 目标预训练至合理水平，暂时冻结 P₀，让校正器学习从 H 提取相对 P₀ 有价值的信息；或按损失来源路由梯度，让 dense struct 主要训练动态更新，而 FM 仍保留经过 P₀ 的梯度。后一方案不能用简单的整条 P₀.detach() 代替，否则也会切断 FM。

对所有深度提交态都使用相同完整未来目标，可能促使它们趋向同一可由条件预测的表示。可将辅助对齐集中到少数较早位置或降低后层权重，把后层生成自由度交给 FM，但同样需要配对验证。不要仅把结构损失移到一个与实际 writer 消费状态脱离的额外头，这会重新增加“辅助头学会了而生成没变”的风险。

第六步，在上述受控试验后，再单独评估后来增加的 GT 初始化。GT 能让训练时预测未来表征更容易，但也可能加强初始化捷径和训练/推理条件差异；25% 无 GT 训练是否足够，没有此次运行的证据。应比较全程无 GT 与混合 GT 训练，在全部无 GT 的留出生成上验收，不能用给 GT 时的更低训练 loss 判优。

相同地，A2 把几乎为零的增量重复两次，不能期待自动救回动态 P；A3 增加 JEPA 输出约束也不保证救回门；B1 会引入新的 B 更新，但不能据此认为已退化且冻结的 A 会自行恢复。不建议仅因某个阶段步数跑满，就继续扩大原配方训练预算。
