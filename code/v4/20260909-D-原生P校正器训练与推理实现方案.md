## 1. 最终范围与相对主设计的调整

冻结 Wan2.2 TI2V-5B、VAE、UMT5 和 V-JEPA 2.1。新增独立条件先验初始化器，以及第 5、10、15、20、25、30 个 block 各自独立的完整 A corrector；每套拥有两层、1664 通道的状态更新核心和全部读写／条件／门控参数。后续 B 阶段在第 18 层使用另一套独立 B corrector。持久 P 与教师最终层保持相同的原生时空网格、1664 通道；writer 必须消费实际提交的 P，结构损失也监督这一张量。

本次生成器使用 FM、更新态 L_struct，以及权重较小的初始条件先验 L_prior；后续阶段可启用 L_out。L_prior 可设为 0 做消融；它不是获得初始化梯度的必要条件，而是明确约束初始化器本身的粗时序语义。L_align 及匹配头仍不启用，不引入独立 P 扩散链、错误视频配对或推理筛选。训练主链改为 A1→A2→A3→B1，AB 为可选联合阶段。A3 先让 A 的实际输出接受 L_out，再以冻结基础的方式训练 B。

离线 teacher 特征提取及在线 L_out 教师前向／反向均固定使用 vjepa2-312 环境，其余预处理、训练主进程与推理使用 moviestory，不允许环境覆盖或回退。在线教师由每个训练 rank 启动独立子进程和独立 FSDP 通信组，通过私有管道回传特征与视频输入梯度；VAE 解码及其反向仍在 moviestory。环境切分不会截断 L_out 梯度，但会增加 CPU 传输及 CUDA 上下文开销，训练主进程的 PyTorch 显存统计不包含教师子进程。详见 README 的环境约束。本实现不安装依赖、不下载权重。教师仅从以下本地文件加载，文件由用户准备：

~~~text
/home/liuzhirui/model/vjepa2/checkpoint/vjepa2_1_vitG_384.pt
~~~

新增代码、文档、缓存、日志、checkpoint、评价和推理结果均位于 v4。不增加哈希／SHA、smoke test、异常吞噬、坏样本替换、自动降配置、重试或自动恢复。显式的几何变换、训练调度、梯度裁剪和用户指定的断点恢复属于正常实现。输入／依赖问题由原调用报告。

## 3. 数据策略：原帧率、宽高比与 101 帧上限

### 3.1 实际数据与开发范围

视频目录为 /run/determined/NAS1/public/Dataset/WISA/data/videos；索引为同目录上一级的 wisa-80k.json。实际 JSON 是包含 79,480 条记录的 list，使用 video_name 和 captions。首轮配置选择前 4,000 条，不能将这一设置称为完整 WISA 实验；limit=0 才选择全部，selection_file 可显式提供原 JSON 的整数索引列表。

按 video_name 分组后用固定种子分训练／验证集，每 20 个唯一名称留出一个。前 4,000 条的名称均不同，对应 3,800 条训练、200 条验证。同名视频不会跨集；不同文件名可能属于同一场景，因此目前不宣称严格场景隔离。若研究结论需要场景泛化，需在选择清单中完成场景分组。

2026-09-12 小规模训练配置：保留已有 4,000 条缓存范围，设置 `train.sample_limit: 1000`，在过滤过短视频并选出训练集后，按 manifest 顺序固定取前 1,000 条有效训练记录；训练顺序仍由固定种子打乱。当前缓存排除 12 条过短训练视频，有效训练池为 3,788 条，验证集仍为 200 条。三套提交 YAML 使用 `PREPARE=0` 直接复用缓存。该限制只影响训练读取，设为 0 使用全部有效训练记录。按用户确认，A1 缩短为 500 个优化器步，A2／A3／B1／AB 各 250 步；默认仍从 A1 开始。global batch=8 时 A1 消费 4000 个样本视图，约遍历这 1000 条记录 4 次。

不将物理标注中的估计量当成精确监督，也不把现象类别当成已验证标签。抽查到的描述包含静态风景、烹饪和多米诺布局等，说明前 4,000 条本身不是经过挑选的接触事件训练集。

### 3.2 连续与间隔取帧的取舍

**当前主线：Wan 输入连续取帧，保留实际时间戳；优先使用覆盖事件的连续窗口。** 保持原帧率是当前用户约束，不能在仍标称原帧率的情况下悄悄间隔抽帧。

以 25 fps 为例，101 个连续帧的首尾相隔 100/25=4 秒；每隔 2 帧取一帧则相隔 8 秒，有效采样率为 12.5 fps。后者若仍以 25 fps 播放就加速两倍。间隔采样可以保留较长前因后果，却损失接触附近的时间细节；固定 101 帧、保留原 fps、覆盖任意完整长视频不能同时成立。

前 4,000 条中 3,800 条具有时长／fps 元字段：视频时长中位数 7.165 秒，fps 中位数 29.97；3,159 条长于其 101 帧窗口，约 83%；692 条 fps≥50。这个统计仅来自 JSON，不能当成逐视频解码验证，更不能据此判断事件是否被截断。结果存于 [采样元数据记录](evaluation/results/wisa_sampling_metadata.json)。

因此：

1. 接触、碰撞、快速响应任务，优先选覆盖前因、交互与结果的连续窗口，并使用窗口对应的描述。
2. 若直接沿用整视频 caption 且没有窗口标注，居中连续截取存在明显弱标注问题。长事件采用间隔取帧可能更合适，但那需要明确改变有效 fps，作为另一套数据视图和独立实验；当前实现未擅自切换。
3. 不能把“随机或居中连续窗口”自动称为“完整事件窗口”，也不自动编造 caption 或定位交互点。

V-JEPA 官方数据接口支持 frame_step、fps 或 duration，连续输入并非教师的唯一合法方式；这不能替代我们自己的任务对照。[官方数据采样实现](https://github.com/facebookresearch/vjepa2/blob/main/src/datasets/video_dataset.py)

### 3.3 确切取窗与分辨率规则

设可用源帧数为 N，上限 M=101，取 F=1+4×floor((min(N,M)-1)/4)。默认起点为 floor((N−F)/2)，随后取 F 个连续源帧；显式窗口从 start_frame 开始。帧数向下满足 Wan 的 4n+1，不重复首尾帧凑长。生成训练窗口需要至少 5 帧。

从解码器读取帧时间戳，减去第一帧时间作为相对秒坐标，并保存原绝对起点及源帧号。数据不统一转换为 24／25 fps。对于可变帧率源，训练保留实际非均匀时间；当前 MP4 推理出口使用指定的恒定输出 fps，不宣称复现任意可变帧率编码。

分辨率同时限制为：长边≤512、画布面积≤147,456、画布两边为 32 的倍数。枚举这些画布，选择保留内容缩放比例最高、同等缩放时面积最小的画布。源内容等比缩小、不放大、不裁掉边缘；居中补黑满足网格要求，整数像素取整可能造成不足一个像素的比例误差。

首条视频实读为 1920×1080、25 fps、250 帧；最终取源帧 74…174，F=101，画布为 512×288，首尾相隔 4 秒。该几何预算最大产生 26×144=3,744 个 Wan hidden token。教师再将同一画布等比缩放／补黑到 384×384。

### 3.4 窗口标注与缓存

clip_annotations 可指向 JSON 列表：

~~~json
[
  {
    "index": 125,
    "start_frame": 30,
    "frames": 101,
    "caption": "填写实际核对过的该窗口描述"
  }
]
~~~

index 是原 WISA JSON 的零基索引。提供标注的记录记为 caption_scope=window；其余使用原 captions 并明确记为 video。示例不是实际标注。帧长度仍受上限和 4n+1 规则限制，描述应对应最终取窗。

先固定样本／几何，再依次进行 VAE、T5、teacher 三个独立编码 pass，最后合并 manifest。这样正式训练不常驻 T5，预编码也不同时驻留三套编码器。每个 GPU 处理明确索引分片；不自动跳过已有文件或重试失败样本。

每条缓存包含 clean latent、独立首帧 latent、文本 token、GT 教师特征、有效内容权重、真实时间、源帧号、教师抽帧号、缩放／补黑和描述作用范围。空文本 token 单独缓存。改变数据选择、时间窗口、caption、分辨率、教师视图或权重后，应使用新缓存目录重新编码；不进行隐藏的缓存兼容性推断。

16 帧教师 BF16 目标为 4,608×1,664，单样本约 14.625 MiB；4,000 条仅此项约 57.1 GiB，全量约 1.11 TiB，另加 latent、文本和文件开销。

## 4. 原生教师空间与坐标接口

教师使用本地 V-JEPA 2.1 的 vit_gigantic_xformers，48 层、1664 通道、26 个注意力头。显式构造编码器，从 pt 的 target_encoder 加载，使用第 47 层后的原生最终归一化输出；不拼接四个层级特征，不加载 predictor，不调用自动下载 hub。官方模型清单将 ViT-G/16 对应到 384 分辨率。[官方模型说明](https://github.com/facebookresearch/vjepa2#models)

教师在当前 Wan 窗口内均匀选择最多 16 个不同帧。少于 16 帧时使用不超过实际长度的最大偶数，避免重复教师时间坐标；常规 WISA 窗口使用 16 帧。tubelet=2、patch=16，所以常规原生 P 网格为 8×24×24，形状为 [1,4608,1664]。GT 目标存 BF16，学生持久 P 存 FP32，单个 P 约 29.25 MiB。

输入视频转换为 RGB、[-1,1]；教师取帧后进行相同的 384 方形 letterbox，再转 [0,1]，按 mean=(0.485,0.456,0.406)、std=(0.229,0.224,0.225) 归一化。GT 和预测侧共用 VideoTeacher.forward。

以 F=101、H=288、W=512 为例：

| 张量 | 形状 |
|---|---|
| 视频 | [1,3,101,288,512] |
| Wan latent | [1,48,26,18,32] |
| 首帧 latent | [1,48,1,18,32] |
| Wan hidden | [1,3744,3072]，网格 26×9×16 |
| 教师／P | [1,4608,1664]，网格 8×24×24 |
| 文本 | [1,L,4096]，L≤512 |

latent 时间锚点使用 times[::4]，教师时间锚点为每个 tubelet 两帧时间的均值。latent／hidden 空间锚点分别为 16／32 像素网格中心。当前 `fusion: cross_attention` 不对 P/H 做时间或空间插值；两种序列分别保留原 token 数，以各自真实时间和同一个教师 letterbox 坐标系生成位置编码。原三线性接口只用于旧 `fusion: interpolate` 检查点及旧 latent 初始化。没有通道池化或可学习 GT 投影；上述锚点不冒充精确神经网络感受野中心。

teacher padding 权重等于每个 16×16 patch 被真实源内容覆盖的面积比例，纯补黑为零，边界 patch 部分计权。场景本身的静态背景完整计权；不凭运动量推断语义重要性。教师注意力仍看完整视图，补黑对上下文的影响并没有被这项权重彻底消除。

位置编码采用时间 512、y 576、x 576 维固定正余弦；时间按 seconds_scale=1.0 的固定秒尺度编码，空间按教师网格编码。教师自身 RoPE 使用帧／patch 索引，Wan 也没有因此自动学到精确速度单位；新增秒坐标提供条件，不能证明绝对动力学已校准。

## 5. Corrector 与原生 Wan 的执行关系

### 5.1 初始化、更新与写入

当前新训练设置 `corrector.initialization: image_text_gt`。P₀ 训练以 75% 概率读取文字、独立首帧和当前 GT 片段的干净 VAE latent，以 25% 概率去掉 GT 条件，所有情况使用同一个初始化器、每个样本只计算一次 P₀。验证和推理只给文字、首帧及请求的时空规格，使用已训练的无 GT 路径。训练 JEPA 目标 T 始终只进入损失，不能拿其特征直接替换 P。设计、可选暖起和验证边界见 [GT 初始化专项说明](evaluation/GT_CONDITION_PRIOR.md)。

条件先验 `ConditionPrior` 的计算如下：

~~~text
有效 UMT5 tokens [1,L,4096] → prior.text(4096→1664) → LN → 1664→512
独立首帧 VAE [1,48,1,h,w] → [1,h*w,48] → LN → 48→512＋图像位置
可选干净 GT [1,48,T,h,w] → 保留 T，空间池化最多 8×8 → LN → 48→512＋时空位置
可用条件序列加入各自类型编码后拼接，作为所有查询共同的 Key/Value
可训练公共 query＋整段时空位置投影 → [1,N_P,512]
  → 2 层全局 self-attention／条件 cross-attention／FFN（8 头）
  → LN → 512→1664→GELU→1664
  → 完整 P₀ [1,N_P,1664]，持久状态 FP32
~~~

首帧图像位置先映射到同一个教师 letterbox 坐标系。所有时间段的查询都能读取全部文本、全部首帧 tokens，提供 GT 时还能读取全部 GT 池化 tokens；没有把首帧复制为 P 的前几个槽，也没有为未来 P 槽采样视频噪声。可训练 query 是保存于 checkpoint 的模型参数，forward 不采样随机 query。512 维是初始化器内部计算宽度；输出使用含 1664 维非线性的原生宽度头，不把输出强制限制在固定的 513 维线性子空间。后续各 block 的 StateCore／持久 P／更新头仍为完整 1664 维。

确定性推理下，同一文本、首帧和视图规格得到同一 P₀，与 Wan 噪声种子及去噪 sigma 无关；后续 P 可以通过 H 适应不同生成轨迹。text dropout 后初始化器和 corrector 同时读取空文本；CFG 的正向／负向分支各用自己的文本初始化并接续 P。教师 T 始终只作为训练目标。覆盖整段的条件预测不等于已准确知道真实未来，所有位置都具有条件信息也不等于所有位置都已达到可靠物理精度。

checkpoint 保存初始化方式、fusion、parameter_sharing 和显式 a_blocks。当前 per_block 用 ModuleDict 注册 A.5、A.10、A.15、A.20、A.25、A.30，各项包括 core 与 site；B_core、B 和 prior 也独立注册。缺少 parameter_sharing 的旧配置保持 shared，历史 RESUME／推理仍能精确恢复；若要改为独立参数须用当前配置新训或 A／AB 的 INIT_FROM。迁移将 shared 核心和 A 适配器数值复制到六套独立参数，B_core 和 prior.text 也复制兼容来源；参数对象、存储、梯度和优化器状态不共享。仅拆分参数时保留全部 writer 数值，优化器重新创建。缺少 initialization 时仍恢复 `latent`，缺少 fusion 时恢复 `interpolate`，缺少 a_every 时恢复原 block_a／block_b；RESUME／推理不改变保存的架构。INIT_FROM 将加法旧权重迁入交叉注意力时，复用兼容的核心、条件投影和适配参数，新建两路注意力和读取门，并将 A/B writer 与 B.b 重置为零；旧 writer 的输入语义已改变，不能直接套用。旧 latent 初始化迁入 image_text_gt 时替换初始化器；旧 image_text 迁入 image_text_gt 只新增 GT 输入层并保留原先验与 writer。仅允许 A／AB 阶段进行新增可训练模块的迁移，不能在 B1 冻结未训练的新网络。同架构阶段切换严格载入全部权重，不重置 writer。原有数据缓存可复用。

每个位置执行：

~~~text
U_i = Read_i(LN(H_i))                         # [B,N_H,1664]，不插值
C_i = sigma_embedding_i + site_embedding_i + depth_embedding_i
R_r = ReadAttention_i(Q=LN(P_r)+E_P+C_i,
                    K=LN(U_i)+E_H, V=LN(U_i)) # [B,N_P,1664]
g_read_r = sigmoid(ReadGate_i(LN_i(P_r)))
Z_r = P_r + g_read_r * R_r + E_P + C_i
Y_r = StateCore_i(Z_r, projected_text_i)
delta_r = DeltaHead_i(Y_r)
G_r = sigmoid(StateGate_i(Y_r))
P_(r+1) = P_r + eta_i(sigma) * G_r * delta_r

S_i = WriteAttention_i(Q=LN(U_i)+E_H+C_i,
                     K=LN(P_final_valid)+E_P_valid,
                     V=LN(P_final_valid))    # [B,N_H,1664]
Q_i = LN_write_i(S_i)
delta_H_i = gamma_i(sigma) * sigmoid(WriteGate_i(Q_i)) * Writer_i(Q_i)
H_next = H_i + delta_H_i
~~~

这里的两路注意力是独立权重的 1664 维、26 头全局非因果 cross-attention，归各位置的 corrector 独占；不同 A 位置及 A/B 之间均无参数共享。同一位置的内部轮次、不同去噪 step 复用自己的网络。训练 B1 时六套 A 和先验冻结，完整 B（含其核心和注意力）训练。位置与 sigma／类型／深度只用于 Q/K 的寻址，V 来自内容。ReadGate 的线性权重初始为零、bias=-2，起始门约 0.119，避免未训练的读取立即盖过 P；它不表示可信度概率。写回没有另加 U_i 的 value/residual 通路，H 负责查询更新后的 P，真正的注入值由 P 提供。

读注意力允许 N_P≠N_H，输出长度由 P 查询决定；写注意力输出长度由 H 查询决定。因此两方向均不需要时空插值，也不拼接 P/H 再拆分。P 仍与固定教师网格直接对齐，教师抽帧和坐标编码仍然需要。为避免 H 直接读取未监督的纯补黑 token，写注意力按几何剔除教师外层 letterbox 的全黑 patch，部分覆盖 patch 保留；常见 512×288、384 教师画布下 K/V 为 2688 个有效位置，P 仍完整保留 4608 个 token。该筛选不依赖 GT 内容，也不声称消除了补黑通过自注意力产生的全部间接影响。

选择依据：旧插值相加具有固定局部对应、计算省、优化简单的优点，但要求两套不同感受野的网格进行逐点融合；新方案让 P 选择需要的观察、让 H 选择需要的先验，更符合不同长度的语义状态与生成特征之间的交互。注意力有额外开销，也可能学到过度平均或错误对应，不能保证物理收益。残差加法仍用于保留状态和注入更新；取消的是固定插值后的直接 P+H 融合，而非取消所有加法。[Perceiver IO 的查询式读写](https://arxiv.org/abs/2107.14795)提供结构参考，并不验证本模型的生成效果。

由 `parameter_sharing: per_block`、`a_blocks: [5,10,15,20,25,30]` 和一致的 `a_every: 5` 定义六套独立模块，调用顺序为 A@5→A@10→A@15→A@20→A@25→A@30，每次更新的 P 立即传入下一调用。各位置的 Read、Writer、门、核心、条件投影和归一化均独立。固定深度正余弦编码仍保留，但参数隔离由各自的 ModuleDict 项保证。一次前向中不执行 optimizer.step；梯度分别累积到各自参数，累积结束后一个优化器统一更新。模型创建后不在 forward 临时创建模块；未注册、缺失或超出实际 Wan 深度的 block 直接报错。日志／损失／归因使用上述唯一调用名称。B1／AB 另外保留 B@18，仅在 sigma<0.65 激活，默认 A1 不使用 B。

每个 StateCore 保留两个不同参数的 pre-LN Transformer block，每个含 self-attention、文本 cross-attention 和 1664→6656→1664 GELU MLP；两个 block 组成的核心只在所属位置的内部轮次和不同去噪 step 间复用；不同位置拥有独立的两个 block。每次位置的 H 通道投影 U_i 只计算一次；A2 等多轮阶段每轮使用更新后的 P 重新做读注意力，写注意力只在该位置最终提交后执行一次。内部迭代不 detach；L_struct 与 writer 消费同一个提交 P，下一正常去噪步继续使用最终 P。

A/B writer 都从零矩阵开始。A 状态强度默认为 0.2，写入强度 0.1；B 状态再乘 tanh(b_B)，b_B=0。B 的启用幅度 q=clip((0.65−sigma)/0.15,0,1)，状态和写入都乘 q；sigma≥0.65 时整个 B 旁路。低噪声处两者再乘 0.25+0.75×clip(sigma/0.15,0,1)，避免最后阶段仍维持最大更新幅度。新配置的写回还乘 `early=0.1+0.9×clip((1−sigma)/0.1,0,1)`：sigma=1 时仅保留 10% 的基础写入，sigma≤0.9 时恢复完整强度。该 early 只作用于 ΔH，P 状态仍可更新；设 early_write_width=0 可消融。它不是 ΔH/H 的范数上界，零 writer 也只保护训练初始化，不能保证训练后的早期推理无害。这些是待校准超参数，不是正确性概率。

### 5.2 Wan 原生路径

ProcessWan 按原有 block 顺序执行，在指定位置调用 corrector，最后到原输出头。默认每次 Wan 前向包含六次 A 调用，参数不复制；A1 每次调用内部一轮更新。保留首帧 latent 槽固定、对应 token 时间为零、其他 token 时间为 sigma×1000，文本补齐至 512 和原始 unpatchify。

Wan 冻结参数，但 A／B 后缀必须保留输入梯度。没有把整个模型包在 no_grad 中；只有预编码、验证和合法上一视图的 P 暖起使用 no_grad。在线 L_out 的解码／教师同样冻结权重但保留输入梯度。

正式两路 CFG 的 cond 与 uncond 各维护自己的 P。K 个去噪步对应 2K 次 Wan 前向、K 次 scheduler 更新，内部多轮 cell 不增加 Wan 前向；当前步骤不回到早层，也不重跑后缀。离线归因入口的额外后缀调用单独计为评价成本。

### 5.3 B 的基础保持条件

B1 冻结初始化器与全部六套 A，并使用已验收 A3 权重。B_core 和 B 适配器均可训练；A 阶段尚未训练 B 的核心，因此不能只训练 B reader／writer 而冻结随机 B_core。在相同输入、随机数、scheduler、数值精度和基础权重下，sigma≥0.65 区间的计算前缀与 A3 相同。B 初始状态／写入都为零时，低噪声位置也为恒等映射。

这只能说明计算关系，不说明基础已足够准确；B 启用后可改变 P 和视频，后续 A 也会读取变化后的 P。不能据此保证中后期不破坏正确关系。AB 会改变初始化器与六套 A 基础，必须重新评价，不能继承 B1 的冻结前缀主张。

## 6. 损失、采样分布与梯度边界

### 6.1 FM

同一 GT latent z0 与高斯噪声 epsilon 构成 z_sigma=(1−sigma)z0+sigma×epsilon，随后将首帧槽替换为合法首帧 latent。预测向量场 v 与 epsilon−z0 仅在后续 latent 槽计算 FP32 MSE。端点为 z_hat0=z_sigma−sigma×v，并恢复合法首帧；不贴回未来 GT。

### 6.2 L_struct

每个启用位置的实际 P_final 直接对同一个 GT 原生教师特征做 FP32 MSE。先按真实内容权重归一化，再在 A、B 各自类型内对调用位置取均值，最后平均活动类型；A、B 同时启用时仍各占 1/2，避免六次 A 稀释 B 的系数。B1 的 A 权重冻结，但 B 之后的 A 仍能把梯度传给上游 B。

最终结构系数为 0.1×min(1,(step+1)/200)×clip((1−sigma)/0.2,0,1)。固定 sigma 衰减放在状态平均之后，避免被重新归一化抵消。P_before 误差、改进量、余弦、同视频常数特征基线只是诊断，不额外进入目标。

### 6.2.1 条件先验 L_prior 与初始梯度

对 P₀ 与固定 T 按每个教师时间槽分别做真实内容面积加权的空间平均，得到 [1,T_P,1664]；保持时间次序，以每个时间槽的有效内容面积加权计算 MSE。没有学习 GT 侧映射或训练读出 R。这样优先蒸馏整体及粗时序语义，不要求首帧／文本精确指定每个未来 patch。空间池化不能单独保证每个位置的细节信息，稠密细节仍由更新态 L_struct 与生成损失共同约束。

默认系数为 `0.02×min(1,(step+1)/200)`，不乘 sigma 衰减，因为该 P₀ 本身不依赖 sigma；设 `loss.prior_weight: 0` 可检验只靠后续损失训练的版本。日志新增 loss/prior、loss/weighted_prior、prior/active。

无额外 L_prior 时，非暖起视图的 L_struct 仍经 P_after→P₀ 训练初始化器；writer 学开后 FM／L_out 也可沿真实写回回传。初始零 writer 会使该时刻的纯 FM 初始化梯度为零，但不阻断结构损失。L_prior 的目的不是补一个不存在的基本梯度路径，而是减少初始化器只依赖后续 H 完成任务的可能；是否提高生成效果必须消融验证。

### 6.3 L_out

使用当前模型真实端点，经可微 Wan VAE decode 和同一冻结 VideoTeacher，再对 GT 特征计算按内容权重归一化的 token 余弦距离。预测路径不转 uint8、不落盘、不 detach；仅 GT 编码缓存。

A3／B1／AB 的 out_weight=0.1，每 4 个 optimizer step 执行一次；该步全部 microbatch／rank 从 sigma∈[0.05,0.4] 采样，并同时计算 FM 和 L_struct。其他 step 的 L_out 为未执行，日志明确 output/active=0；不能把该零值当作教师误差已经为零。

这里改变了训练 sigma 混合分布：四分之一的 step 来自输出可读区间，其余来自阶段主区间。没有乘 4 宣称无偏估计全 sigma 的输出目标。L_out 只约束合法 GT 加噪视图的端点，不将自由生成的合法不同未来强拉向单一 GT。

### 6.4 GT 条件选择、可选暖起与同步

默认 `gt_condition_dropout: 0.25`、`state_warmup_every: 0`。每个样本生成一次 P₀，随后一次 Wan 前向包含六次独立 A 更新；换视频重新初始化 P。GT／无 GT 的选择使用共同 step 种子，同一步全部 rank 和累积样本一致；文本有 10% 概率使用缓存空文本，首帧保留，各 rank 的样本和 epsilon 独立。

非零 state_warmup_every 是显式可选的同视频双加噪视图对照：由当前 GT／无 GT 条件生成一次带梯度 P₀，较高 sigma 的 no_grad Wan 从其 detach 副本开始；所得 P 再 detach 后交给较低 sigma 的正式视图。原 P₀ 接受 L_prior，不重复初始化。第二个视频输入仍由同一 GT 和 epsilon 标准加噪构造，不来自第一个预测的 scheduler 更新，因此不是实际采样 rollout，也没有长程收益保证。GT 内容初始化与跨步状态训练的作用不同，不能声称前者已完全替代后者。

无 GT step 仅排除 GT 专用输入层的同步／裁剪，参数 grad=None，AdamW 不更新这些参数；普通初始化层与 A 正常训练。可选暖起且关闭 L_prior 时，初始化组不参与同步／更新。AB 如果所有 microbatch 的 B 都关闭，则排除 B 组。B1 主 sigma 低于 0.65；A／AB 常规 sigma∈[0.02,0.999]。条件选择和 sigma 调度跨 rank 一致，恢复后可复现。

总损失仍为 weighted_fm+weighted_struct+weighted_prior+weighted_out。默认 A1 每样本六次 P 更新；主动开启暖起时为十二次。推理 50 步中每个 CFG 分支有三百次更新，cond／uncond 分开保存 P，同一 block 复用自己的权重；单步训练与长程采样的分布差异仍需无 GT 完整生成检查。

## 7. 阶段、硬件与显存实现

| 阶段 | 可训练部分 | cell 轮数 | 损失 | 默认步数／学习率 |
|---|---|---:|---|---|
| A1 | 独立初始化器＋六套 A | 1 | FM＋struct＋prior | 500／1e-4 |
| A2 | 独立初始化器＋六套 A | 2 | FM＋struct＋prior | 250／5e-5 |
| A3 | 独立初始化器＋六套 A | 2 | 再加 out | 250／2e-5 |
| B1 | 完整独立 B（核心＋适配器） | 2 | FM＋struct＋out，prior 仅监测冻结先验 | 250／5e-5 |
| AB，可选 | 全部新增模块 | 2 | FM＋struct＋prior＋out | 250／1e-5 |

当前参数量逐项枚举为：独立初始化组（含其文本投影）20,610,880；每个 A 完整 corrector 136,224,515，共六套；B 完整 corrector 136,224,516。A 阶段可训练合计 837,957,970；B1 可训练 136,224,516；AB／全部模型合计 974,182,486。每个核心／条件／双向注意力部分 125,988,098，每个 A 的适配器 10,236,417。所有组无重复 Parameter 或共享存储，代码按块名注册和保存。生成阶段无需教师。

训练 microbatch 固定为单视频。48G／80G／96G 三类入口均由提交 YAML 的 slots_per_trial 决定卡数，预处理与训练进程数跟随平台实际分配，不执行启动预检。目标 global batch 默认为 8，梯度累积取 ceil(8 / 实际卡数)：1／2／4／8 卡分别累积 8／4／2／1 次；不能整除时实际 batch 向上取整。按 (F,H,W) 组织确定性形状桶；不丢弃或复制样本凑齐整桶。跨桶边界允许各 rank 形状不同，参数 collective 次序由相同前向调度保持一致。

具体显存控制：

- Wan 每个原生 block 单独 FULL_SHARD，激活 checkpoint 放在 FSDP 内部；不绕过根 FSDP forward 调子模块。教师输出阶段的 48 个 block 同样逐块分片和重计算。
- Wan 大部分冻结权重 BF16；原生时间 embedding／调制和输出头从原始文件恢复 FP32。其 affine norm3 的原生实现处理 FP32 输入，保留 FP32 并作为极小复制模块排除在 BF16 flat parameter 之外。
- corrector 训练参数、优化器状态和持久 P 为 FP32；线性与 attention 用 BF16 autocast。训练上下文显式设置 `cache_enabled=False`，使 no_grad 暖起与带梯度前向不复用 AMP 权重缓存；非重入 checkpoint 捕获该设置并用于反向重计算。该设置修复实验 61001 的首步 `CheckpointError`，同时覆盖 48G／80G／96G 共用训练入口。各 block 的 StateCore、读取 attention／gate 和写回 attention 继续使用非重入 checkpoint。SDPA 不返回或保存用于日志的稠密注意力权重；实际后端由 PyTorch 和设备决定，CPU 检查不能证明 GPU 已使用 FlashAttention。
- VAE 解码按因果 latent chunk 重计算，cache 显式作为输入／输出，用局部列表承载调用内修改；不 detach 跨 chunk 缓存，不让反向重算修改全局缓存。
- A1／A2 正式训练不加载在线教师和 VAE；A3 以后稀疏执行真实输出路径。预编码的 VAE／T5／teacher 分三个进程阶段释放。
- 推理文本编码结束释放 T5，采样时 VAE 放 CPU，结束采样后释放 Wan／corrector，再把 VAE 放回 GPU 解码。

corrector 未做 FSDP 分片，在每个 rank 保留完整 FP32 参数。全部权重约 3.63 GiB；计入活动参数的梯度和两份 Adam 状态，A／B／AB 的每卡静态预算约 12.99／5.15／14.52 GiB。这不包括冻结 Wan、激活、重计算临时张量、通信缓冲、VAE／教师和分配器，远不是训练峰值；不能把多卡数量直接除到该预算上。原生 P 有 4,608 个 token，当前 Wan 有 3,744 个 token；新增每轮一次 P←H、每位置一次 H←P 注意力，其注意力乘积成本随 N_P×N_H 增长。A1 每次 Wan 前向有六次读和六次写注意力，A2 有十二次读和六次写；不增加完整 Wan 前向数，但增加计算／激活／重计算成本。尚未证明原硬件预算必定足够。在线教师输入反传、VAE 缓存、通信和分配器也有额外成本。

分辨率／帧数上限、分片和分阶段加载提供明确预算控制，但本轮未运行本地 GPU 训练，实际峰值与吞吐均未验证；当前名为 4x48g 的提交 YAML 实际指向 ada-24g／2 卡，4x80g 为 amp-80g／4 卡，4x96g 已按单卡测试改为 blk-96g／1 卡，容量以实际分配为准；不保证零 OOM。当前不自动降帧／降画幅或捕获 OOM 继续训练。

## 8. 每步监控与问题定位

每个 rank 的每个 microbatch 写 JSONL／TXT，chief 每个 optimizer step 打印全局 loss 分项与训练摘要，并把全部指标写入 steps.jsonl／steps.txt；所有日志位于 train/train_log/run_name/session_id。Determined 平台采集标准输出，训练进程不加载其 SDK，不上报 Core 指标曲线。TensorBoard／TensorFlow 集成及 profiling 配置已删除。W&B 默认关闭，仅显式开启后由 rank 0 导入本地凭证并上报。凭证文件不进入日志配置、提交上下文或 checkpoint 源码快照。完整记录格式和开关见 README 第 4 节。

| 记录 | 内容与用途 |
|---|---|
| 损失 | FM／struct／prior／out 的原始值、加权值、总损失、sigma 权重、warmup、输出执行开关 |
| 每个位置 | P_before／after 误差与余弦、struct_gain、P RMS、候选／有效增量 RMS、写入 RMS、delta_H/H |
| gate | 状态／写入 gate 的均值、低于 0.05／高于 0.95 的比例、B 的 q 与 tanh(b) |
| 梯度／优化 | initialization、A@5／10／15／20／25／30、B 各活动组 norm／RMS、权重 RMS、裁剪前总 norm、裁剪系数、LR；例如 grad/A@10_norm |
| 数据／状态 | F、H、W、原 fps、实际秒长、teacher 帧数、窗口 caption 标记、GT 条件启用／可选暖起开关／previous sigma |
| 成本 | 数据、前向、反向、更新、总 step 秒数，吞吐，逻辑 Wan 前向数；不把反向重计算藏成免费成本 |
| 显存 | 每个 rank 当前 allocated／reserved 及本 step peak，两类数值均以 GiB 记录 |

出现低 struct 但完整生成无改善，先看 writer 归因；teacher 常数基线已很低，需警惕静态内容占优；有效 P 增量或相对写入持续放大，检查状态累积；out 执行步梯度／时间突增，检查真实解码和教师路径。日志不自动判定成功，不跳过异常或删掉失败样本。

每 250 步在固定留出样本、固定噪声种子、sigma=0.1/0.35/0.6/0.85/0.98 上验证；默认每 rank 一个样本，所有 rank 执行相同数量前向。out 阶段在可读桶也计算真实 out。validation_loss 是这些桶的平均 FM，供曲线观察，不是物理正确率，也不替代完整验证集评价。

## 9. Checkpoint、恢复与运行入口

每 250 步和阶段结束保存一次，目录为 v4/checkpoints/run_name/checkpoint-0000250 等，最终为 checkpoint-final。每次启动（含 INIT_FROM、RESUME）都在运行名前缀后追加 rank 0 广播的 UTC 时间戳与唯一标识，例如 wisa_native_p_A1_4x96g_20260912T150000Z-12345678；run_name_base 保存原前缀。续训加载原状态后写入新时间戳目录，保留 resume_from/source_run_name 来源信息。同名 checkpoint 目录存在时，在任何写入前向全部 rank 报错，禁止覆盖已有或部分保存。阶段衔接未指定 INIT_FROM 时，从配置的 checkpoint_root 选同硬件前一阶段最近完成的 checkpoint-final，兼容旧目录；推理可在未指定 CHECKPOINT 时显式设置 CHECKPOINT_RUN 开启相同查找。每个目录包含：

- corrector.pt：全部新增权重，包括当前冻结的六套 A／prior／B_core／B，便于下一阶段和完整推理。
- training.pt：优化器、scheduler、下一 step、全局已消费数据游标、world_size。
- rng_rankN.pt：各 rank Python、NumPy、Torch CPU 与当前 CUDA RNG。
- config.yaml、data_manifest.json、metrics.json、runtime.json：解析后的完整配置、源视图及分集、最后训练／验证指标和运行数值精度。
- source/：v4 Python、shell、YAML、根文档与 README 快照。外部冻结大模型以明确本地路径引用，不重复塞入每个 checkpoint。

latest.json 在各 rank 保存结束后更新为普通路径指针。不自动选择最好分数、不清除历史 checkpoint。

RESUME 与 INIT_FROM 互斥。旧 shared checkpoint 必须通过 A／AB 的 INIT_FROM 拆分后才成为独立模型，不能把恢复旧架构描述成独立参数训练。RESUME 指向同一实验 checkpoint，恢复优化器、LR 和游标，梯度累积随实际卡数重新计算。同卡数恢复各 rank 的 RNG；改变卡数时按恢复步数和新 rank 重新设种子，不保证与原卡数相同的随机序列。INIT_FROM 用于新阶段，只载入 corrector 权重，重新创建优化器。数据游标记录真正消费的样本，不跟随 DataLoader 预取。精确续训仍要求同样 world size、batch、输入资产和配置。

训练提供 48G、80G、96G 三组 shell／Determined YAML，沿用 MovieStory 的镜像及挂载形式，资源池与卡数以 YAML 的实际字段为准（当前为 ada-24g／2、amp-80g／4、blk-96g／1）。现有文件名和 checkpoint 路径中的 4x 作为固定入口标签保留，卡数由 slots_per_trial 决定；96G 实验显示名已同步为 1x96g，不需要重命名文件或入口。

当前三套 YAML 默认 PREPARE=0、PHASE=A1，直接复用缓存；首次构建缓存才设 PREPARE=1。后续阶段设置 PHASE=A2/A3/B1，并指定已验收前阶段 checkpoint。启动详见 README。真实 checkpoint 由上述训练代码直接写共享目录；YAML 中的 determined_checkpoints 存储声明不代表已经使用 Core checkpoint 注册接口。

## 10. 推理与独立效果评价

正式推理默认 Euler、50 步、shift=5、CFG=5，另提供 Wan 原生 UniPC／DPM++ 调度器选项。比较必须统一 solver、步数、seed、首帧、prompt、fps 和几何。当前尚未执行任何实际 GPU solver 对照。

推理首帧按同一宽高比策略处理。请求帧数受训练配置 max_frames 限制，并向下取 4n+1；默认 101。单张图没有原 fps，必须明确输入输出 fps；脚本示例 24 只是请求值。WISA 评价导出工具携带原 fps 和实际帧数。duration 若显式指定，会按 (F−1)/duration 确定播放 fps。

variants 包含原 Wan 旁路、A-only、full。cond／uncond 不共享 P；reset-state 和 writer-off 只用于消融。日志记录每步 q／gate／写入等，以及总前向／scheduler 次数。没有在线教师、评分挑选、重启或额外候选。

### 10.1 合法噪声视图的逐位置归因

attribute_correctors.py 复制同一位置前的 H／P，比较：

~~~text
on         : 后缀(H + delta_H, P_after)
writer_off : 后缀(H,           P_after)
off        : 后缀(H,           P_before)
~~~

三种分支使用相同后续策略；可分别让后续 corrector 全开／全关，避免两边条件不同。输出 FM 与可读范围内可选 L_out 的 gain=loss_without−loss_with，并报告 on 分支后缀重放误差。这是离线研发成本，不能据此改变正式每步前向数；合法端点 gain 也不是完整采样成功率。

### 10.2 完整采样与人工评价

export_cases.py 从最终缓存清单的留出视频导出实际窗口首帧、prompt、fps、F 和空评分表。generate_cases.py 对所有指定 case×seed×variant 逐个生成，不打分、不选择结果。默认 8 个 case、2 个 seed 仅用于人工观察，样本量不足以支持强统计结论；正式样本量和规则应在看结果之前确定。

评分至少分开：过程关系是否完整正确、画质；notes 记录角色、数量、接触、前后因果及失败原因。同一输入多个 seed 按 case 聚合，不把同一场景的多个 seed 当独立场景。summarize_ratings.py 报告配对成功率增量、原正确样本破坏、画质变化和 case bootstrap 区间；另报告 case 层面的 Wilson 区间。

例如 50 个独立可破坏 case 中观察到零破坏，95% Wilson 上界仍约 7.13%，不能把 bootstrap 的零宽区间说成总体零风险。对基础成功率、最大允许破坏、净收益和画质容忍度，需要事先按研究目标设定阈值；本文不虚构已经达到的 90%／95% 指标。

A3 对原 Wan 验证基础；B1 同时对其冻结来源 A3 做净收益／保持评价。B1 checkpoint 内的 A-only 对照可用于此目的；AB 内关闭 B 的 A 已共同训练过，不能替代原 A3 checkpoint。基础不过关应先修数据、教师可见性和实际写入，不用新增 B 掩盖问题。

### 10.3 创新性应由哪些结果支持

D 已将原生视频表征蒸馏与双流物理 latent 等相邻工作列为比较对象。使用 V-JEPA 或增加一个 P 本身不足以证明新颖性。当前有意义的可检验主张是：原生受监督 P 被真正写入消费；冻结可靠基础后，后层新观察带来净改善；在相同 Wan 调用数下，各位置独立 cell 的额外成本有收益。

需要分别对照 FM-only、加 struct、加 out；一次／两次 cell；持久／重置 P；A-only／冻结基础加 B／联合。再结合逐位置 writer 归因、独立物理关系和质量评价，才能区分“表征拟合更好”“额外容量更大”和“顺序校正确实有效”。当前没有据此宣称论文新颖性或效果成立。

## 11. 已执行检查与交付边界

本次按 block 拆分的最新测试与预算见 [独立参数检查说明](evaluation/INDEPENDENT_CORRECTORS.md)。下列已有 JSON 是各历史修改时的证据，不应把共享架构的参数量或单 corrector 检查当作当前六套独立模型的 GPU 结果。

实验 61001 的 AMP／checkpoint 故障及后续 22 项相关 CPU 回归见 [修复说明](evaluation/CHECKPOINT_AUTOCAST_FIX.md)。三份训练 YAML 均以 `PHASE=A1`、`TRAIN_CHECK_STEPS=0` 执行当前完整 A1：500 个优化器 step、已选 1000 条训练记录、FM＋L_struct＋L_prior；第 250／500 步验证与保存，结束保存 checkpoint-final。单卡 96G 仍按 global batch=8 累积 8 次。测试替身仅用于 evaluation 中验证控制流；正式入口加载真实 Wan 和缓存。此前 116 项检查未覆盖引发该故障的完整 AMP 组合，不能用历史通过记录代替修复后的集群实跑。

[CPU 检验记录](evaluation/results/cpu_contracts.json)：moviestory，Torch 2.8.0+cu128，23 项、零失败／错误。使用完整 1664 通道 corrector、小空间网格和 CPU 张量；数学检查不是完整视频实验。结合新增集成测试覆盖：

1. 零 B 恒等性及起步 b／writer 梯度。
2. 单次状态损失不经过本次 writer；后续位置状态损失可以训练较早位置的独立 writer，本次 writer 不属于本次 P 损失的计算路径。输出消费实际提交 P；历史共享核心的冻结梯度兼容检查另外保留。
3. 非重入 checkpoint 输出／梯度一致性。
4. 精确参数预算、暖起有／无 L_prior 时的初始化梯度、AB 高噪声 B 缺席的梯度边界。
5. CPU BF16 autocast 下 FP32 P 保留小增量。
6. 三线性映射的线性场保持与梯度质量、矩形教师映射、短窗严格递增时间坐标。
7. 原帧率连续窗口／分辨率边界、真实内容权重。
8. FM 端点恒等式和首帧梯度掩码、sigma 衰减不被状态均值抵消。
9. 形状桶全局采样顺序与断点游标。
10. 零观测破坏不能声称零总体风险的统计边界。

另有 WISA 索引／首视频解码器元数据读取，以及 Python AST、YAML、shell 语法与入口交叉检查，见 [静态检查记录](evaluation/results/static_review.json)。局部检查未加载完整 Wan／教师做前向，没有调用本地 GPU，也没有执行长时间测试；PyTorch CPU backward 出现过 CUDA 驱动枚举警告，没有 GPU 张量或 GPU 计算。

新增 [条件先验与多位置 CPU 集成检查](evaluation/test_condition_prior.py) 验证初始化对视频噪声不敏感、所有时间段读取文本和首帧、后续损失可训练初始化器、六次 A 顺序接续、逐位置 writer 关闭与精确后缀重放、同层 A/B 顺序、早期只减写入及旧权重迁移。测试使用真实 corrector 与小型冻结 Wan 替身，不代表真实 Wan 视频效果。

[真实缓存尺寸检查](evaluation/results/condition_prior_full_shape.json) 使用默认 512 维、两层条件初始化器与一条实际缓存首帧／文本，在 CPU 上得到 [1,4608,1664] FP32 P₀；重复前向误差为零，改变文本影响全部八个时间槽。该检查使用未训练的新初始化器，只证明接口、完整尺寸和条件依赖，不证明语义准确性。

[双向注意力专项检查](evaluation/test_cross_attention.py)新增11项测试，覆盖不等长无插值读写、时空寻址、补黑过滤、非因果注意力、写入 Value 来自提交 P、零 writer 起步、两轮重查询与重计算梯度、旧结构的严格恢复和迁移，以及同架构阶段切换不重置 writer。本轮合计60项 CPU 检查通过，范围见 [审查记录](evaluation/results/cross_attention_review.json)。[完整尺寸记录](evaluation/results/cross_attention_full_shape.json)在 CPU 上使用真实缓存条件／教师目标和模拟 H，验证 H=[1,3744,3072]、P=[1,4608,1664] 的前向及反向：零 writer 保持 H 完全一致，打开 writer 后先验、两路 attention 和读写投影均获得有限非零梯度。未加载真实 Wan 或验证 GPU 显存、生成效果。比较理由与完整审查见 [P/H 交互审查](../v3/analysis/20260912-D-PH双向交叉注意力与加法融合_实现审查.md)。

尚缺的实证：用户准备的正式教师 pt 实际载入、真实 VAE／教师输入梯度整链、多 GPU FSDP／NCCL 与实际显存、全部 solver 运行、训练收敛和独立完整视频收益。只有完成相应实际实验后才能提高这些结论的置信度，不能通过继续重复短时 CPU 检查代替。
