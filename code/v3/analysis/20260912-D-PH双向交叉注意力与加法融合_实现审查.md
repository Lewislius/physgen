# P/H 双向交叉注意力与加法融合：实现审查

对应 2026-09-12 的 v4。默认 A1，1000 条训练记录、500 个优化器步；Wan 第 5、10、15、20、25、30 层后各有一套独立 corrector；同一 block 跨去噪 step 复用自己的权重。本文讨论 P/H 的交互；当前 P₀ 训练已加入可选干净 GT 视频条件和 25% 无 GT 路径训练，推理只读文字／首帧，JEPA 仍只作监督。暖起默认关闭。详见 [GT 初始化说明](../../v4/evaluation/GT_CONDITION_PRIOR.md)。

## 1. 修改前是什么

旧实现先做 `U=Read(LN(H))`，再按时空坐标三线性插值到 P 网格，得到 observation，与 P、位置和条件逐元素相加。SharedCore 随后做融合序列的全局自注意力和对文本的交叉注意力。

因此旧版本虽有 attention，却没有直接的 `CrossAttention(P,H,H)`。写回同样先在 P 网格生成残差，再插值到 H 网格。

## 2. 为什么选择双向交叉注意力

| 方法 | 优点 | 局限 |
|---|---|---|
| 插值后相加 | 固定局部对应、参数和计算少、优化较简单 | 两种不同感受野的时空网格被迫逐点融合，读写缺少按内容选择的接口 |
| P 查询 H，写回仍插值 | P 可以选择观察 | 写回依旧需要 P→H 插值，不能声称完全取消时间插值 |
| **P 查询 H，H 查询更新后的 P** | 双方保持各自 token 数，分别选择观察与先验 | 新增两路注意力；可能错误匹配或过度平均，需要位置、门控与实际评价 |

本版选择第三种。P 是由条件预测并经教师监督的学生状态，需要根据本次生成的 H 更新；H 则根据当前位置的需求选择 P 中的信息。两种 Query 回答不同问题，不应只选择一个方向。

这是结构上的选择，不是已证明优于加法的实验结论。小数据时原加法方案有更强的局部归纳偏置；新注意力是否值得额外成本，要在相同训练数据和完整生成协议下对照。[Perceiver IO](https://arxiv.org/abs/2107.14795)提供以输入／输出查询连接不同长度序列的参考，不提供本任务的物理收益证据。

## 3. 当前数据流

```text
条件：文本＋首帧 → P₀ [B,4608,1664]

H [B,3744,3072] → LN_H＋Read → U [B,3744,1664]

每轮状态更新：
  R = CrossAttention(Q=LN(P)+E_P+C, K=LN(U)+E_H, V=LN(U))
      [B,4608,1664]
  g_read = sigmoid(Linear(LN(P)))             [B,4608,1]
  Z = P + g_read*R + E_P + C
  delta, g_state = 当前位置两层 StateCore_i(Z, 本位置文本投影)
  P_next = P + eta(sigma)*g_state*delta       [B,4608,1664]

当前位置提交后：
  S = CrossAttention(Q=LN(U)+E_H+C,
                     K=LN(P_next_valid)+E_P_valid,
                     V=LN(P_next_valid))     [B,3744,1664]
  S_norm = LN_write(S)
  delta_H = gamma(sigma)*sigmoid(WriteGate(S_norm))*Writer(S_norm)
                                             [B,3744,3072]
  H_next = H + delta_H
```

上图的 LN 分别属于对应模块，不共享所有归一化参数。`C` 包含 sigma、A/B 类型和 Wan 层深；`E_P/E_H` 是同一坐标系中的时空位置。两路 attention 各有独立参数，都是1664维、26头、全局非因果形式。P/H 不拼接，也没有需要拆回两条流的融合序列。

H 的通道投影 U 每个位置只计算一次；A1 内部一轮，A2 等内部两轮，每轮以更新后的 P 重新查询 U。写 attention 只在提交 P 后执行一次；它的 Value 来自 P，没有在检索结果上再添加 H 内容的残差旁路。H 作为 Query 会影响读出权重，因此也不能把写回描述成与 H 无关。

例如“球落下后反弹”：P 的某个时间位置可以从不同 H token 读取球、地面及运动相关信息；更新后，H 中不同位置再各自查询 P。注意力提供这种选择能力，是否能学到正确接触时刻和轨迹仍依赖训练，不能把 attention 权重当成已知物理关系。

## 4. 无需插值，但仍需时间和位置

读 attention 的输出长度由 P Query 决定，写 attention 的输出长度由 H Query 决定，所以当前 P/H 读写都不做时间或空间插值。

仍保留真实帧时间、教师 tubelet 时间锚点、教师抽帧、首帧／hidden 的空间位置及 letterbox 变换。位置进入 Q/K，V 使用内容。P 仍与教师的原生网格直接计算监督，交叉注意力并不取消教师对齐。

写回按输出几何剔除教师外层 letterbox 的完全补黑 patch，保留部分覆盖 patch，避免直接读取未受结构损失监督的空白位置。常见 512×288 画布对应 P=4608，写入 K/V 为2688个位置；P 本身没有压缩。该选择不使用 GT，训练推理相同；没有宣称消除了补黑经自注意力产生的全部间接影响。

## 5. 学习、参数独立与稳定性

- 初始读取门约0.119，权重可训练；不是置信度。P、R 相加是门控残差，保留原状态，替换的是旧的固定插值相加接口。
- A/B writer 仍为零初始化，初始不改变 H。L_struct 能立即训练 A 的 P 读取／更新路径；writer 可以从输出任务获得梯度，写 attention 的上游任务梯度在 writer 学开后出现。
- B.b 与 writer 起始均为零，B 对 H/P 恒等；B 专属 Read 的最初任务梯度为零，仍是有意的起步设计。
- 各位置的两路 attention、读取门、更新核心、条件投影和适配器全部独立，分别归入 A@5／10／15／20／25／30 参数组；B_core 与 B 适配器归入独立 B 组。P₀ 的文本投影也归独立初始化组。内部轮次与不同去噪 step 仅复用同位置参数；B1 冻结六套 A 与 P₀，训练完整 B。
- 保留 P 的 FP32 残差更新、原高低噪声幅度调度及既有损失，不在每五层调用后执行 optimizer.step。

训练／推理的长期状态差异仍然存在：A1 单次 Wan 前向更新六次 P，默认推理每个 CFG 分支50步累计300次。注意力本身不能消除长期漂移或保证所有写入有益，需要结合完整生成、逐位置 writer 归因和接续／重置状态的对照评价。

## 6. 参数、计算与兼容

| 参数组 | 数量 |
|---|---:|
| 条件初始化（含独立文本投影） | 20,610,880 |
| 每个 A 的核心、条件、读写注意力、读取门 | 125,988,098 |
| 每个 A 的适配器 | 10,236,417 |
| 每个完整 A，共六套 | 136,224,515 |
| 完整 B（核心＋适配器＋b） | 136,224,516 |
| A 阶段可训练合计 | 837,957,970 |
| AB／模型总参数 | 974,182,486 |

每套核心的双向 attention／读取门含22,182,785个参数，现在各位置分别拥有这些参数。corrector 未分片，A 阶段每卡参数／梯度／Adam 状态约12.99 GiB，AB约14.52 GiB，尚未包含 Wan 和激活。A1 每个 Wan 前向有六次读 attention 和六次写 attention；A2有十二次读和六次写。使用 SDPA，不导出稠密注意力矩阵；读写注意力和核心支持非重入 checkpoint。全局 attention 仍有序列长度乘积成本，不能承诺 GPU 显存或吞吐与旧版相同。[PyTorch SDPA](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html)

当前默认 `corrector.fusion: cross_attention`、`parameter_sharing: per_block` 和显式六位置 a_blocks。缺少 parameter_sharing 的旧 checkpoint 恢复为 shared；其 RESUME 继续旧实验。用 A／AB 的 INIT_FROM 才会将 shared 核心与 A 适配参数复制到各自存储，并重建优化器；仅拆分不清零 writer，不合并独立 checkpoint，也不默默改变注册 block。旧检查点缺少 fusion 时按 `interpolate` 恢复，RESUME／推理保留旧计算。通过 INIT_FROM 迁入新结构时只允许 A／AB：载入兼容权重，新注意力与读取门从头学习，A/B writer 与 B.b 重新归零；旧 latent 先验若也切换则同时替换。同架构正常阶段切换不清零。不能把加法旧权重迁入后直接在 B1 冻结随机的新 A 模块。已有 GT 缓存可直接复用。
