## 2. 想解决的核心问题

原始问题是：仅把物理规则扩写成长 prompt，往往不能让视频更符合物理规律，反而会带来状态冲突、主体漂移和动作缺失。主要原因包括：

- 一段全局长 prompt 同时描述初态、中间态和终态，模型不知道每句话应该对应哪段视频时间。
- `must not disappear` 等逻辑否定对视频文本编码器并不稳定，反而可能激活错误概念。
- 重复的实体、动作和物理词会稀释外观、主体与场景语义。
- 普通 CFG 会整体放大条件差异，无法只增强“正确物理关系”。
- 首帧、去噪步骤、DiT 层深、输出视频时间和空间区域是不同控制轴，不能混为一谈。

因此整体思路改为把条件职责拆开：

```text
初态图像 I0   -> 只负责 t=0 的实体、初始状态、布局、相机和连续性锚点
语义条件 c_sem -> 负责实体、角色、场景和事件目标
因果条件 c+/c- -> 用“正确过程 - 最近错误反事实”突出触发、顺序、变化和终态保持
```

需要保护的也不是“整个对象外观永远不变”，而是相机、背景、无关实体及身份/材料来源；位置、速度、姿态、大小、形状、相态、数量和完整性等应变化属性必须保留为 transition variables。

## 3. 当前模型架构和几个版本

### 3.1 共同基座

- 基础模型：`Wan2.2-TI2V-5B`，30 个 DiT block，统一支持 T2V/I2V。
- Wan 官方代码和 checkpoint 保持只读；所有新增逻辑位于 `Project/physGen/code/v1`。
- 不训练 LoRA、adapter 或新 attention 权重，只做外置推理适配。
- I2V 直接复用 Wan 原生 VAE 首帧 latent 和逐步重锚机制，不额外训练视觉编码器。
- 原语义通过 T5 和原 cross-attention 进入所有 block；ACE 仅在 conditional branch 的指定 block 中增加因果残差，counterfactual 不是 CFG negative prompt。

ACE 的核心形式为：

\[
h' = h + r_{sem} + \lambda_0 g_{layer}(\ell)g_{step}(k)
\left[CA(q,c_+) - CA(q,c_-)\right].
\]

安全版进一步把候选残差逐样本裁剪为 semantic residual 范数的一定比例，防止因果引导破坏主体结构。

### 3.2 M0～M4

| 版本 | 输入/架构 | 目的 |
|---|---|---|
| M0 | 纯 T2V；原始短 prompt；无首帧、无 ACE | Wan T2V 基线 |
| M1 | 原生 I2V；同一张审核首帧 + 原始短 prompt；无 ACE | 分离“首帧锚点”本身的收益 |
| M2 | I2V + cplus-only residual，即 `semantic + scale × (positive - semantic)` | 判断只增强正确过程是否有效 |
| M3 | I2V + `positive - counterfactual` 因果残差 | 当前 I2V 研究主线，测试首帧锚点与因果残差是否互补 |
| M4 | 纯 T2V + `positive - counterfactual` 因果残差 | 判断无图像时 causal routing 是否仍有独立收益 |

### 3.3 M3/M4 的初版与安全版

初版 ACE 使用 `lambda0=0.5`、blocks 8～23、legacy step schedule、未做相对范数裁剪，并把原 prompt 重复拼入 c+/c-；首轮审计发现单层残差可达 semantic 的约 10%～16%，容易造成形变或拓扑过冲。

当前安全版已经改为：

- M3-safe：compiled I2V semantic，relation-only c+/c-，`lambda0=0.10`，blocks 14～23，2% residual cap，step gate 为 `0.5/1.0/0.3/0.1`。
- M4-safe：更完整的 compiled T2V semantic，不读取图片 tensor，relation-only c+/c-，`lambda0=0.08`，blocks 14～23，1.5% cap，step gate 为 `0.25/0.8/0.3/0.1`。
- CFG unconditional 改为空文本，不再使用与任务失败类型不匹配的通用 Wan negative prompt。
- `conditioning.compiled.json`、context、输入 hash、裁剪前后 residual norm 和 clip 比例均会落盘。

另保留 `initial_v1_hd97` 兼容版本，用 1280×704、97 帧复现原始强残差配置，以便与安全版做同分辨率/同时长对照。

### 3.4 后续架构方向：TRACE-Lite / TRACE-Field

当前 ACE 只路由两个轴：DiT 层深 \(\ell\) 和去噪步骤 \(k\)。它还不能明确控制“哪段成片时间”和“哪个空间区域”发生变化。

已设计但尚未实现的 TRACE-Lite 将增加：

- 三阶段条件：precondition、transition、terminal；
- 输出视频时间 gate \(\alpha_m(f)\)，分别作用于前、中、后段 latent token；
- 粗 ROI / motion corridor / contact region 空间 gate \(\beta_m(f,x,y)\)；
- 四轴路由：layer × denoise step × output time × space。

更长期的 TRACE-Field / Reader–Writer–Corrector 方向，是把固定 gate 升级为可学习的状态转移场和低维 causal memory，但需先证明 TRACE-Lite 的时间/空间路由确实有效。

## 4. 测试集与完整数据流程

### 4.1 测试集

当前使用自建的 20 条 pilot prompt（P01～P20），覆盖：

- 刚体与接触：滑板车碰撞、双球碰撞、球拍击球、多米诺、斜坡摩擦、书本坠落、纸箱倾倒；
- 相变与不可逆变化：冰/黄油融化、气球爆裂、玻璃破碎、纸张撕裂；
- 颗粒、液体和扩散：蒲公英、倒水/果汁、沙堆、染料扩散；
- 弹性/耗散：海绵回弹、多次衰减弹跳；
- 多物理共存：雪地篝火旁倒咖啡。

### 4.2 每条样本需要准备的额外文本和图片

每个 `Pxx` 当前都有以下资产：

```text
Pxx-origin.txt             原始短视频 prompt
Pxx-cplus-cminus.json      正确因果句、最近错误反事实、事件类型、变化变量等
Pxx-i0.json                首帧生成 prompt、实体/初态/布局、保护项、变化项、reject_if
Pxx-i0.png                 原始/兼容首帧
Pxx-i0-1280x704.png        HD97 I2V 实际使用的首帧
```

两份额外提示词模板分别位于：

- `prompt/generate_high_quality_i0.txt`：把原视频文本编译成“事件发生前”的静态首帧描述和审核规则。
- `prompt/generate_cplus_cminus.txt`：生成不超过 32 词的 c+ 与只改变一个因果关系的 c-，禁止否定词和无关外观/镜头描述。

理想的完整流程为：

```text
原始视频 prompt
  ├─> LLM 首帧状态编译 -> 固定 T2I 生成 8 张候选
  │                     -> 仅看图片审核实体/数量/初态/尺度/空间/伪影
  │                     -> 固定一张 I0，裁剪缩放到 1280×704
  └─> LLM 因果编译 -> c+ / c- JSON
                       -> 实体一致、单关系变化、长度/token、禁用词检查

origin + I0 metadata + causal metadata
  -> deterministic conditioning compiler
  -> schema/path/hash/尺寸 preflight
  -> M0～M4 推理（50 steps，CFG 5，当前 HD97 为 97 帧/24 fps）
  -> video + manifest + resolved config + contexts + conditioning + diagnostics
  -> 关键帧/VLM/人工 postflight 和 A/B/C/D 严格评级
```

正式流程应为每张 I0 保存 `Pxx-i0-selection.json`，记录候选、hash、审核项和 reviewer，并在推理时强制校验。目前 20 张 I0 已齐全，但 selection manifest 仍未补齐和强制启用。

- 首轮低分辨率 100 个视频：A=0、B=3、C=33、D=64，严格合格仅 3%，说明“成功输出视频”不等于“物理任务完成”。

- M3-safe 已从“强全局扰动”改善为“较安全、偶尔有效的全局因果方向”，部分样本出现更完整的状态演化，但还不是稳定的因果控制器。
- M4-safe 没有稳定净提升，说明无首帧时仅靠文本残差很难固定实体、布局与交互空间。
- CFG 3.5 整体更稳；CFG 5 偶尔增强运动，也会同步放大复制、形变、错误来源和终态预置，因此暂时只保留作压力测试。

## 7. 目前仍然存在的问题

问题可以集中概括为三层：

- **方法层：**当前 ACE 只按 DiT 层和去噪步路由，仍把同一因果残差作用到所有输出时间和空间 token，无法明确约束“何时发生、在哪里发生、由谁触发、作用到谁”。
- **生成层：**主要失败仍是结果预置/中间态删除、触发—响应断裂、对象复制或幽灵残留、源—流—汇不耦合、状态进度不单调、空间泄漏以及终态不保持。
- **实验层：**目前只有 seed 42，缺 M0/M1 compiled 公平基线、I0 selection manifest 和自动 postflight；新 HD97 批次也还没有完成多 seed 的统一盲评。

1. **ACE 有效性尚未成立。** 首轮 M2/M3 的严格评级没有超过 M1，很多样本与基线 SSIM 很高；发生明显变化的样本又可能出现 P12 树枝化等过冲。
2. **全局文本残差不等于物理控制。** 当前没有 output-time phase、对象 mask、轨迹、液位、粒子数量或材料守恒约束，难以解决复杂物理事件。
3. **首帧只锚定 t=0。** 它改善构图，但不能保证后续同一对象的身份、数量和材料连续性；同时 selection manifest 尚缺失。
4. **新 HD97 目前只有初步定性审计。** 更长、更清晰没有自动解决因果链；仍需等运行完成后做全样本、多 seed、统一标准的盲评和配对比较。
5. **缺少关键公平基线。** 仍需增加 M1-compiled 和 M0-compiled，判断收益来自“更完整的 semantic prompt”还是 ACE residual。
6. **当前只有 seed 42。** 无法区分方法稳定性和偶然 seed，尚不能报告方差、平均通过率或 pass@N。
7. **缺少自动化视频 postflight。** 现有 diagnostics 只能发现 NaN、范数和裁剪问题，无法检测对象复制、外物、顺序、守恒或终态回退。
8. **不同物理类别需要不同控制。** 碰撞/弹跳更适合 mask、轨迹或光流；液体/沙子需要源—流—目标和单调量约束；融化/扩散/破碎可能需要多关键帧或简单模拟骨架。
9. **TRACE-Lite 仍停留在设计阶段。** 三阶段 prompt、输出时间 gate、空间 ROI/tube 和相应演化指标尚未进入当前代码。

## 8. 建议的下一步

1. 等当前三组 HD97 作业完成，先对 P02、P08、P12、P13、P20 做安全版与 initial-v1 的关键帧配对审计，不立即扩大新批次。
2. 补齐并强制启用 I0 selection manifest；增加 `quality_audit.json` 和硬 reject 规则。
3. 增加 M0-compiled / M1-compiled 基线，以同一 semantic 隔离 ACE 的真实增益。
4. 用 5 个代表样本 × 4 个配置 × 2 个 seed 做小规模诊断，先确认 1%～3% capped residual 是否既有作用又不增加 EX/ID/DEF。
5. 若安全版仍无法显著超过 compiled baseline，停止继续扩大纯 ACE，优先实现 TRACE-Time；验证输出时间 phase 后再加入空间 ROI。
6. 对需要严格守恒和轨迹的任务，引入对象级显式控制或模拟/程序动画运动骨架，ACE 只保留为轻量语义因果引导。
